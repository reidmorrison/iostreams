# CLAUDE.md

## Tests

- `test/test_helper.rb` generates PGP test keys on first run, so a working `gpg` binary is required.
- S3 and SFTP path tests skip unless env vars are set (`S3_BUCKET_NAME`; `SFTP_HOSTNAME`, `SFTP_USERNAME`, `SFTP_PASSWORD`).
- On JRuby, `bundle exec rake` first downloads the zstd-jni jar for `.zst` into `~/.m2/repository` (`bundle exec rake zstd_jni`, see `test/zstd_jni.rb`), since JRuby cannot load the zstd-ruby C extension.
- The gem itself has zero runtime dependencies; format-specific gems (rubyzip, aws-sdk-s3, nokogiri, etc.) are dev-only and loaded lazily.

## Architecture

The public entry points are `IOStreams.path(...)` (returns a `Path` subclass based on URI scheme) and `IOStreams.stream(io)` (wraps an existing IO). Both return an `IOStreams::Stream` which is configured via chained `#stream`/`#option` calls and consumed via `#reader`, `#writer`, `#each`, `#read`, `#write`, `#copy_from`, etc.

**Public API boundary:** The `IOStreams` module itself is the only public entry point. Everyone starts from `IOStreams.path`/`IOStreams.stream`/`IOStreams.join`, and the instance methods on the `Stream`/`Path` they return are then public. Everything else (`Path` subclasses, the `Reader`/`Writer` classes, and the format/storage submodules) is internal: nothing else should be instantiated or called directly, including method signatures like `Zip::Writer.stream`. This keeps the user-facing API tiny and lets the internals be refactored freely without breaking callers. When changing code, preserve the `IOStreams.*` module methods and the `Stream`/`Path` instance methods; treat the rest as private and changeable.

**Backward compatibility is mandatory for the public interface.** This library must never break backward compatibility in its public interface; everything else can be refactored freely as needed. The `IOStreams` module is the public interface, but whatever it returns or otherwise makes accessible is also part of that public interface. For example, `IOStreams.path` returns `Path` objects, so those are public. `Builder` is itself hidden, but its arguments and formatting options are exposed through the public API (e.g. via `#stream`/`#option` and file-name format detection), so they must remain backward compatible too. Evolve these by adding or extending new values, never by removing or changing the meaning of existing features that end users of the API may depend on.

**Paths are configuration, not code.** A path or url is meant to be externalized, for example into a centralized configuration system or an environment variable, so the exact same application code runs against local files in development and a completely different file store in staging or production. For example, while migrating production from on-prem to the cloud, the on-prem instance can use local files while the cloud instance uses S3, with only the configuration differing. Code should never need to know which file store a path refers to. So when a concept exists in one scheme, give the other schemes the equivalent form where it makes sense, even when that bends a url standard: `sftp://hostname/~/data/a.csv` is within the login directory, so `file://~/data/a.csv` is within the home directory, letting one setting switch between the two. Likewise, keep path operations behaving the same across schemes.

**The internals of `lib/io_streams/`**, how the builder, schema, tabular mappings, Parquet, slices, readers, writers and format registries fit together, are in [lib/io_streams/CLAUDE.md](lib/io_streams/CLAUDE.md), which loads when working with the files there.

`lib/iostreams.rb` defines the top-level autoloads, and each format module autoloads its own reader and writer; everything is lazy-loaded so optional dependencies are only required when the corresponding format is used.

## Conventions

- **API calls are strict.** An option or argument that a method does not accept must raise `ArgumentError`, never be silently ignored. Accepting and discarding options leaves callers no way to tell their setting had no effect, and some ignored options give false assurance (for example a PGP `signer:` that, if dropped when reading, would check no signer). Declare explicit keyword arguments rather than passing `**args` or an options hash through to a dependency unchecked. Each format `Reader`/`Writer` declares `self.option_names`, the keywords it takes, and only those are passed to it; keep it in sync when changing a signature (`test/stream_options_test.rb` checks it). A `Reader`/`Writer` also declares `self.sensitive_option_names`, those of its options that hold a secret, such as a PGP `passphrase`, so that `#inspect` does not display them. One option hash is shared by a stream's reader and writer, so that a path can be written and then read, so by default each direction also accepts the other direction's `option_names` and ignores them, such as `compress` when reading `.enc`, whose header records it; `IOStreams::StreamFormat#valid_option_names` computes this from the format's reader and writer. `Builder#option`/`#stream` reject a name that neither direction accepts as soon as it is set, even for a stream the file name does not include. When adding an option, check whether a caller could expect it to have an effect in the other direction, such as the PGP `signer` before the reader checked it; if so, list it in that direction's class's `self.unsupported_option_names`, so that `IOStreams::StreamFormat#validate_options` raises with a message that names the direction it belongs to, until that direction supports it. A class never lists the other direction's options that it accepts, so it does not have to know them. Moving from strict to lenient is backward compatible but moving back is not, so once released, an option that the other direction ignores can never raise there again.
- **A stream never closes the IO supplied to it.** Whoever opens an IO closes it: a format `Reader`/`Writer` closes only what it opened itself, such as its own wrapper object or a file it opened by name in `.file`, and leaves the IO passed to `.stream` open for the caller. Many wrappers close the IO underneath them, for example `Zlib::GzipWriter#close` and `SymmetricEncryption::Writer.open`, so end them without closing it: `#finish` for Zlib, `close(false)` for SymmetricEncryption, `autoclose: false` for bzip2-ffi. `test/stream_close_test.rb` checks every registered stream that has both a reader and a writer, and the built-in encode stream.
- **Callers rescue IOStreams exceptions, never those of a gem.** To keep IOStreams generic, its interface does not rely on the exceptions of the gems that provide a path or a stream, such as `Zip::Error` from rubyzip or `Aws::S3::Errors::NoSuchKey`, so that a gem can be replaced with a newer or better one, or differ by platform, as zip does on JRuby, without breaking the exceptions that callers rescue. Never raise a gem's exception class: for a failure that IOStreams finds itself, raise its own exception, tagged with the kind of failure, such as `IOStreams::Errors::StreamFailure` tagged as `IOStreams::Errors::MissingEntry`. Tag an exception that a gem raises with the kind of failure that it means, rather than replacing it, so that code that rescues it by its class keeps working: a path makes each request of its storage within `#tag_failure` and answers `#failure_kind` (`NotFound`, `PermissionDenied` and `Unavailable`, which include `StorageError`), and a format's reader makes each call of its gem within `.tag_failure` and answers `.failure_kind` (`Corrupt`, `MissingEntry` and `MissingKey`, which include `StreamError`; the PGP reader tells them from gpg's status, see `Pgp::Status`), including each read, which `BlockReader` makes within it. Docs and tests name the kind of failure, and name a gem's exception only to say that it is kept. See docs/errors.md.
- **A deprecated method or option reports a warning when it is used.** The class that owns it calls `IOStreams::Deprecation.warn` with what is deprecated and what to use instead, where the application supplies it, so that Ruby reports a deprecation warning at the line of the application, only while `Warning[:deprecated]` is on, which it is not by default. What is deprecated still works, and IOStreams never uses its own deprecated methods and options. `test/test_helper.rb` fails any test that causes an IOStreams deprecation warning, which it asks `IOStreams::Deprecation.warning?` to tell from the others, that it does not assert with `assert_deprecated(pattern) { ... }`.
- The pre-v1.6 deprecated API has been removed (as of v2.0.0). Do not reintroduce it.
- **v2.x is maintained on the `v2` branch**, from which v2.2, a bridge to v3.0, is released: it backports v3.0's replacements, such as `#schema`, `#raw` and `#encoding`, onto v2.1's code, and reports deprecation warnings for what v3.0 deprecates or removes. `v2` is not merged into `main`, since its code is v2.1's: a fix that applies to both branches is made on each, by its own PR, and the PR on `v2` says where the fix went on `main`, or why `main` does not need it. `main`'s CHANGELOG and upgrade guide also hold the sections for v2.2.
