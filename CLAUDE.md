# CLAUDE.md

## Tests

- `test/test_helper.rb` generates PGP test keys on first run, so a working `gpg` binary is required.
- S3 and SFTP path tests skip unless env vars are set (`S3_BUCKET_NAME`; `SFTP_HOSTNAME`, `SFTP_USERNAME`, `SFTP_PASSWORD`). The S3 and Google Cloud Storage tests otherwise run against an in-memory store (`test/s3_stub.rb`), and against a real Cloud Storage bucket with `GCS_BUCKET_NAME`, `GCS_ACCESS_KEY_ID` and `GCS_SECRET_ACCESS_KEY` (an HMAC key).
- The query tests in `test/query/` load Active Record, which changes how ActiveSupport writes JSON, so `bundle exec rake` runs them in a process of their own (`rake query_test`); how they are set up, and run on other versions of Active Record, is in [lib/io_streams/query/CLAUDE.md](lib/io_streams/query/CLAUDE.md).
- On JRuby, `bundle exec rake` first downloads the zstd-jni jar for `.zst` into `~/.m2/repository` (`bundle exec rake zstd_jni`, see `test/zstd_jni.rb`), since JRuby cannot load the zstd-ruby C extension.
- The gem itself depends only on `csv` and `bigdecimal`, which are bundled gems from Ruby 3.4; format-specific gems (rubyzip, aws-sdk-s3, zip_kit, etc.) are dev-only and loaded lazily.
- `Gemfile.lock` is untracked on purpose, so the gems resolve to their latest versions. A new worktree has none, and `bundle exec` then fails resolving the optional `mysql` group (`Could not find gem 'mysql2'`); when it is missing or stale, delete it and run `bundle install`.
- Put a worktree for running tests at a short path inside the repo, such as `tmp/<name>`: `test/test_helper.rb` sets `GNUPGHOME` to `tmp/gnupg` of the checkout, and gpg-agent's socket path is limited to about 104 bytes on macOS, so a long path fails with "File name too long" before any PGP test runs. Before removing a worktree, stop its agent with `gpgconf --homedir <worktree>/tmp/gnupg --kill gpg-agent`.
- `.rubocop.yml` excludes `tmp/**/*`, so in a worktree under `tmp/`, `bundle exec rubocop` inspects 0 files and looks clean. Pass the files explicitly: `bundle exec rubocop $(git ls-files '*.rb' 'Rakefile' '*.gemspec' 'Gemfile' | grep -v '^docs/\|^test/files/\|^gemfiles/')`, and check that the count inspected is not 0.
- PGP test failures that are not regressions: "Corrupted protection" from `generate_key` is a gpg-agent flake, so rerun before investigating when the change does not touch `IOStreams::Pgp`. "There is no assurance this key belongs to the named user" everywhere means the test key `receiver@example.org` lost its ultimate trust, such as from a script that ran `import_and_trust_key:` against `tmp/gnupg`; keep such scripts on a throwaway `GNUPGHOME`. To reset the test keyring, kill its agent and remove `tmp/gnupg`; the next run regenerates it.
- `bundle exec ruby -I<other checkout>/lib` still loads this checkout's `lib/`, since the Gemfile's `gemspec` puts it first, so a comparison of `main` against a branch silently runs the same code twice. Extract the other tree (`git archive origin/main lib | tar -x -C <dir>`), run plain `ruby -I<dir>/lib` outside the checkout, and confirm with `$LOADED_FEATURES.grep(/io_streams/)` which copy loaded.
- A change to how a spreadsheet is read is also checked against the 200 workbooks of ExcelDataReader's test data, which are too slow and large for the standard tests: `bundle exec rake xlsx_corpus` downloads them, at the commit that `test/xlsx_corpus.rb` pins, into `tmp/xlsx_corpus`, and compares what each one reads with `test/xlsx_corpus.json`, `SHOW=1` printing every row of a difference. Check each difference against the workbook, then `bundle exec rake xlsx_corpus_record`. Run it on JRuby too.
- To run the tests on JRuby without touching the MRI `Gemfile.lock`, use a scratch Gemfile that holds only `eval_gemfile "<repo>/Gemfile"` (the project Gemfile picks Active Record 8.0 and AR-JDBC on JRuby itself), with `BUNDLE_GEMFILE` and `BUNDLE_PATH` pointing at the scratch directory. Do not hand-write a Gemfile of a few gems: it misses bzip2-ffi, zip_kit, base64 and others.

## Architecture

**Public API boundary:** The `IOStreams` module itself is the only public entry point. Everyone starts from `IOStreams.path`/`IOStreams.stream`/`IOStreams.join`, and the instance methods on the `Stream`/`Path` they return are then public. Everything else (`Path` subclasses, the `Reader`/`Writer` classes, and the format/storage submodules) is internal: nothing else should be instantiated or called directly, including method signatures like `Zip::Writer.stream`. This keeps the user-facing API tiny and lets the internals be refactored freely without breaking callers. When changing code, preserve the `IOStreams.*` module methods and the `Stream`/`Path` instance methods; treat the rest as private and changeable.

**Backward compatibility is mandatory for the public interface.** This library must never break backward compatibility in its public interface; everything else can be refactored freely as needed. The `IOStreams` module is the public interface, but whatever it returns or otherwise makes accessible is also part of that public interface. For example, `IOStreams.path` returns `Path` objects, so those are public. `Builder` is itself hidden, but its arguments and formatting options are exposed through the public API (e.g. via `#stream`/`#option` and file-name format detection), so they must remain backward compatible too. Evolve these by adding or extending new values, never by removing or changing the meaning of existing features that end users of the API may depend on. Observable details count too: fixed-width `record_parse` returns Symbol keys, and changing them to Strings would break callers. The one exception is v3.0 while it is unreleased: flag each breaking change, prefer the compatible path when it costs little, and make a justified break only with an entry under "Breaking" in CHANGELOG.md's [3.0.0] section and a section in docs/upgrading.md ("Upgrading to v3.0").

**Design for every caller.** Rocket Job is one real user of IOStreams, handy for testing a design against, but not the only one: the aim is to bring batch and large-file processing to other job frameworks, starting with ActiveJob. Reason about a public interface from general use cases first, then check Rocket Job as one concrete consumer and list its impact separately. Move capabilities that are generally useful into IOStreams, and keep behavior that only Rocket Job needs in Rocket Job.

**Paths are configuration, not code.** A path or url is meant to be externalized, for example into a centralized configuration system or an environment variable, so the exact same application code runs against local files in development and a completely different file store in staging or production. For example, while migrating production from on-prem to the cloud, the on-prem instance can use local files while the cloud instance uses S3, with only the configuration differing. Code should never need to know which file store a path refers to. So when a concept exists in one scheme, give the other schemes the equivalent form where it makes sense, even when that bends a url standard: `sftp://hostname/~/data/a.csv` is within the login directory, so `file://~/data/a.csv` is within the home directory, letting one setting switch between the two. Likewise, keep path operations behaving the same across schemes.

**The internals of `lib/io_streams/`**, how the builder, schema, tabular mappings, Parquet, slices, readers, writers and format registries fit together, are in [lib/io_streams/CLAUDE.md](lib/io_streams/CLAUDE.md), which loads when working with the files there, and how an Active Record query is read is in [lib/io_streams/query/CLAUDE.md](lib/io_streams/query/CLAUDE.md).

## Conventions

- **API calls are strict.** An option or argument that a method does not accept must raise `ArgumentError`, never be silently ignored. Accepting and discarding options leaves callers no way to tell their setting had no effect, and some ignored options give false assurance (for example a PGP `signer:` that, if dropped when reading, would check no signer). Declare explicit keyword arguments rather than passing `**args` or an options hash through to a dependency unchecked. Each format `Reader`/`Writer` declares `self.option_names`, the keywords it takes, and only those are passed to it; keep it in sync when changing a signature (`test/stream_options_test.rb` checks it). A `Reader`/`Writer` also declares `self.sensitive_option_names`, those of its options that hold a secret, such as a PGP `passphrase`, so that `#inspect` does not display them. One option hash is shared by a stream's reader and writer, so that a path can be written and then read, so by default each direction also accepts the other direction's `option_names` and ignores them, such as `compress` when reading `.enc`, whose header records it; `IOStreams::StreamFormat#valid_option_names` computes this from the format's reader and writer. `Builder#option`/`#stream` reject a name that neither direction accepts as soon as it is set, even for a stream the file name does not include. When adding an option, check whether a caller could expect it to have an effect in the other direction, such as the PGP `signer` before the reader checked it; if so, list it in that direction's class's `self.unsupported_option_names`, so that `IOStreams::StreamFormat#validate_options` raises with a message that names the direction it belongs to, until that direction supports it. A class never lists the other direction's options that it accepts, so it does not have to know them. Moving from strict to lenient is backward compatible but moving back is not, so once released, an option that the other direction ignores can never raise there again.
- **A stream never closes the IO supplied to it.** Whoever opens an IO closes it: a format `Reader`/`Writer` closes only what it opened itself, such as its own wrapper object or a file it opened by name in `.file`, and leaves the IO passed to `.stream` open for the caller. Many wrappers close the IO underneath them, for example `Zlib::GzipWriter#close` and `SymmetricEncryption::Writer.open`, so end them without closing it: `#finish` for Zlib, `close(false)` for SymmetricEncryption, `autoclose: false` for bzip2-ffi. `test/stream_close_test.rb` checks every registered stream that has both a reader and a writer, and the built-in encode stream.
- **Callers rescue IOStreams exceptions, never those of a gem.** To keep IOStreams generic, its interface does not rely on the exceptions of the gems that provide a path or a stream, such as `Zip::Error` from rubyzip or `Aws::S3::Errors::NoSuchKey`, so that a gem can be replaced with a newer or better one, or differ by platform, as zip does on JRuby, without breaking the exceptions that callers rescue. Never raise a gem's exception class: for a failure that IOStreams finds itself, raise its own exception, tagged with the kind of failure, such as `IOStreams::Errors::StreamFailure` tagged as `IOStreams::Errors::MissingEntry`. Tag an exception that a gem raises with the kind of failure that it means, rather than replacing it, so that code that rescues it by its class keeps working: a path makes each request of its storage within `#tag_failure` and answers `#failure_kind` (`NotFound`, `PermissionDenied` and `Unavailable`, which include `StorageError`), and a format's reader makes each call of its gem within `.tag_failure` and answers `.failure_kind` (`Corrupt`, `MissingEntry` and `MissingKey`, which include `StreamError`; the PGP reader tells them from gpg's status, see `Pgp::Status`), including each read, which `BlockReader` makes within it. Docs and tests name the kind of failure, and name a gem's exception only to say that it is kept. See docs/errors.md.
- **A write keeps its target only when the caller chose to stop.** Leaving a writer block with `break` or `return` keeps what was written so far, on every scheme; an exception during the write, or a kill of the thread while it writes, discards the target, so no truncated file is left. Setup errors (a missing schema, a bad option value, a gem that is not installed) raise before the target is opened, so a write that never started never deletes an existing file. Route a new writer through `IOStreams::Utils.finish_or_abort(finish:, abort:)`, and give a format writer a `.check` that `StreamFormat#check_stream` calls before the output is opened.
- **A deprecated method or option reports a warning when it is used.** The class that owns it calls `IOStreams::Deprecation.warn` with what is deprecated and what to use instead, where the application supplies it, so that Ruby reports a deprecation warning at the line of the application, only while `Warning[:deprecated]` is on, which it is not by default. What is deprecated still works, and IOStreams never uses its own deprecated methods and options. `test/test_helper.rb` fails any test that causes an IOStreams deprecation warning, which it asks `IOStreams::Deprecation.warning?` to tell from the others, that it does not assert with `assert_deprecated(pattern) { ... }`.
- The pre-v1.6 deprecated API has been removed (as of v2.0.0). Do not reintroduce it.
- **v2.x is maintained on the `v2` branch**, from which v2.2, a bridge to v3.0, is released: it backports v3.0's replacements, such as `#schema`, `#raw` and `#encoding`, onto v2.1's code, and reports deprecation warnings for what v3.0 removes. `v2` is not merged into `main`, since its code is v2.1's: a fix that applies to both branches is made on each, by its own PR, and the PR on `v2` says where the fix went on `main`, or why `main` does not need it. `main`'s CHANGELOG and upgrade guide also hold the sections for v2.2.
- **The v2.2 upgrade suite checks that code without deprecation warnings on v2.2 runs on v3.0.** The tests of v2.2's public, non-deprecated behavior that v3.0 keeps live once, on `v2`, in `test/upgrade`, which `main` ignores. `main` runs them at the `v2` commit that `UpgradeSuite::COMMIT` pins in `test/upgrade_suite.rb`, with its own test helper: `bundle exec rake upgrade_test`, which CI runs on every Ruby. A PR that ports a change of `v2` moves the pin, and CI's "v2.2 Upgrade Suite is current" job (`rake upgrade_suite_current`) fails until `v2` holds the pinned commit, such as when the pull request that it was on was merged as other commits, and while `v2` has changed the suite since. A change on `main` that fails the suite either keeps v2.2's behavior, or, when v3.0 changes it on purpose, goes with a `v2` PR that turns that test into a version check, `IOStreams::VERSION.to_i >= 3`, naming the section of docs/upgrading.md that documents the change.
