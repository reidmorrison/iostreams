# Changelog

All notable changes to this project are documented here.

This project adheres to [Semantic Versioning](https://semver.org/).

## [3.0.0] - Unreleased

### Breaking

- **Ruby 3.3 or later is required.** Ruby 3.2 reached its end of life in March 2026. Its timeout library, 0.3, also leaves the block that a `Timeout` interrupts with `throw`, as `break` does, rather than with an exception, so a write that it interrupted kept what was written, as after `break`, and a PGP read or write that it interrupted while its stream stalled waited for the stream. Ruby 3.3 and later raise an exception, so the write is discarded.

Text is read as UTF-8 by default:

- **Lines, rows and records are UTF-8 strings.** Reading with `#each`, or `#reader` in the `:line`, `:array` or `:hash` mode, decodes the data with the encode stream and its default options, unless an encoding is set with `#encoding`, so the strings are UTF-8, and data that is not valid UTF-8 raises `Encoding::UndefinedConversionError`. Previously they were binary (`ASCII-8BIT`) strings, apart from values parsed from JSON, which could not be combined with UTF-8 text: for example, writing a CSV row that mixed a value read from a file with a non-ASCII UTF-8 value raised `Encoding::CompatibilityError`, and a column name with a non-ASCII character, read with `cleanse_header: false`, did not match the same UTF-8 string. The values of a spreadsheet were also binary, although they are UTF-8 in the file. Fixed width files are read as ASCII instead, see below. To read binary strings as before, supply `encoding("BINARY")`, and for another encoding, such as Windows-1252, supply it to `#encoding`. `#raw` reads and writes the data as it is stored, as bytes, see Added.
- **A UTF-8 byte order mark at the start of the data is removed** when reading lines, rows or records, or reading through an encode stream with `encoding: "UTF-8"`. Excel writes one at the start of a "CSV UTF-8" file, so reading such a file with a quoted header row raised `CSV::MalformedCSVError: Illegal quoting`, and with `cleanse_header: false` its first column name began with the byte order mark (U+FEFF). So is the byte order mark at the start of UTF-16 or UTF-32 text of either byte order, such as the UTF-16LE "Unicode Text" that Windows programs export, read with `encoding("UTF-16LE:UTF-8")`. `#read` keeps it, like `File.read`.
- **`#read` returns the whole file as UTF-8, without checking it, like `File.read`.** A binary file, such as an image, can still be read, since its bytes are unchanged. Previously it was binary, apart from `.gz` and `.enc` files, which were in `Encoding.default_external`, so their encoding depended on the locale. An IO that you supply, read without any streams, keeps the encoding that it gives its data, and with an encode stream the data is in the stream's encoding, and checked. `#read` with a length, such as `read(1024)`, the `:stream` mode, and writing still read and write bytes.

These changes were postponed from v2.1, where each one logged a warning via `IOStreams.logger` when it would change the result.

- **Fixed width files are read and written as ASCII by default.** Reading or writing rows or records in the `:fixed` format, or lines when the format of the path is `:fixed`, uses the encode stream with `encoding: "US-ASCII:UTF-8"`, unless an encoding is set with `#encoding`, or the data is read as stored with `#raw`; other encode options, such as `replace:`, are kept. Their sizes count bytes, and their text is ASCII or a single-byte code page, so the values read are UTF-8 strings, and a byte that is not ASCII raises `IOStreams::Errors::InvalidEncoding`, naming the byte and its offset, where previously the values were binary strings. Writing a value that is not ASCII raises `Encoding::UndefinedConversionError`, where previously its UTF-8 bytes were written, making the line longer than the layout in bytes. Set the encoding of the file instead, such as `encoding("ISO-8859-1:UTF-8")`, `"IBM037:UTF-8"` for EBCDIC, or `"UTF-8"` for UTF-8 written by a program that counts characters, or supply `replace: " "` to replace each character that is not ASCII with a space.
- **Cleansing a header row keeps letters and digits that are not ASCII.** Now that the header row is read as UTF-8, the column `Prénom` is cleansed as `prénom`, and `日付` as `日付`, where they were `prnom` and an empty name, since `\W` only matches ASCII, so columns such as `日付` and `金額` had the same empty name. JSON keys are cleansed the same way when they are matched to columns. Whitespace that is not ASCII, such as a no-break space, is converted to `_` and stripped like a space, so `First Name` with a no-break space is `first_name`, where it was `firstname`. Rename any `allowed_columns`, `required_columns` or `columns` written to match the previous names, such as `prnom`.

- **`allowed_columns`, `required_columns` and `skip_unknown` now apply to every input when reading records.** `IOStreams.enforce_column_restrictions` now defaults to true. Previously they were only applied to a header row read from the file, and only when `cleanse_header` was true, so they were ignored for JSON and `:hash` input, when `columns:` was supplied, and with `cleanse_header: false`. Since the format is usually inferred from the file name, renaming an upload from `.csv` to `.json` bypassed the allow list. When either `allowed_columns` or `required_columns` is set, JSON keys are now cleansed like a header row (for example `"Name"` becomes `"name"`), unknown keys are skipped or raise `IOStreams::Errors::InvalidHeader`, and a record missing a required column raises `IOStreams::Errors::InvalidHeader`. The keys of the columns that they keep are kept as they are when they are already the names of their columns, such as the Symbol keys of `:hash` records, so that `{name: "Jack", zip: 12}` read with `allowed_columns: ["name"]` is `{name: "Jack"}`, while a key that cleansing renames, such as `"Name"`, becomes the name of its column, `"name"`. Set `IOStreams.enforce_column_restrictions = false` to keep the previous behavior.
- **BZip2 options are strict.** The BZip2 reader and writer now raise `ArgumentError` for an option that neither of them accepts, like every other stream, instead of ignoring it. They accept `autoclose`, `first_only` and `small` when reading, and `autoclose`, `block_size` and `work_factor` when writing, and each ignores the options of the other.
- **`IOStreams::Pgp.export(email: nil)` without a `key_id:` raises `ArgumentError`** instead of `IOStreams::Pgp::Failure`.

These are removed:

- **`#format_options`, the layout of a fixed width file, is removed**, as are `format_options:` of `IOStreams::Tabular.new` and `IOStreams::Schema.from_layout`, so calling `#format_options` raises `NoMethodError`, and `format_options:` supplied to `#each`, `#reader` or `#writer` raises `ArgumentError` as an unknown option. v2.2 deprecates `#format_options`, and its `IOStreams::Schema.from_layout` returns the schema of a layout, so convert each layout with v2.2, save its schema, such as in a JSON file, and set it with `#schema` instead, see Added and [`#format_options` is replaced by `#schema`](https://iostreams.reidmorrison.com/upgrading#format_options-is-replaced-by-schema). `IOStreams::Errors::InvalidLayout` is kept, so that code that rescues it still works, though nothing raises it.
- **The Zip writer no longer accepts `zip_file_name`.** Use `entry_file_name`, which the documentation has used in its place for a long time, and which also chooses the file to read within a zip file. `option(:zip, zip_file_name: "a.csv")` now raises `ArgumentError`.

These changes affect code that registers extensions, or reads them with `IOStreams.extensions`:

- **`IOStreams.extensions` returns the format registered for each extension**, such as `IOStreams::Gzip` for `:gz`, instead of an `IOStreams::Extension` struct. A format answers `reader_class` and `writer_class` as before, and also `compressed?` and `encrypted?`, but not the methods of a struct, such as `to_a`, `to_h`, `==` or `[]`. An extension registered with its reader and writer classes is still an `IOStreams::Extension`, which is now frozen, so its setters, such as `writer_class=`, raise `FrozenError`. Previously the setters changed the registered extension for the whole process, since `IOStreams.extensions` returns a copy of the registry that shares its entries.
- **The `:encode` stream is built in, rather than a registered extension.** It converts the text that the application reads or writes, rather than the data of a file format, so `IOStreams.extensions` no longer includes it, `IOStreams.register_extension(:encode, ...)` raises `ArgumentError`, since `:encode` is a reserved keyword, instead of replacing it, and `IOStreams.deregister_extension(:encode)` returns `nil`. It is applied with `#encoding`, see Added, and still with `#option` or `#stream`, as before.
- **`:none` cannot be registered as an extension.** It is a reserved keyword, which `#stream` takes to apply no streams, so `IOStreams.register_extension(:none, ...)` raises `ArgumentError`. Previously it registered a stream that `stream(:none)` could not apply.
- **An extension registered with just its reader and writer classes is neither compressed nor encrypted.** So after replacing a built-in extension that is, such as `:xlsx`, `:gz` or `:pgp`, with your own reader and writer classes, `#compressed?` or `#encrypted?` is now `false` for its files, where previously both were based on the file name. Register a format that answers `compressed?` or `encrypted?` to keep them `true`.

These bug fixes change behavior that existing code may depend on:

- **`allowed_columns`, `required_columns` and `skip_unknown` now also apply when reading rows** with `each(:array)`: to the supplied `columns:`, and to the header row with `cleanse_header: false`. Previously they were ignored in both cases, as they were when reading records. The header row is still yielded as it was read, and each row still contains every value. Set `IOStreams.enforce_column_restrictions = false` to keep the previous behavior, which logs a warning when applying them would change the header row.
- **`each(:array)` and `reader(:array)` yield each row of every format as an Array**, as they did for CSV, PSV and spreadsheets, so that the rows of a JSON, fixed width or Parquet file can be written with `writer(:array)`, and copied with `copy_from(source, mode: :array)`. A fixed width file, a JSON or Parquet file with a schema, and a file whose schema has `header: false`, have no header row, so the first row is a header row of the names of the fields, and each row after it the values of the fields, in order, `nil` for a key that a JSON record does not have, so that every file whose columns are known starts with a header row, unless the deprecated `columns:` are supplied, which name the values of the rows instead, as before, whatever the format. Without a schema, the first row of a JSON or Parquet file is a header row of the keys of its first record, and each row after it the values of a record in that order, `nil` for a key that it does not have, so a record with a key that the first record does not have raises `IOStreams::Errors::InvalidHeader`, since no row has a column for it. `#header?` of the reader that `reader(:array)` yields says whether the first row is a header row. `allowed_columns`, `required_columns` and `skip_unknown` apply to the keys of the first record, and never change a row. `writer(:array)` of a JSON file without a schema or `columns:` takes the first row as its header row, as for CSV, without writing a line for it, where it raised `IOStreams::Errors::InvalidHeader`. A JSON line that is not an object, such as `[1,2]` or `5`, raises `IOStreams::Errors::TypeMismatch`, also with `each(:hash)`, where `each(:array)` yielded it, and a line of `{}` is read as `nil`, like `null`, also with a schema, where `each(:array)` yielded `{}`. Previously the rows of these files were the Hashes that `each(:hash)` reads, which `writer(:array)` and a copy rejected with `ArgumentError: Must supply an Array`, and the column options were ignored for them. Read Hashes with `each(:hash)`. Rocket Job reads the header row of the rows of a JSON file that it uploads in its `:array` mode, so upgrade it with IOStreams.
- **A blank row is the same in every format**, and is read as `nil`, as a blank line already was: a line that is empty or only whitespace, including Unicode whitespace such as a no-break space (U+00A0), as Rails' `String#blank?` matches it, or a row or record whose every value is `nil` or such text. Previously `each(:array)` and `each(:hash)` returned a row or record of `nil` values for a line of CSV or PSV of only delimiters, such as those that Excel writes after the last row, a JSON or Parquet record whose every value is null, and a fixed width line whose every field is blank, although its filler held text, while a row of empty spreadsheet cells was `nil`, and only spaces, tabs and line endings were whitespace. So a copy now skips those rows too, a header row of only blank values is skipped, so that the header row is the next one, a blank row no longer raises `IOStreams::Errors::InvalidValue` for a field that is required, and `IOStreams::Tabular#record_parse`, which Rocket Job's workers parse the rows of a slice with, returns `nil` for it. A value such as `false` or `0` is data, so a row that holds one is not blank. Supply `skip_blanks: true` to skip blank rows, see Added.
- **PGP email addresses match exactly.** An email address now only matches keys with exactly that email address, ignoring case, for the writer's `recipient` and `signer`, and the `email:` argument of `IOStreams::Pgp.list_keys`, `key?`, `export`, `delete_keys` and `set_trust`. gpg treats a bare email address as a search for any user id containing it, so `delete_keys(email: "bob@example.com")` also deleted the keys for `jimbob@example.com` and `bob@example.com.attacker.net`, `set_trust(email:)` could trust one of those keys instead, and when the key for the recipient was missing, the file was encrypted to one of those keys instead of failing.
- **Reading gzip returns every member.** Reading a gzip file that contains several members, for example gzip files that were concatenated, returns the contents of every member, as `gunzip` does. Previously only the first member was returned, without an error. Zero bytes after the last member are ignored. The stream supplied to the block when reading gzip is no longer a `Zlib::GzipReader`, see the stream supplied to a reader block, below.
- **The `:encode` stream keeps valid characters, and validates every read.** It keeps valid characters in data read from a file. Data read from a file has no encoding, so it was converted from binary, where every byte above 127 is undefined: with `replace:`, for example `option(:encode, encoding: "UTF-8", replace: "")`, every non-ASCII character was removed, turning `José` into `Jos`, and without it, reading a whole file raised `Encoding::UndefinedConversionError` for any non-ASCII character. Binary data is now treated as already being in the requested encoding, so only invalid characters are replaced, or raise `Encoding::UndefinedConversionError`, when reading and when writing. Previously reading lines let invalid characters through without raising. With `replace:`, the sizes of fixed width columns read through the encode stream as UTF-8 now count characters, as they already did without it, where they counted bytes, since each byte of a non-ASCII character was replaced. A multi-byte character split across two blocks is kept, where previously reading lines could raise `ArgumentError: invalid byte sequence in UTF-8` for files over 64KB. The encode reader also accepts the buffer argument of `IO#read`, so that `#copy_from` and `#copy_to` with an encode stream no longer raise `ArgumentError`, and each read returns a new string. Data read is treated as bytes whichever streams it was read through, so reading the whole of a `.gz` or `.enc` file is no longer converted from `Encoding.default_external` first, which, for example, made `option(:encode, encoding: "Windows-1252").read` raise for a Windows-1252 `.gz` file but not for the same data in a plain file.
- **Writing PGP to an IO streams the encrypted data into it.** Writing PGP to an IO supplied to `IOStreams.stream`, such as a `StringIO`, a socket, or a `File`, now writes the encrypted data to it as it is written, instead of copying it there from a temp file once the block completes. So when the block raises, or `gpg` fails, the IO holds the start of a PGP message, which reading raises `IOStreams::Pgp::Failure` for, where previously nothing was written to it. A local path still removes its partial file. The stream supplied to the block when writing PGP, or when reading PGP from an IO that is not a local file, is no longer an `IO`; like the other streams, it responds to `#write`, `#<<`, `#print`, `#puts` and `#printf` when writing, and to `#read`, `#readpartial`, `#gets`, `#each_line` and `#eof?` when reading.
- **A `+` in an S3 or SFTP url is kept.** `IOStreams.path("s3://bucket/a+b.csv")` now reads the key `a+b.csv`. Previously the path of an S3 or SFTP url was decoded like a query string, so a `+` became a space and it read the key `a b.csv`. Use `%20` or a space for a space.
- **A `%`, `?` or `#` in an S3 or SFTP name is percent-encoded in `#to_s`**, as `%25`, `%3F` or `%23`, so that the path can be created again from its url. For example the file `a#b.csv`, found by `#each_child` or joined to a path, is `sftp://host/data/a%23b.csv`, where it was `sftp://host/data/a#b.csv`, which is the file `/data/a` when created again, so that an application that stored the url read or wrote another file. `#path` and `#basename` are unchanged.
- **The `#path` of an HTTP(S) url is decoded**, like S3 and SFTP paths, so `IOStreams.path("https://example.com/my%20file.csv").path` is `/my file.csv`, and `#basename` is `my file.csv`. Previously it was percent-encoded, as `/my%20file.csv`, unlike S3 and SFTP paths, and unlike a path from `#join`, which was not encoded. `#to_s` is unchanged. A url without a path, such as `https://example.com`, has the path `/`, where it was empty.
- **An SFTP or HTTP(S) url without a path ends with `/`**, like the root of an S3 bucket, `s3://bucket/`. `IOStreams.path("sftp://host").to_s` is now `sftp://host/`, and `IOStreams.path("https://host?a=1").to_s` is `https://host/?a=1`. Previously the url was returned as supplied, so `IOStreams.path("sftp://host")` was not equal to `IOStreams.path("sftp://host/")`, or to its own `#directory`, and they were different `Hash` keys, although they are the same location.
- **A direct copy between S3 paths is made with the client and options of its target.** `#copy_to` with `convert: false`, and `#move_to`, from one S3 path to another now request the copy with the client of the target, and its options, such as `acl:` and `storage_class:`, as `#copy_from` with `convert: false` already did, and with the source's customer encryption key, as `copy_source_sse_customer_algorithm`, `copy_source_sse_customer_key` and `copy_source_sse_customer_key_md5`, and its `request_payer`, which S3 needs to read the source. Previously they used the client and options of the source, so moving an object into a bucket of another account dropped the ACL that the bucket required, such as `acl: "bucket-owner-full-control"`, the new object took the storage class of the source, and the source's customer key was supplied as the key to encrypt the new object, rather than to read the source. To keep an option of the source for the new object, such as its `storage_class:`, set it on the target too.
- **A direct copy between S3 paths returns the number of bytes copied**, like every other copy. `#copy_from` with `convert: false` from another S3 path returned the response from the `copy_object` call, and `#copy_to` with `convert: false` to another S3 path returned the target path. Copying between S3 paths with conversions, or with any other path, already returned the number of bytes. `#move_to` still returns the target path.
- **Local `#each_child` and `IOStreams.each_child` honor `case_sensitive:` on every platform.** On a case-sensitive file system, such as on Linux, the default `case_sensitive: false` was ignored unless nothing matched, so `"r*.md"` did not return `README.md`, and `"*.csv"` did not return `DATA.CSV` when `data.csv` was also present. On a case-insensitive file system, such as on macOS, `case_sensitive: true` was ignored, so `"*.CSV"` returned `data.csv`.
- **The file within a zip file written to a path is named after the path.** Writing `example.csv.zip`, or `example.csv.zip.pgp`, now names the file within the zip file `example.csv`, as documented. Previously it was named `file`, unless `entry_file_name:` was supplied.
- **A hash key that matches a column once cleansed supplies its value.** When writing a hash with `columns:`, or reading JSON or `:hash` records with `columns:`, a column without a key of the same name now takes the value of the key that is the same once both are cleansed like a header row, so the key `"First Name"` supplies the column `first_name`. Previously the column was always empty, so for example `writer(:hash, columns: ["first_name"])` wrote an empty field for `{"First Name" => "Jack"}`. A key that matches the column exactly is still used first.
- **Writing to an SFTP path returns the result of the block**, like local and S3 paths, for example from `#writer`. Previously it returned the size of the file written.
- **`#reader`, `#writer`, `#copy_from` and `#copy_to` raise `ArgumentError` for options they cannot use**, whatever their value, including nil, instead of ignoring them, so that a misspelled option is reported. This applies to options supplied to the `:stream` mode, which is the default, to `#copy_from` and `#copy_to` without a `mode:`, and to `#copy_from` and `#copy_to` with `convert: false`, including `mode:`. Options for the `:line`, `:array` and `:hash` modes already raised.
- **Misspelled stream options raise when they are set.** An option supplied to `#option` or `#stream` that neither the reader nor the writer for the stream accepts now raises `ArgumentError` when it is set, even when the file name does not include that stream, so a misspelled option is reported wherever the code runs. Previously it was only checked once the stream was used, so for example `IOStreams.path("data.csv").option(:pgp, recipent: "partner@example.org")` was ignored, and only raised for a `.pgp` file, which could be only in production when the path comes from configuration.
- **The gzip and `.enc` streams no longer close the IO supplied to them**, like every other stream. Reading or writing an IO with `IOStreams.stream(io)` through the `:gz`, `:gzip` or `:enc` stream closed `io` when the block finished, while the `:bz2`, `:zip`, `:pgp` and `:encode` streams left it open.
- **Text written with an encoding to an IO supplied to `IOStreams.stream` is written in that encoding**, as it is to a file, even when the IO converts the text written to it to an encoding of its own, as a `StringIO` does, a file opened with an encoding, such as `File.open(name, "w:UTF-8")`, and any file opened in text mode in a Rails process. Previously the IO converted it back to its own encoding, so `encoding("Windows-1252")` wrote `café` to a `StringIO.new` as UTF-8. The String of such a `StringIO` now holds the bytes of the encoding that was set, but keeps its own encoding, UTF-8, so read it with `force_encoding`, such as `io.string.force_encoding("Windows-1252")`, or supply a `StringIO` of a binary String, such as `StringIO.new(+"".b)`. To write the text in the encoding of the IO, as before, do not set an encoding.
- **The bzip2 stream no longer switches an IO supplied to `IOStreams.stream` to binary mode**, when reading or writing, so that it leaves your IO as it was, as the gzip, zip, zstd, `.enc` and encode streams do. Previously bzip2-ffi switched it for good, so the String of a `StringIO.new` that `.bz2` data was written into, or read from, became binary (`ASCII-8BIT`), where it now keeps its encoding, UTF-8 by default, with the same bytes. Adding those bytes to a binary String, such as data read from a database, raises `Encoding::CompatibilityError`, so supply a `StringIO` of a binary String, such as `StringIO.new(+"".b)`, or call `.b` on its String. A file opened in text mode stays in text mode, and the streams still write their bytes to it as they are, see Fixed. Writing PGP or Parquet, and copying without any streams, still switch a `File` that you supply to binary mode, as `IO.copy_stream`, which writes it, does, as PGP and copies did in v2.1.
- **Writing `.gz`, `.bz2` or `.enc` to an IO no longer completes the data when the block fails.** When the block supplied to `#writer` raises, or the thread writing is killed, the end of the compressed or encrypted data, such as the gzip trailer or the last block of the cipher, is no longer written to an IO supplied to `IOStreams.stream`, such as a `StringIO`, a socket or a pipe, so that whoever reads it cannot take the data written before the failure for a complete file: reading it raises, or returns no data. Previously the end was written, so the partial data read back without an error. `.zst` (see Added) behaves the same way, and reading the compressed data flushed before the failure raises `RuntimeError: zstd decompress error: Truncated source`. Leaving the block early, such as with `break`, still writes the end, so that what was written is complete. Paths are not affected, since a local path removes its partial file, and S3, SFTP and HTTP paths only store a file once the block completes.
- **The stream supplied to a reader block is no longer the reader of a gem.** When reading `.gz`, `.bz2`, `.zip` or `.enc`, or PGP within another stream or from an IO that is not a `File`, see Fixed, the stream is no longer the reader of its gem, or the pipe from `gpg`, such as a `Zlib::GzipReader`, a `Bzip2::FFI::Reader`, a `Zip::InputStream` or a `SymmetricEncryption::Reader`. Like every other stream, it responds to the methods of an IO that read, `#read`, `#readpartial`, `#gets`, `#readline`, `#readlines`, `#each_line`, `#each` and `#eof?`, which now behave as they do for an IO whichever streams the data uses, so that code that reads a `.gz` file, or a library that reads an IO, such as `CSV.new(io)`, still works when the file name changes to `.bz2`: `read(length)` returns `length` bytes unless the data ends first, and nil at its end, a buffer supplied to `#read` holds only the bytes read, and is emptied at the end of the data, `#readpartial` raises `EOFError` at the end of the data, and `#eof?` is true once all of the data has been read. Previously the `.bz2` stream had no `#readpartial`, `#gets`, `#readline`, `#readlines` or `#each_line`, the `.zip` stream and the stream of an `.enc` file written with `compress: false` had no `#readpartial`, a `.zip` stream left the data of an earlier read in the buffer at the end of the data, and kept the encoding of the buffer, as did a compressed `.enc` stream, and `#eof?` of a `.bz2` stream could be false once all of its data had been read. The other methods of those readers, such as `#rewind`, `#pos`, `#lineno`, `#getc` and `#size`, now raise `NoMethodError`, as does a library that calls them. The encode stream, applied with `#encoding`, reads like an IO that converts text, such as `File.open(name, "r:Windows-1252:UTF-8")`, so that `CSV.new(io)` reads the stream whether or not an encoding is set: it responds to the same methods, which return text in the encoding that is read, where in v2.1 it had only `#read`, and a limit supplied to `#gets` that would split a character reads to the end of it. Unlike an IO, which reads bytes with a length, `read(length)` and `#readpartial` return whole characters, up to `length` bytes of them, or the first character when it is longer, where in v2.1 `read(length)` returned `length` bytes, which could end within a character, or more than `length` bytes when it converted the text from another encoding. Read lines with `each(:line)` or `reader(:line)`, or where the stream must be a `File`, copy the file into a local file first, for example with `copy_to(local_path, convert: false)`.
- **Reading a corrupt file within a zip file raises `IOStreams::Errors::StreamFailure`, tagged as `IOStreams::Errors::Corrupt`**, naming the file and the zip file, such as `The file "data.csv" within the zip file /data/a.zip is corrupt: invalid entry CRC (expected 0x9d0b854a but got 0x1e367632)`, once all of the file has been read and its size or CRC32 is not the one that the zip file records. Previously the corrupt data was returned without an error on MRI, since `rubyzip` does not check either, and on JRuby it raised `SystemCallError: Unknown error`.
- **A zip file that does not contain the file to read raises `IOStreams::Errors::StreamFailure`, tagged as `IOStreams::Errors::MissingEntry`**, naming the zip file, and the file when `entry_file_name:` is supplied, such as `The zip file /data/a.zip does not contain the file "missing.csv"`, on every platform. Previously a zip file of only folders did not call the block on MRI, so `#read` returned nil and `#each` yielded nothing, and a missing `entry_file_name:` raised `Errno::ENOENT` naming only the file within the zip file, as if the zip file itself were missing, while on JRuby both raised `TypeError: exception class/object expected`. A folder supplied as `entry_file_name:` raises the same way, where it read as empty on MRI. On JRuby, which reads zip files with Java's own support, a file that is not a zip file, such as an empty file, now raises `IOStreams::Errors::StreamFailure` tagged as `IOStreams::Errors::Corrupt`, where it read as empty. On MRI it still raises the `Zip::Error` of `rubyzip`, now tagged as `IOStreams::Errors::Corrupt`. JRuby does not load `rubyzip` to read a zip file. See Added for the kinds of failure of a stream. The messages, and the `#display_name` of the exception, name the zip file by the display name of the path that is read, such as `/data/a.zip`, `s3://bucket/a.zip`, or a url without its credentials or query, or by the file name of a stream, rather than the temp file that a zip file that is not a local file is copied into, as does the message of the `Zip::Error` of `rubyzip` on MRI, such as `archive/bad.zip: Zip end of central directory signature not found`.
- **An empty `.bz2` file raises `IOStreams::Errors::Corrupt`**, as `bzip2 -d` does, since bzip2 data always starts with its header, even when it holds no data. Previously it read as empty, so an empty file, such as one whose upload failed before it started, could not be told apart from a file without any data. The exception is an `IOStreams::Errors::StreamFailure`, with the message `The bzip2 data is empty`.
- **An empty `.enc` file raises `IOStreams::Errors::Corrupt`**, since the writer never writes one: encrypting no data still writes the header, or a block of padding. Previously it read as empty. The exception is an `IOStreams::Errors::StreamFailure`, with the message `The encrypted data is empty`.
- **A url that cannot be parsed raises `ArgumentError`, without its password or query in the message.** Creating a path from an S3, SFTP or HTTP(S) url that `URI` cannot parse, such as an SFTP url whose password holds a `/`, `?` or `#`, or an HTTP url with a space, raised `URI::InvalidURIError`, whose message is the whole url, so the password, or a token in its query, was written to logs and error trackers. The message now names the url with everything before its last `@` replaced with `[FILTERED]`, since such a password can hold these characters, and without its query or fragment, such as `Invalid url "sftp://[FILTERED]@example.org/a.csv": it cannot be parsed`. Rescue `ArgumentError` instead of `URI::InvalidURIError`, and supply a password that holds one of these characters with `password:`.
- **A url part or S3 argument that a path cannot use raises `ArgumentError` when the path is created**, rather than being ignored, so that a mistake in a configured url is reported wherever the code runs. The message names the url without its user name, password or query, and says what to supply instead:
  - an S3 url with a fragment, such as an unencoded `#` in `s3://bucket/a#b.csv`, which read the key `a`: encode it as `%23`, as `#to_s` does;
  - an S3 url with a port, such as `s3://bucket:9000/a.csv`: supply the endpoint of a service that implements the S3 API with `client: {endpoint: "https://host:9000"}`;
  - an S3 url with a user name or password, such as `s3://AKIA...:secret@bucket/a.csv`: supply the credentials with `access_key_id:` and `secret_access_key:`;
  - an S3 url without a bucket, such as `s3:///a.csv`, whose `#to_s` named the key as the bucket;
  - an SFTP url with a query, such as `sftp://host/a.csv?IdentityFile=/tmp/key`, whose ssh options were ignored: supply them with `ssh_options:`, since an option such as `ProxyCommand` runs a command, so a url cannot hold one, and encode a `?` in a file name as `%3F`;
  - an SFTP url with a fragment, an unencoded `#`: encode it as `%23`;
  - an SFTP or HTTP(S) url without a host, such as `sftp:///a.csv` or `http:///a.csv`;
  - an S3 path whose `client:` is an `Aws::S3::Client`, with `region:`, `access_key_id:` or `secret_access_key:`, which the client ignored since it has its own: supply them to `Aws::S3::Client.new`, or supply `client:` as a Hash of the options of a new client, such as `client: {endpoint: "https://..."}`, which they are added to.
- **A local `#move_to` onto an existing directory raises `ArgumentError`**, which names the file within it to supply instead, such as `IOStreams.path("/archive").join("a.csv")`, like every other path, which cannot move a file onto a directory. Previously it moved the file into the directory, like `mv`, and returned the directory rather than the file.
- **S3 `#exist?` is true for a directory**, like a local or SFTP path: a path within which there are other keys, such as `s3://bucket/a` for the key `a/b.csv`, or a folder object, such as `a/`, as `#directory?` already answered. When no object has the key, `#exist?` makes a second request, which lists a key within the path. Use `#file?` to check for an object only, with one request. The bucket itself, such as `s3://bucket/`, exists, and is a directory, when the bucket exists and can be listed; previously `#directory?` was always true for it, even when the bucket did not exist, and `#exist?` raised `ArgumentError: :key must not be blank` from the AWS SDK. `#size` and `#mtime` of the bucket raise `Errno::EISDIR`, tagged as `IOStreams::Errors::NotFound`, saying that the bucket is not an object, so `#size?` returns nil. S3 `#delete` of a directory still does nothing, since no object has its key, and nor does `#delete` of the bucket itself, which raised `ArgumentError: :key must not be blank` from the AWS SDK; use `#delete_all` to delete the keys within it.
- **A name joined to an S3 bucket is a key within it, and a key that starts with `/` keeps it in its url.** A name that starts with `/` joined to the bucket itself, such as `IOStreams.path("s3://bucket") / "/exports/a.csv"`, or `IOStreams.join("/exports/a.csv")` with the root `s3://bucket`, is now the key `exports/a.csv`, as a name joined to the local directory `/` is within it. Previously it was the key `/exports/a.csv`, which S3 holds as another object, and whose `#to_s` was `s3://bucket/exports/a.csv`, the url of the key `exports/a.csv`, so the path did not name the same object when created again from its url, and it passed the allowed path `s3://bucket/exports`, although it is not within the `exports/` prefix. `#to_s` now keeps a key that starts with `/`, such as `s3://bucket//exports/a.csv`, which is within the allowed paths only when the allowed path's key starts with `/` too. To read an object written with such a key by a previous version, name it in the url, such as `IOStreams.path("s3://bucket//exports/a.csv")`.
- **Local `#each_child` raises `Errno::EACCES`, tagged as `IOStreams::Errors::PermissionDenied`, for a directory that cannot be read**, like SFTP, rather than return nothing, as `Dir.glob` does, so that an unreadable directory no longer looks empty. This is the directory that the pattern lists within, such as `data` for `IOStreams.path("data").each_child("*.csv")`, or `data/in` for `each_child("in/*.csv")`. A directory that does not exist, or a file, still returns nothing, and a directory within it that cannot be read is still skipped while listing with `**`, like `Dir.glob` and SFTP. Rescue `IOStreams::Errors::PermissionDenied` to treat it as empty.
- **Paths compare by the parts of their full name that identify the file, as each kind of path decides.** `==` and `<=>` compared only `#path`, so paths with the same key or file name compared equal across S3 buckets, SFTP or HTTP hosts and ports, and stores, for example `IOStreams.path("s3://bucket-a/x.csv") == IOStreams.path("s3://bucket-b/x.csv")`, and comparing a path with anything else, such as a `String`, raised `NoMethodError`. A path is now equal to a path of the same class that names the same file, whatever its streams and options, and is not equal to anything else, including a `String`, even its own name, as with `Pathname#==`. A local path compares its name as it is written, as `Pathname#==` does, so a relative name is not its absolute name; an S3 path its bucket and key as they are, but not its options, such as those in the query of its url; an SFTP url its host, ignoring case, its port, with or without the default port 22, and its decoded path, which is the name that the server is sent, so `sftp://Example.org:22/a%20b.csv` equals `sftp://example.org/a b.csv`, and its user name only for a path within the login directory, such as `sftp://host/~/a.csv`; and an HTTP(S) url its scheme and host, ignoring case, its port, with or without the default port of its scheme, and its path and query, in which each percent-encoded letter, digit, `-`, `.`, `_` or `~` is the same as the character, as RFC 3986 normalizes urls, so `https://Example.com:443/%7Ea.csv` equals `https://example.com/~a.csv`, while `%2F` is not `/`. The password and the other arguments of a path, and the fragment of a url, are not compared, and `.` and `..` are not resolved. Equal paths are the same `Hash` key, so `#uniq` removes duplicates, and `<=>` sorts paths by their full name, spelled as `==` compares it, so that equal paths sort together.
- **`#path` is read-only.** `Path#path=` is no longer public, so `path.path = "b.csv"` raises `NoMethodError`. Changing the path in place also changed the path's `#hash`, so a path used as a `Hash` key or in a `Set` could no longer be found, and it was never documented. Use `#join` or `#directory`, which return a new path with the same settings, such as the S3 client or SFTP credentials, or `IOStreams.path` with the new name.
- **`#builder=` is no longer public** on a path or a stream, so it raises `NoMethodError`. It takes an internal object, and was only used by `#join` and `#directory` to clear the streams and options of a new path. To start again without the streams and options set with `#stream` or `#option`, create the path again with `IOStreams.path`.
- **`IOStreams.path`, `IOStreams.stream`, `IOStreams.new`, `IOStreams.join`, `IOStreams.root` and `IOStreams.roots` return a copy instead of an existing path or stream.** `IOStreams.path(path)` and `IOStreams.stream(stream)` returned the path or stream supplied, so `IOStreams.path(path).option(:pgp, passphrase: "secret")` also changed `path`. `IOStreams.join` without any elements, `IOStreams.root` and `IOStreams.roots` returned the root paths themselves, so `IOStreams.join.stream(:none)` changed the root for the whole process. Each now returns a copy with the same streams and options, which is equal to the original, see `#==`, but is a different object. `Path#join` without any elements also returns a copy instead of itself. `#copy_from`, `#copy_to` and `#move_to` still use, and return, the path supplied to them.
- **`IOStreams.add_root` freezes the root path, and returns it frozen.** Previously the path it returned was the root itself, so `IOStreams.add_root(:default, "/data").stream(:gz)` changed the root for the whole process. Changing the returned path now raises `FrozenError`. `IOStreams.root` and `IOStreams.join` still return copies that can be changed.
- **S3 options are strict.** An option supplied to an S3 path, or in the query string of its url, that no S3 request accepts now raises `ArgumentError` when the path is created, for example a misspelled `acll: "public-read"`, as does a request parameter that the path sets itself, such as `key` or `bucket`. Previously an unknown option raised from the AWS SDK when the path was used.
- **An SFTP url without a path is the root directory `/`, and a path starting with `~` is within the login directory.** `IOStreams.path("sftp://host").each_child` lists `/`, like `sftp://host/`. Previously it listed the login directory, but returned children in `/`, so reading a listed file read `/a.csv` instead of the file in the login directory. Use `sftp://host/~` to list the login directory, and `sftp://host/~/data/a.csv` for the file `data/a.csv` within it, as curl does.
- **A failed copy to S3 no longer deletes the target.** `#copy_from` an S3 path no longer checks whether the object exists first, or deletes a new object when the copy fails. S3 only stores an object once its upload completes, so there is never an incomplete object to delete. The delete could instead remove a complete object when only the response to its upload was lost, or an object that another writer created during the copy. This also saves a HEAD request on every copy.
- **A redirect from `https` to `http` is not followed** when reading an HTTP(S) path, and raises `IOStreams::Errors::CommunicationsFailure`. Previously the download continued over plain http, where the data could be read or changed in transit.
- **A `Content-Encoding` that IOStreams cannot decompress raises `IOStreams::Errors::CommunicationsFailure`** when reading an HTTP(S) file through streams that neither compress nor encrypt it, such as `data.csv`, before the block is called, naming the `Content-Encoding` and the url. That is any `Content-Encoding` other than `gzip`, `x-gzip`, `identity` or `none`, such as `br`, `zstd`, `deflate`, `compress`, `gzip, gzip`, or a value that is not a content coding, such as `utf-8`. Previously the body was returned as the file while it was still encoded, apart from `deflate`, which Net::HTTP decompressed, see Fixed. To read the body as it is sent, supply `headers: {"Accept-Encoding" => "identity"}`, or read the file with `#raw`.
- **SFTP `#each_child` is case-insensitive by default**, like local and S3 paths, as documented, so `"*.csv"` also returns `DATA.CSV`. Previously SFTP defaulted to `case_sensitive: true`. Supply `case_sensitive: true` to keep the previous behavior.
- **`#size` raises `IOStreams::Errors::NotFound` for a file that does not exist** on S3, SFTP and HTTP paths, as it already did for a local file, which raises `Errno::ENOENT`, like `File.size` and `Pathname#size`, so that it behaves the same way wherever the file is stored. Previously it returned `nil`. `#size?` still returns `nil` for a file that does not exist, or that is empty, like `File.size?`. A direct copy within S3 of an object that does not exist still raises `Aws::S3::Errors::NoSuchKey`.
- **SFTP `#each_child` returns a symbolic link to a file**, like a local path, and like an exact name, which it already returned. A server lists a link with its own attributes, so every link to a file was skipped. A link is now a file or a directory by what it refers to, and is yielded with the attributes of what it refers to, such as its size, where with `directories: true` it was yielded with the attributes of the link itself. A directory that a link refers to is still not listed, like `Dir.glob`, and a link that refers to nothing is only returned with `directories: true`, as before.
- **S3 and SFTP `#each_child` match an exact name ignoring case by default**, like a pattern and a local path. When no object or file has a name without pattern characters, such as `README.MD`, the directory is listed, and a name that differs from it only in case, such as `README.md`, is returned. Previously an exact name was looked up as it was, ignoring the default `case_sensitive: false`. A name that is found is still returned without listing the directory, so a second name that differs from it only in case is not returned with it, as it would be for a local path on a case-sensitive file system. Supply `case_sensitive: true` to only look up the exact name.
- **SFTP `#each_child` returns nothing for a directory that does not exist**, or for a path that is a file, like local and S3 paths. Previously it raised `Net::SFTP::StatusException`. It also only lists the directories that the pattern can match within, so `"*.csv"` lists only the path's directory, where it listed every directory below it, and skips a directory below the path that cannot be read, like `Dir.glob`, where it raised `Net::SFTP::StatusException`. Errors such as a path that cannot be read still raise.
- **S3 `#each_child` returns directories with `directories: true`**, like local and SFTP paths, such as `a` and `a/b` for the key `a/b/c.csv`. Previously it only returned empty folders created with a key ending in `/`, only with a pattern that included `**`, and with the trailing `/`, such as `s3://bucket/a/`. An empty folder is now returned without the trailing `/`, and its attributes are those of the folder object when every key below the directory is listed, such as with `**/*`, as before; other directories, and the directories of a pattern that can only match names directly within the directory, such as `*`, which S3 lists by name only, have empty attributes.
- **An exact name supplied to `#each_child` is returned the same way as one that matches a pattern.** On an S3 path it is now yielded with its attributes, like the children that match a pattern. `IOStreams.each_child` with a name without any pattern characters now yields the attributes for S3 and SFTP paths, and only yields a directory with `directories: true`; previously it yielded only the path, and yielded a local directory regardless.
- **S3 and SFTP `#each_child` match a pattern the same way as local paths.** A pattern is within the path even when it starts with the path's own name, so `IOStreams.path("s3://bucket/data").each_child("data/*.csv")` lists `s3://bucket/data/data/`, where it listed `s3://bucket/data/`. A backslash escapes the next character, as documented, so `each_child("a\\b.csv")` returns `ab.csv`, where S3 and SFTP looked for a name containing the backslash.
- **Local `#each_child` returns `nil`**, like S3 and SFTP paths. Previously it returned an internal array of the names it found, including directories that it did not yield.
- **A local file name of `~`, or starting with `~/`, is within the home directory**, for example `IOStreams.path("~/data/a.csv")` is `/home/user/data/a.csv`, as `sftp://hostname/~/data/a.csv` is within the login directory, so a configured path can change between local files and SFTP without changing the code. Previously it was within a directory called `~` in the current directory. Use `./~/data/a.csv` for that directory, and a warning is logged via `IOStreams.logger` when the current directory contains one. `#each_child` yields a child of such a directory as `./~/a.csv`, also for a pattern that starts with `~/`, such as `IOStreams.path("").each_child("~/*.csv")`. A name such as `~user/a.csv` or `~$Book1.xlsx` is unchanged.
- **`#compressed?` and `#encrypted?` follow the streams.** They are true when a stream in the pipeline compresses or encrypts the data, whether it was inferred from the file name or set with `#stream`, so `IOStreams.path("data.csv.gz.pgp").compressed?` and `IOStreams.path("tempfile2527").stream(:gz).compressed?` are now true, and `IOStreams.path("data.csv.gz").stream(:none).compressed?` is now false. Previously they only checked the last extension of the file name. Compression within PGP or `.enc` data is still not reported, since only the encrypted data records whether it was used.
- **A file name ending in `.encode` no longer applies the `:encode` stream.** It is applied with `#encoding`, see Added, since file names do not name it. Previously `IOStreams.path("notes.encode")` read and wrote its data through the encode stream, which for example raised `Encoding::UndefinedConversionError` for binary data.
- **The `cleaner` option of the `:encode` stream is strict.** A `cleaner` that is neither the name of a built-in rule nor a Proc, such as the String `"printable"`, raises `ArgumentError` when it is set. Previously it was ignored, so the data was not cleansed. Use a Symbol, such as `cleaner: :printable`.
- **Writing an S3, SFTP or HTTP(S) file keeps what was written when the block leaves early**, such as with `break`, as a local file does, since leaving early is intended. Previously nothing was stored, and an S3 multipart upload was left incomplete, with its parts kept by S3. A stream registered with `IOStreams.register_extension` whose writer only writes files also keeps what was written, as a writer of streams does, where its output was discarded. Writing PGP completes the PGP message with what was written, so that it can be read, where a local `.pgp` file was left empty, and nothing was written to an IO supplied to `IOStreams.stream`. To discard what was written, raise an exception from the block instead.

- **The rows of a spreadsheet are CSV, whatever format its file name names.** A spreadsheet is read as CSV, one line for each row of its worksheet, so its rows and records are now always parsed as CSV, and `#format` returns `:csv` for a `.xlsx` or `.xlsm` path, where it returned `nil`. Previously the format was taken from the file name, so `report.json.xlsx` parsed the CSV of each row as JSON, which raised, and `report.psv.xlsx` as PSV, which joined the cells of each row into one value. Setting another format with `#format`, such as `format(:psv)`, now raises `ArgumentError` when the rows, records or lines are read or written, rather than parse them in that format. `each(:line)` keeps a line break within a cell in its line, as for a CSV file, where it split the line there.
- **A date or time cell of a spreadsheet is read as ISO 8601**, as a field of type `any` writes it, so that a field of type `date` or `datetime` of a schema can read it: a date cell as `2026-01-02`, as before, and a time cell as its time of day in UTC, such as `2026-01-02T09:30:00Z`, since Excel holds a time without a time zone. Previously a time cell was the text of the `Time` that `creek` returns in the local time zone of the process, such as `2026-01-02 09:30:00 -0500`, which a field could not read, and which differed between processes in different time zones. A decimal cell that `creek` returns as a `BigDecimal` is read as a plain decimal, such as `12.5`, where it was `0.125e2`. Every other cell reads as before.
- **A writer supplied to `IOStreams.stream` raises for what it cannot apply.** A line, row or record writer that is already open, such as the one that `writer(:line)` yields, handed to code that calls `IOStreams.stream(io).writer(:line)`, is still used as it is, but options of the call, such as `delimiter:` or `columns:`, streams, an encoding, and for lines, a format or a schema, now raise `ArgumentError`, since the open writer writes with its own. Previously they were ignored, so for example `writer(:hash, columns: ["a"])` wrote every column.
- **A `Pathname` names a file.** `IOStreams.new` returns the path of a `Pathname`, such as `Rails.root.join("data.csv.gz")`, and `#copy_from` and `#copy_to` read and write the file that it names, applying its streams, where they treated it as an IO, so that for example copying from a `Pathname` of a `.gz` file wrote its compressed bytes. `IOStreams.stream` raises `ArgumentError` for a `Pathname`, as it does for a String, rather than failing once it is read.
- **Leaving a PGP reader block early still checks the file.** When the block leaves early, such as with `break` or `return` after reading the first line, the rest of the file is decrypted and checked, as when the block returns before reading all of it, so `IOStreams::Pgp::Failure` is raised when the file fails gpg's integrity or signature checks, such as a file changed after it was written, or without integrity protection (MDC) read without `ignore_mdc_error`, or was not signed by the `signer`. Previously leaving early stopped gpg without checking anything, so `each(:line) { |line| ...; break }` accepted a file that was changed after it was written. Checking the rest takes as long as reading the whole file. To stop without checking the file, raise an exception from the block instead.
- **Writing PGP raises `ArgumentError` for a missing, empty or blank recipient or signer before the file is opened**, so that an existing file is kept: writing without a `recipient` or `import_and_trust_key`, with an empty list of recipients, such as `recipient: []`, with a blank recipient, key or signer, such as `recipient: [""]` or `signer: ""`, and with `encrypt: false` without a `signer`. Previously a local file was opened, and so emptied and then deleted, before the error was raised, and an empty list, or a blank recipient or signer, raised `IOStreams::Pgp::Failure` from gpg, such as `gpg: no valid addressees`. An empty list with `IOStreams::Pgp::Writer.audit_recipient` set still encrypts the file for the audit recipient alone, as before.
- **Without gpg, PGP raises `IOStreams::Pgp::Failure`**, naming the executable, such as `GPG Failed to run the gpg executable "gpg": No such file or directory - gpg. Install GnuPG, or set IOStreams::Pgp.executable to the gpg executable`, instead of `Errno::ENOENT`, for every call that runs gpg, including `IOStreams::Pgp.pgp_version`, and reading or writing PGP. The `Errno` error is its `#cause`.
- **`IOStreams::Pgp.set_trust` without an `email:` or `key_id:` raises `ArgumentError`**, like `key?`, `export` and `delete_keys`, instead of `IOStreams::Pgp::Failure` from gpg. The trust of no key was changed.
- **`IOStreams::Pgp.list_keys` and `IOStreams::Pgp.key_info` return the curve of an elliptic curve key as its `key_type`**, such as `"ed25519"`, `"nistp256"` or `"brainpoolP256r1"`, and the size of the curve in bits as its `key_length`, such as `255`, `256` or `521`. Previously the name was split into its letters and digits, so an `ed25519` key had the `key_type` `"ed"` and the `key_length` `25519`, a `nistp256` key `"nistp"` and `256`, and a `brainpoolP256r1` or `secp256k1` key had no `key_type`, `key_length`, `date` or `private` at all. RSA, DSA and ElGamal keys are unchanged, such as `"rsa"` and `4096`. A curve that gpg does not know, which it lists as `E_` and its OID, has that as its `key_type`, and a nil `key_length`.

- **`#absolute?` no longer ignores leading spaces.** `IOStreams.path(" /a").absolute?` is now false, and `#relative?` true, like `Pathname`, since the name is not `/a`. Previously the name was stripped first.
- **`#each`, `#reader` and `#writer` without a block raise `ArgumentError`**, which says that a block is required, before the file is opened. Previously `#each` and `#reader` raised `LocalJumpError` from within the reader, and `#writer` raised once the file was opened, which removed an existing local file.
- **A pattern supplied to `#each_child` or `#children` that is not a String raises `ArgumentError`**, such as `Pathname`'s `children(false)`. Previously it raised `NoMethodError`.
- **The `:stream` mode reads bytes from `.gz` and compressed `.enc` streams**, like every other stream, so `reader { |io| io.read }` returns an `ASCII-8BIT` String whichever streams the file uses. Previously reading the whole of a gzip or compressed `.enc` stream returned it tagged with `Encoding.default_external`, like `Zlib::GzipReader#read`, while a plain, `.bz2` or `.zip` file returned bytes. `#read`, and the `:line`, `:array` and `:hash` modes, still return UTF-8 text.
- **`IOStreams.temp_file` applies the streams that its extension implies**, like any other path, so writing to a temp file with the extension `.csv.gz` compresses the data, and `#compressed?` is true. Previously the path it yielded had `stream(:none)`, so its data was read and written as stored. IOStreams itself no longer uses it for its own temp files. To read or write the data as stored, as before, call `#raw` on the path.
- **An option for a format applies to each of its extensions.** `option(:pgp, passphrase: ...)` now also applies to a `.gpg` file, `option(:gz, ...)` to a `.gzip` file, and `option(:xlsx, ...)` to a `.xlsm` file, and the other way around. Previously an option only applied to a file name with the same extension, so changing a file name held in configuration from `.pgp` to `.gpg` silently dropped the passphrase, and also the `signer` that reading checks. When options are set for more than one extension of a format, those for the extension in the file name take precedence.
- **PGP key dates are a `Date`.** `IOStreams::Pgp.list_keys` and `IOStreams::Pgp.key_info` return the `date:` of each key as a `Date`, as they already did in an application that had loaded the `date` library, as `yaml` and Rails do. Previously it was a `String`, such as `"2017-10-24"`, in an application that had not, since IOStreams did not require the library.
- **Reading an S3 or HTTP(S) path supplies the block with an IO that is not a `File`**, now that the file is read as the block reads it, see Added. When the path has no streams, such as `data.csv`, or is read with `#raw`, the IO that `#reader` supplies responds to the methods of an IO that read, like every other stream, see above, rather than being the `File` that the path downloaded into. So `#rewind`, `#pos`, `#size` and `#path` raise `NoMethodError`, as does a library that calls them, and on HTTP the IO can only be read by the thread that called `#reader`. Where the IO must be a `File`, copy the file into a local file first, for example with `copy_to(local_path, convert: false)`.
- **`#each`, `#reader`, `#writer` and `#copy_from` no longer accept `format:` or `format_options:`**, and raise `ArgumentError` for them. Set the format on the path with `#format`, and the layout of a fixed width file with `#schema`, see Added, so that they describe the file wherever it is read, including in the `:line` mode, which splits and decodes lines for the format. They were the only way to set the format before v1.6, which added `#format` to the path.
- **A fixed width `:integer` or `:float` column that holds no number raises `IOStreams::Errors::InvalidValue`**, naming the field and the value, such as `N/A` or `12-`, when it is read or written. Previously it was converted with `to_i` or `to_f`, to `0`, or to the number that its leading digits make, such as `12` for `12-`. Writing a fraction to an `:integer` column also raises, where previously it was truncated. An `:integer` column still reads a whole number with a decimal point, such as `12.0`, as `12`, as `to_i` did, but a fraction, such as `12.5`, raises, where `to_i` returned `12`. A blank column is still read as `nil`, and a missing number is still written as zeros.
- **A `Hash` or an `Array` written to a fixed width `:string` column raises `IOStreams::Errors::InvalidValue`**, where its `to_s`, such as `[1, 2]`, was written. Any other value is still written as its text, but a `BigDecimal` is written as `12.5`, and a `Date` or `Time` in ISO 8601, such as `2026-10-13T09:30:00Z`, where their `to_s`, such as `0.125e2` or `2026-10-13 09:30:00 UTC`, was written.
- **`#writer`, `#copy_from` and `#copy_to` raise `ArgumentError` for the options that only apply when reading**, `allowed_columns:`, `required_columns:`, `skip_unknown:`, `cleanse_header:`, `embedded_within:` and `buffer_size:`. Previously a writer ignored `allowed_columns:`, `required_columns:` and `skip_unknown:`, so a copy, which uses its options to write the target, copied every column for `copy_from(source, mode: :hash, allowed_columns: ["name"])`. Supply `columns:` to choose the columns that are written.
- **`#each`, `#reader`, `#writer`, `#copy_from` and `#copy_to` raise `ArgumentError` for `file_name:`, `original_file_name:` and `default_format:`**, which set the format of one call by another name, now that the format is set on the path, see `format:` above. `original_file_name:` was never documented: in the `:array` and `:hash` modes it set the format of a stream that had none, such as `IOStreams.stream(io).each(:hash, original_file_name: "a.json")`; set it with `#format` or `#file_name` on the stream instead, such as `IOStreams.stream(io).format(:json).each(:hash)`.
- **A `BigDecimal`, `Time` or `DateTime` without a field in the schema is written as its usual text**, in CSV, PSV and JSON, as a field of type `any` writes it: a `BigDecimal` as a plain decimal, such as `12.5`, where it was `0.125e2` outside of Rails, and a `Time` in ISO 8601, such as `2026-10-13T09:30:00Z`, where it was `2026-10-13 09:30:00 UTC`, and in JSON in a Rails application `2026-10-13T09:30:00.000Z`. JSON writes them as text, within an object or an array too, so that a `BigDecimal` keeps all of its digits. A `Date` is written in ISO 8601, even when an application changes what `Date#to_s` returns. This also applies to the values copied from a source with a schema into a target without one. The header row that `writer(:array)` takes from the first row written is written the same way, and PSV writes an `Array` value in one column, as JSON, see below, where its items were written as more columns.
- **A `Hash` or an `Array` without a field in the schema is written as JSON** in CSV, PSV, fixed width files and spreadsheets, such as `{"a":1}` or `[1,2]`, the same as the JSON format writes it, with a `BigDecimal`, `Date` or `Time` within it as its text. Previously its `to_s` was written, Ruby's inspect text, such as `{"a"=>1}`, which other programs cannot read as JSON, and which Ruby 3.4 writes as `{"a" => 1}`. A `Float` within it that JSON cannot hold, such as `NaN`, is handled as writing JSON handles it: it raises, or is written as `null` where ActiveSupport writes JSON, as in Rails.

### Deprecated

- **`stream(:none)`.** Use `#raw` to read or write the data as it is stored, see Added, or `#file_name` to read a file that is not named for its format, such as `file_name("data.csv")` for a CSV file named `data.txt`. `stream(:none)` still works as before: it applies no streams, but text is still read and written in its default encoding, such as UTF-8, where `#raw` reads and writes bytes.
- **Setting the encode stream with `option(:encode, ...)` or `stream(:encode, ...)`.** Use `#encoding` instead, see Added. Both still work, and set the same options as `#encoding`, so no change is needed. `stream(:encode, ...)` still stops the streams being taken from the file name, like any other stream set with `#stream`. `option(:encode, ...)` no longer raises `ArgumentError` after `#stream`, or for a stream without a file name.
- **`columns:`, `allowed_columns:`, `required_columns:` and `skip_unknown:`.** A schema describes the columns of the file on its path instead, see Added: its fields are the columns, in order, and with `header: false` the columns of a file without a header row, `fieldsMatch` says which other columns the file can have, and `constraints: {required: true}` which fields it must have. They still work without a schema. With one, they raise `ArgumentError` unless they are nil, and `skip_unknown:` is accepted, since it only applies to `allowed_columns:`, so that code can supply the same options with and without a schema. `IOStreams.enforce_column_restrictions` only applies to them.
- **`cleanse_header:`.** A schema names the keys of the records read instead, and matches the columns of the header row to them, whatever their case, spaces and punctuation, see Added, so that the keys no longer depend on how the cleansing rule changes a column, such as `Amount ($)` and `Amount (€)`, which are both `amount_`. It still works without a schema, and raises `ArgumentError` with one.
- **`IOStreams.enforce_column_restrictions=`.** It only applies to the column options of each call, which are deprecated above, and true is the default, so remove it. A schema applies to every input. Setting it still works: `false` still applies the column options only to a header row that is cleansed, as before v3.0.
- **`embedded_within:` when reading rows and records.** The format of the file splits the lines of its rows and records, since its parser must agree with where they are split, so set the format with `#format` instead. It still works, and is still the way to choose the lines that `each(:line)` returns.

### Added

- **S3 objects are written without a temp file.** Writing to an S3 path uploads the data as it is written, instead of writing it into a temp file that was uploaded once the block completed, so the file no longer has to fit on the local disk, and the upload overlaps with writing it. Upto 8MB is still stored with a single `put_object` request once the block completes. More is uploaded in parts of 8MB, four at a time in other threads, while the block writes the next part, so writing holds about 40MB in memory. The size of a part doubles after every 1,000 parts, so an object can still be as large as S3 allows, 5TB, within its limit of 10,000 parts. S3 only stores the object once the block completes, as before. When the block raises, including `Interrupt` or the exception that `Timeout` raises, or the upload of a part fails, the upload is aborted, so that S3 discards the parts already uploaded, and the exception is raised unchanged. A failed upload raises the error of the request that failed, such as `Aws::S3::Errors::AccessDenied`, rather than `Aws::S3::MultipartUploadError`. An object larger than 8MB has the ETag of a multipart upload, such as `"...-3"`, rather than the MD5 digest of its data, which it had upto 100MB. With an option that describes the whole object, `content_md5`, `content_length`, `write_offset_bytes`, or the checksum of its data, such as `checksum_crc32`, the data is still written into a temp file first.
- **S3 objects are read without a temp file.** Reading an S3 path requests the object 8MB at a time, as the application reads it, so the application starts on the data straight away, and the object no longer has to fit on the local disk. The first range is requested before the block is called, so a missing object, or a bucket that cannot be reached, raises before the block runs, and before `#copy_from` changes its target. Previously the whole object was downloaded into a temp file before the block was called. Every range after the first is read from the same version of the object, by its version id in a versioned bucket, and otherwise by its ETag, so an object replaced while it is read raises `Aws::S3::Errors::PreconditionFailed`, rather than returning parts of both. A failure to read part way through the object now raises from within the block, once some of the data has been processed, as it can for any other stream. With the `range` or `part_number` option, which choose the bytes to read, the object is still downloaded into a temp file first. S3 returns no checksum for a range of an object, so the AWS SDK no longer checks one when reading, apart from the transfer's own TLS integrity checks.
- **HTTP(S) files are read without a temp file.** Reading an `http://` or `https://` path reads the response one chunk at a time, as the application reads it, so the application starts on the data straight away, and the file no longer has to fit on the local disk. Previously the whole file was downloaded into a temp file before the block was called. The connection now stays open while the block runs, and is closed once it returns, including when the block stops reading part way through, or raises, so a block that is slow to read can reach the idle timeout of the server. The request is still made before the block is called, so a missing file, or a server that cannot be reached, raises before the block runs, and before `#copy_from` changes its target. A failure to read part way through the file, or a body that exceeds `maximum_file_size`, now raises from within the block, once some of the data has been processed, as it can for any other stream. A connection that closes before the whole body has been received raises `IOStreams::Errors::CommunicationsFailure`, tagged as `IOStreams::Errors::Unavailable`, rather than `EOFError`, which a reader takes for the end of the data, and a body shorter than its `Content-Length` now raises it too, where it was accepted. Once the response has arrived, a failure no longer sends the request again, which Net::HTTP before v0.5, as in Ruby 3.2 and 3.3, does for a GET. A failure raised by the block itself is still not tagged as a failure of the request. Under a Fiber scheduler, such as Async, the scheduler runs its other Fibers while the read waits for the network. A zip file or spreadsheet on HTTP is still copied into a temp file, now by the format, since it is read from a file. The IO that the block reads is no longer a `File`, see Breaking.
- **Writing Excel spreadsheets, `.xlsx` and `.xlsm`**, using the `xlsxtream` gem, for example `IOStreams.path("report.xlsx").writer(:hash) { |io| io << {"name" => "Jack"} }`. The CSV text written becomes the rows of a workbook with one worksheet, streamed with `zip_kit` to the stream below it, such as `.pgp` in `report.xlsx.pgp`, without a temp file of its own. Every cell is text by default, so reading the spreadsheet returns the same CSV. The writer accepts `sheet_name`, which defaults to `"Sheet1"`, `auto_format: true`, which writes values that look like numbers, dates, times or booleans as Excel numbers, dates and booleans, and `use_shared_strings: true`, which stores each distinct value once. Reading ignores `auto_format` and `use_shared_strings`, and raises `ArgumentError` for `sheet_name`, since it always reads the first worksheet. A `sheet_name` that Excel rejects, empty, longer than 31 characters, containing any of `[ ] : * ? / \`, or starting or ending with an apostrophe, raises `ArgumentError` before the file is opened. The CSV can end its records with `"\r\n"`, `"\n"` or `"\r"`, such as `writer(:line, delimiter: "\r")`.
- **Zstandard compression for `.zst` files**, using the `zstd-ruby` gem, for example `IOStreams.path("data.csv.zst").each(:hash)`. Writing accepts a compression `level`, such as `option(:zst, level: 19)`, and reading returns the contents of every frame in the file, like `zstd -d`. On JRuby, which cannot load the `zstd-ruby` C extension, it uses the [zstd-jni](https://github.com/luben/zstd-jni) jar instead, which the application adds to the classpath, for example with `require_jar "com.github.luben", "zstd-jni", "1.5.7-3"`. On MRI it is built on `Zstd::StreamingCompress` and `Zstd::StreamingDecompress`, since the [zstd-ruby README marks its `Zstd::StreamWriter` and `Zstd::StreamReader` classes as experimental](https://github.com/SpringMT/zstd-ruby#stream-writer-and-reader-wrapper), and reading needs `zstd-ruby` 2.0.0 or later, which holds one zstd block in memory at a time. A `level` must be an Integer from -131072 to 22. Reading checks the checksum of every frame that has one, such as a file written by the `zstd` command, and raises `RuntimeError`, tagged as `IOStreams::Errors::Corrupt`, when the data does not match it. On JRuby each frame written ends with the checksum of its content, as the `zstd` command writes it, while on MRI it does not, since `zstd-ruby` has no option to write it. Reading empty data raises `RuntimeError`, tagged as `IOStreams::Errors::Corrupt`, like `zstd -d`, since it is not zstd. Data that ends within a frame, such as a file that was cut short, raises `RuntimeError: zstd decompress error: Truncated source`, tagged the same way, as `zstd -d` does. IOStreams follows the frames of the data to find it, since `zstd-ruby` does not report it, and zstd-jni does not report a frame cut off before its checksum.
- **Read and write Apache Parquet files**, with the `parquet` gem, for example `IOStreams.path("s3://bucket/people.parquet").each(:hash)`. Parquet is a tabular format, like CSV or JSON, selected by a `.parquet` file name or `format(:parquet)`, whose records are read with typed values, such as an `Integer`, `BigDecimal`, `Date` or `Time`, even without a schema. Its rows, read with `each(:array)`, are the values of its columns after a header row of their names, or with a schema the values of its fields, in order. Writing needs a schema, whose fields are the columns, and whose types give their Parquet types: `string`, `int64`, `decimal(38, decimals)` or `double` for a `number` with `floatNumber: true`, `boolean`, `date32` and `timestamp_micros` in UTC. A `number` field needs `decimals` or `floatNumber`, and a field of type `any` raises `ArgumentError`, as do a missing schema and an unknown compression, before the file is opened, so that an existing file is kept. A Parquet file is read from, and written to, a temp file when it is not a local file, since it records its columns at its end. Set how its columns are compressed with `option(:parquet, compression: "zstd")`; the default is `"snappy"`, and reading ignores it. With a schema whose `fieldsMatch` is `"subset"` or `"partial"`, only the columns of its fields are read. The `:line` mode, the `delimiter:` and `embedded_within:` options, and `#encoding`, raise `ArgumentError`, since it has no lines of text. A value that its column cannot hold, such as an integer outside the range of an `int64`, raises `IOStreams::Errors::InvalidValue`, naming its field, when the record is written. A `number` is rounded to its `decimals` as CSV writes its text, a `BigDecimal` half up and a `Float`, with `floatNumber: true`, as Ruby's `format` rounds it, so that both files hold the same number, and a `double` holds `NaN` and `INF` as they are, while a `decimal` raises `IOStreams::Errors::InvalidValue` for them. Not available on JRuby, since the gem is a Rust extension.
- **Read a file in slices of its rows, to parse elsewhere**, with `each(:slice, size: 100)` or `reader(:slice, size: 100)`, for example to hand each slice to another thread, process or job. Each slice, an `IOStreams::Slice`, is an Array of up to `size` rows as they are in the file, such as the lines of a CSV file, and describes them: `#header` is the header row of its file as it was read, a frozen Array that every slice of the file shares, and `#format` is the tabular format of its rows, such as `:csv`. Before the first slice is yielded, the header row is matched to the fields of the schema, or for a format of records that supply their own keys, such as JSON or Parquet, the keys of its first record, so a file that does not match raises `IOStreams::Errors::InvalidHeader` before any rows are handed on. `validate: true` also parses each row before its slice is yielded, and raises for a value that is not valid, once the slices before it have been yielded, while each slice still holds the rows as they are. A file without a header row, such as fixed width, JSON, or a schema with `header: false`, gives its slices no header row. The column options, such as `columns:`, raise `ArgumentError` unless they are nil, as they do with a schema, since the header row that they would change is read again where a slice is parsed: describe the columns with a schema. A `size` or `validate` that is not valid raises `ArgumentError` before the file is opened.
- **Store a slice with `IOStreams::Slice#to_h`, and read it back with `IOStreams.slice`.** `#to_h` returns what a slice holds as a Hash of Strings and Arrays, which JSON and BSON keep as they are, such as `{"rows" => ["Jack,21"], "header" => ["Name", "AGE"], "format" => "csv"}`, so that a job can store it, or send it to another process, without knowing what a slice holds. `IOStreams.slice(hash)` turns it back into the slice, with its header row frozen, accepting String or Symbol keys and format, and raises `ArgumentError` for a Hash that does not describe a slice: without rows, with a key that a slice does not have, a header row that is not an Array of Strings, or a format that `IOStreams.tabular_formats` does not include.
- **Read the rows of a slice with `IOStreams.stream(slice)`**, as the rows of its file are read, for example `IOStreams.stream(slice).schema("people.json").each(:hash) { |person| p person }`, so that whoever parses a slice, such as another thread or job, uses the same settings as for a file. Its rows start with the header row that the slice carries, which is matched to the schema, and are read in the format of the slice, in the `:array`, `:hash` and `:slice` modes. Setting another format, the `:stream` and `:line` modes, `#read`, `#stream`, `#option`, `#encoding`, `#raw`, the options of lines such as `delimiter:`, and writing raise `ArgumentError`, since a slice holds rows already split and decoded rather than bytes, and is only read.
- **Read and copy the rows of an Active Record query** with `IOStreams.stream(relation)`, or `copy_from(relation, mode: :hash)`, for example `IOStreams.path(ENV["EXPORT_PATH"]).copy_from(Order.where(paid: true).order(:created_at), mode: :hash)`, so that the path in configuration decides the format, compression, encryption and storage of an export. A relation is read as one query, which the driver of its database streams, so that a sorted or grouped query runs once, rather than once for each batch, and `relation.in_batches(...)` is read in those batches, with its own settings, such as `of:` and `cursor:`, the rows of each batch in the order of the primary key, since Rails gives a batch no order. Each row is cast as `pluck` casts it, so an enum attribute is the name of its value and an encrypted attribute its plain text, and every row is a record, so a row whose every value is null or empty is read and copied, unlike a blank line of a file, and `#schema` returns a schema of the types of the columns, which the rows are read by, and which a copy gives a target without a schema, so that a Parquet file keeps the types of the columns, and CSV writes the decimals of each number. The query borrows a connection from the pool and hands it back when it ends, skips the query cache, and runs in the fiber of the caller. SQLite is read with a statement of the `sqlite3` gem; a database that cannot stream a query raises `ArgumentError`, suggesting `in_batches`. Active Record 7.2 or later is needed. A failure of the database is tagged as `IOStreams::Errors::Unavailable` or `PermissionDenied`, see Rescue a missing file, below. The `Enumerator` that `find_each` returns raises `ArgumentError`, as any `Enumerator` supplied to `IOStreams.stream` now does, since it is not an IO. A query is only read, so writing, the `:stream` and `:line` modes, `#stream`, `#option`, `#encoding` and `#raw` raise `ArgumentError`, as for a slice.
- **`skip_blanks: true` skips blank rows when reading**, with `each(:array)` and `each(:hash)`, and their `#reader`, including the rows of a slice read with `IOStreams.stream(slice)`, rather than yield `nil` for each one, for example `IOStreams.path("export.csv").each(:hash, skip_blanks: true) { |record| p record }`. A blank row is the same in every format, see Breaking. It defaults to false, so that the rows yielded still count the lines of the file. The `:slice` mode does not take it, since, like `each(:line)`, it hands on every row as it is in the file. A `skip_blanks` that is not true or false raises `ArgumentError` before the file is opened, and `#writer`, `#copy_from` and `#copy_to` raise `ArgumentError` for it, since a copy always skips blank rows. 
- **`IOStreams.tabular_formats` returns the names of the formats that `#format` accepts**, such as `:csv`, `:json` and `:fixed`, so that an application can check a format held in configuration, or offer a choice of formats, without using the internal `IOStreams::Tabular.registered_formats`.
- **`#raw` reads and writes the data as it is stored**, applying no streams and no encoding, for example to checksum a compressed file as it is stored, `Digest::SHA256.hexdigest(IOStreams.path("data.csv.gz").raw.read)`, or to write data that is already compressed, `IOStreams.path("data.csv.gz").raw.write(gzipped)`. Text is read and written as bytes. Setting a stream, option or encoding after it raises `ArgumentError`, since the data is as stored.
- **`#encoding` sets the encoding of the text that the application reads or writes**, and the other options of the `:encode` stream, for example `IOStreams.path("legacy.csv").encoding("Windows-1252:UTF-8")` or `encoding("UTF-8", replace: "?")`. Unlike `stream(:encode, ...)`, it keeps the streams taken from the file name, so `IOStreams.path("data.csv.gz").encoding("BINARY")` is still decompressed. Each call merges its options with those already set, and `stream(:none)` removes them. Without any arguments, `#encoding` returns the encoding that was set, or nil, like `IO#encoding`, and `#raw?` returns whether `#raw` was called.
- **Rescue a missing file, a file that cannot be accessed, or a server that cannot be reached, the same way wherever the file is stored.** Every path tags the exception that its storage raises for a file, directory or S3 bucket that does not exist with `IOStreams::Errors::NotFound`, for access that the storage does not permit, or credentials that are missing or not valid, with `IOStreams::Errors::PermissionDenied`, and for a server that cannot be reached, or cannot handle the request at the time, with `IOStreams::Errors::Unavailable`, which can be retried. A host name that does not resolve, such as a mistyped host, is not `Unavailable`, since retrying will not fix it, unless name resolution failed temporarily, such as during a DNS outage, on Ruby 3.3 or later. So `rescue IOStreams::Errors::NotFound` handles a missing file whether the path is a local file, S3, SFTP or HTTP, and a path held in configuration can change without changing the code. `IOStreams::Errors::AccessDenied`, which IOStreams raises for a path outside the allowed paths, is not a `PermissionDenied`. Previously a missing file raised `Errno::ENOENT` locally, `Aws::S3::Errors::NoSuchKey` on S3, and `IOStreams::Errors::CommunicationsFailure` on SFTP and HTTP, which those also raise for unrelated failures. The tag does not replace the exception, which keeps its class, so code that rescues it by its class still works. Its `#display_name` is the path that failed, without any credentials, and its message starts with it unless it already includes it, so that a log names the file, which for example the message from S3 did not. Only the failure of a path's own request of its storage is tagged, not an exception raised by the block supplied to it, so reading an HTTP path now downloads the file and closes the connection before calling the block. Every kind of failure includes `IOStreams::Errors::StorageError`. See [Errors](https://iostreams.reidmorrison.com/errors).
- **Rescue a file whose data cannot be read the same way whatever its format.** Every stream tags the exception that the gem reading its format raises for data that is damaged, cut short, or not in that format at all, such as a text file named `.gz`, with `IOStreams::Errors::Corrupt`, and the zip stream raises `IOStreams::Errors::StreamFailure` tagged with `IOStreams::Errors::MissingEntry` for a zip file that does not contain the file to read. So `rescue IOStreams::Errors::Corrupt` handles a corrupt file whether its name ends in `.gz`, `.bz2`, `.zst`, `.zip`, `.enc`, `.pgp`, `.xlsx` or `.parquet`, without naming the exception of each gem, such as `Zlib::GzipFile::Error`, `Bzip2::FFI::Error::DataError`, `OpenSSL::Cipher::CipherError`, `Zip::Error` or `IOStreams::Pgp::Failure`, and keeps working when IOStreams replaces a gem with another, or reads a format with another library on another platform, as JRuby reads zip files with Java. The tag does not replace the exception, which keeps its class, so code that rescues it by its class still works. Every kind of failure of a stream includes `IOStreams::Errors::StreamError`, and is not a `StorageError`. PGP tells why gpg failed from gpg's status, which does not depend on the locale: data that is not PGP data, is cut short, or was changed is `Corrupt`, and a secret key that is not in the keyring, a passphrase that is missing or wrong, or the public key of a signature that is not in the keyring is `IOStreams::Errors::MissingKey`, as is a version of the cipher of `.enc` data that is not configured. A PGP file that was not signed by the `signer` is not tagged, since only PGP checks who signed a file. The parquet gem raises a plain `RuntimeError` for every failure, so only a `RuntimeError` that it raised while the block was not running, and that is not an operating system error, is tagged. The failure of PGP data read from a path, or a stream with a file name, also starts with the name of the file, the display name of the path, such as `s3://bucket/data.csv.pgp`, or the file name of the stream, where it named only `stream` for data that gpg read through its stdin. A reader registered with `IOStreams.register_extension` can tag the failures of its gem the same way. See [Errors](https://iostreams.reidmorrison.com/errors).
- **`signer` when reading PGP** requires that the file was signed by that key: reading raises `IOStreams::Pgp::Failure` unless the file has a good signature by a key with that email address, key id or fingerprint, which gpg fully or ultimately trusts. Previously the reader accepted a file that was not signed, or that was signed by any key in the keyring, and `signer:` raised `ArgumentError` when reading. Like the other checks, it is made once the whole file has been read, including when the block leaves early, such as with `break`, so supply `verify_first: true` to check it before the contents are processed.
- **`import_and_trust_key` when reading PGP** imports and trusts the sender's public key, and requires that the file was signed by it, or by the `signer` when both are supplied, so that the sender's key does not have to be managed on every server. Since the key itself is supplied, a signature by it is accepted whatever trust gpg places in it. When reading, the trust of the key is only changed when `import_and_trust_level` is supplied, so a key that is already trusted keeps its trust. Previously both raised `ArgumentError` when reading.
- **`#file?`, `#directory?`, `#empty?` and `#size?` for every path**, like the `File` methods with the same names. `#empty?` is true for a file without any data, or a directory without any children. `#size?` returns the size of the file, or nil when it does not exist or is empty. A path is `#blank?` only when its name is empty, so with ActiveSupport loaded, `blank?`, `present?`, `presence` and ActiveModel's `validates_presence_of` and `allow_blank:` behave as before, instead of checking `#empty?`, which can make a request to the file store and raise when it cannot be reached. S3 has no directories, so an S3 path is a directory when any key is within it, or when a folder object exists for it; HTTP has no directories, so every url that exists is a file. SFTP paths also support `#exist?` and `#size`, which raised `NotImplementedError`.
- **`#display_name` for every path** returns its full name without any credentials, for logging, such as `"sftp://example.org/a.csv"` for `sftp://jack:secret@example.org/a.csv`. It removes the user name and password of an SFTP url, and the user name, password, query and fragment of an HTTP url, which can hold credentials, such as the signature of a pre-signed url. `#to_s` still includes them, so that the path can be created again from it. `#inspect` already displayed this name.
- **`IOStreams.redact_path_options` and `IOStreams.redact_stream_options`** return the options of a path or its streams with each secret replaced with `"[FILTERED]"`, for an application that stores a url and its options, or its streams, to create the path later, and displays them. For example `IOStreams.redact_path_options("sftp://example.org/a.csv", password: "secret")` returns `{password: "[FILTERED]"}`. Each path class declares its secrets with `sensitive_option_names`: the SFTP `password` and `IdentityKey` ssh option, the S3 `secret_access_key` and customer encryption keys, and the HTTP `password`, `parameters` and cookie headers. Every value is replaced when the url is not valid, or when its scheme is registered with a class that does not declare its secrets. As a precaution any option whose name contains `passphrase`, `password`, `secret`, `token`, `credential`, `auth`, `apikey` or `privatekey` is also replaced, such as the headers `Authorization` and `X-Api-Key`, and names match in any case, with or without `_` and `-`. The options within a Hash option, such as `ssh_options:`, `client:` or `headers:`, are replaced the same way, as are those within an Array of Hashes or of `[name, value]` pairs. The options of a stream that are not a Hash are replaced whole, since they cannot say which of their values are sensitive. `IOStreams.redact_stream_options` also accepts the options of the rows of a Parquet file, `parquet:`, which `#option` sets, and redacts them as Parquet decides, as `#inspect` does, so `IOStreams.redact_stream_options(parquet: {compression: "zstd"})` returns them unchanged. `#inspect` on a path or stream hides options with these names too.
- **`#format` accepts the name of a format as a String**, such as `format("json")` for a format held in configuration, and `#setting` the name of a stream, such as `setting("gz")`. Previously `format("json")` raised `ArgumentError`, and `setting("gz")` returned nil for a stream set with `#stream`.
- **The reader that `reader(:line)` and `reader(:array)` yield is `Enumerable`**, as the one that `reader(:hash)` yields already was, so that the block can call `#map`, `#first` or `#each_slice` on it, such as `path.reader(:array) { |rows| rows.first(10) }`. Previously they raised `NoMethodError`.
- **`#allowed?` for every path** returns whether it can be accessed, which is whether it is within the allowed paths, like `IOStreams.allowed_path?`, for example `IOStreams.path("/etc/passwd").allowed?`.
- **Write to HTTP(S) paths.** Writing to an `http://` or `https://` path uploads the file with an HTTP PUT, for example `IOStreams.path("https://example.com/upload/report.csv").write(data)`. The file is written to a tempfile first and uploaded once the block completes, with its `Content-Length`. Only a `307` or `308` redirect to the same scheme, host and port is followed when writing, so that a redirect cannot send the data being uploaded to another server. Previously writing to an HTTP path raised `NoMethodError`.
- **`headers:` for HTTP(S) paths** adds headers to every request, when reading and when writing, for example a bearer token or the `Content-Type` of an upload. Since any header may hold a credential, the headers are not resent across a redirect to another scheme, host or port, apart from an `Accept-Encoding`, which holds none, so that a response is read the same way after a redirect.
- **`#exist?`, `#size` and `#delete` for HTTP(S) paths.** `#exist?` and `#size` use an HTTP HEAD, and `#delete` uses an HTTP DELETE. A `404 Not Found` or `410 Gone` response means the file does not exist. `#delete` follows the same redirects as writing. `#move_to` from an HTTP path now deletes it once it is copied; previously it copied the file and then raised `NotImplementedError`. `#mkpath` does nothing, like S3, so `#move_to` an HTTP path also works.
- **`#delete` for SFTP paths** deletes a file, or an empty directory, and does nothing when it does not exist, like local and S3 paths. It uses `net-sftp`, like `#each_child`. `#move_to` from an SFTP path now deletes it once it is copied; previously it copied the file and then raised `NotImplementedError`, leaving both copies.
- **Each HTTP(S) redirect that is followed is logged** at info level via `IOStreams.logger`, without any user name, password or query string, which can hold the signature of a pre-signed url.
- **`#compressed?` and `#encrypted?` for streams**, such as `IOStreams.stream(io).stream(:gz).compressed?`, like paths.
- **Register a format with `IOStreams.register_extension(:xz, MyXz)`**, a module that answers `reader_class`, `writer_class`, `compressed?` and `encrypted?`, and extends `IOStreams::StreamFormat`, which checks the options of its reader and writer and opens them, so that a custom format can declare that its data is compressed or encrypted. The built-in formats are registered this way, so their readers and writers are now loaded when first used, rather than when `iostreams` is required. Registering the reader and writer classes still works, for a format that is neither compressed nor encrypted. `IOStreams.extension(:gz)` returns the format registered for one extension, in any case, such as `IOStreams::Gzip`, or nil, without copying every extension as `IOStreams.extensions` does.
- **A writer of a registered format can define `.check`**, which is supplied the same options as `.stream`, and raises for those that it cannot write with, such as a compression level that is out of range. It is called before a path opens its output, so that an existing file is kept, rather than replaced by a file that the writer then cannot write.

- **Invalid UTF-8 names where it is.** Data that is not valid in the encoding that it is read or written in raises `IOStreams::Errors::InvalidEncoding`, an `Encoding::UndefinedConversionError`, so code that rescues that still works, and its `#error_char`, `#source_encoding` and `#destination_encoding` answer what that error answered. Its message gives the byte offset of the first invalid byte, within the data after any decompression or decryption, and, when reading a line at a time, such as with `each(:line)` or `each(:hash)`, the line that it is on, for example `"\xE9" is not valid UTF-8 at byte offset 1043 on line 12`; `#byte_offset` and `#line_number` return them. The lines before the invalid data are read first, where previously the error was raised for the whole block of up to 64KB that held it, before any of its lines were read. Previously the message only gave the invalid bytes.
- **Convert text from one encoding to another while reading**, with Ruby's `"external:internal"` form of the `:encode` stream's `encoding`, like `File.read(name, encoding: "Windows-1252:UTF-8")`. For example `IOStreams.path("legacy.csv").encoding("Windows-1252:UTF-8").each(:hash)` returns UTF-8 strings, where previously it could only return Windows-1252 strings. Writing with the same option writes the external encoding.
- **`#delete_all` for S3 and SFTP paths**, like local paths. On S3 it deletes the object, and every key within the path as a directory, in batches of up to 1,000 keys; a key that only starts with the same characters, such as `a.csv` for `s3://bucket/a`, is not deleted. On SFTP it deletes the directory and everything within it, without following symbolic links. Previously both raised `NotImplementedError`.
- **`#respond_to?` is false for an operation that a path does not support**, such as `#each_child` and `#delete_all` on an HTTP path, like Ruby's own methods that are not implemented on the platform, such as `Process.fork` on Windows. It is also false for an operation built on one that the path does not support, such as `#children`, which uses `#each_child`, `#size?`, which uses `#size`, and `#move_to`, which uses `#delete`. Calling it still raises `NotImplementedError`, whose message now names the path class, the operation and the path.
- **`#mtime` for every path**, like `File.mtime`: the time a local file was modified, the `last_modified` time of an S3 object, the `mtime` of an SFTP file, or the `Last-Modified` header of an HTTP(S) url, which is nil when the server does not supply it, or supplies a value that is not a time, which is logged as a warning via `IOStreams.logger`. It raises `IOStreams::Errors::NotFound` when the file does not exist.
- **`#relative_path_from`**, like `Pathname#relative_path_from`, returns the name of a path relative to another path in the same store as a String, for example to copy every file within a directory to another store. It raises `ArgumentError` for a path in another store, such as another S3 bucket or SFTP host.
- **Each temp file that IOStreams uses is logged** at debug level via `IOStreams.logger`, when it is created, with what it holds, such as `Created temp file /tmp/iostreams_s320261008-41-1x5yq2 for the download of s3://bucket/data.csv`, and when it is deleted, with its size, so that it can be seen when, and why, a file was copied to local disk. See [When temp files are used](https://iostreams.reidmorrison.com/config#when-temp-files-are-used).
- **`#/`, `#cleanpath` and `#sub_ext`**, like `Pathname`. `#/` joins like `#join`, so an absolute element is joined to the path rather than replacing it. `#cleanpath` removes `.`, `..` and repeated `/` without accessing the file, and keeps the streams and options. An SFTP name within the login directory is cleaned within it, keeping a `..` that leaves it, such as `sftp://host/~/../x.csv`, since only the server knows what is above the login directory, and an S3 key or HTTP(S) url keeps a trailing `/`, since it names another object or url. `#sub_ext` replaces the last extension, and clears the streams and options, since they were for the old file name.
- **`#schema` gives the type of each field of rows and records**, a [Frictionless Table Schema](https://datapackage.org/standard/table-schema/), as a Hash, or as the path or url of a JSON file in any store, which is read the first time that a reader or writer needs it. Reading rows and records with a schema returns each value as its type, `string`, `integer`, `number`, which is a `BigDecimal`, or a `Float` with `floatNumber: true`, `boolean`, `date`, `datetime`, `object` or `array`, a `Hash` or an `Array` held as JSON text, such as `{"a":1}`, or `any`, and writing them writes each value in the text form of its type, for every format. JSON writes an `object` or an `array` as itself, and Parquet writes its JSON text in a `string` column. JSON writes numbers and booleans as themselves, with all of the digits of a `number`, such as `12345678901234567.89`, and the digits after the decimal point that its `decimals` give, such as `12.50`, the same as CSV, rather than through a `Float`, including when ActiveSupport replaces how Ruby writes JSON, and reads them back with all of their digits, while the numbers of the other fields are still a `Float`. A `number` field accepts a `Rational`, which keeps every digit of a decimal that ends, whatever the version of bigdecimal, and rounds one that does not, such as `1/3r`, and a fixed width file writes a number that is not finite, such as `NaN`, with spaces rather than zeros, so that it can be read back. A value that is not of the type of its field raises `IOStreams::Errors::InvalidValue`. A schema also gives the position of each field of a fixed width file, with the `width`, `start` and `truncate` of each field and the `width` of each line, which IOStreams adds to Frictionless, as it does `decimals`. The parts of Frictionless that IOStreams does not support yet, such as `primaryKey`, raise `ArgumentError`, rather than being ignored. An `integer` field also reads the text of a whole number with a decimal point, such as `12.0`, as a spreadsheet stores every number as a double, while a fraction, such as `12.5`, raises. A `datetime` without an offset from UTC, such as `2026-10-13T09:30:00`, or text in a `format` without a zone, is read as UTC, rather than in the time zone of the process, so that a file reads the same on every server, while a zone in the text is read at its offset, and a zone whose offset Ruby does not know raises `IOStreams::Errors::InvalidValue`. A `Time` written with a `format` without a zone is written in UTC, so that it reads back as the same time. A schema file that starts with a UTF-8 byte order mark is read. A `number` field needs the `bigdecimal` gem, which is a bundled gem from Ruby 3.4. The schema is held as it was set, as a frozen copy, so `#schema` returns it unchanged when the caller changes the Hash, String or path that it supplied, and changing the schema that `#schema` returns raises `FrozenError`. See [Schema](https://iostreams.reidmorrison.com/formats#schema).
- **A schema with `header: false` describes a file without a header row**, whose columns are the fields of the schema, in order: reading takes every line as a row, and writing writes no header row. Since it is set on the path, every reader of the path reads the file that way, including `#copy_from` and `#copy_to`. Previously a file without a header row could only be described with `columns:` for each call, which a copy supplies to its target, so a copy read the first row of such a source as its header. `copy_from(source, mode: :array)` from such a file gives the target the names of the fields as the columns of its rows, so that a target with a header row, such as CSV, writes them as its header row, and one without, such as JSON, takes the keys of its records from them. A format without a header row, such as JSON or fixed width, ignores `header: false`. For a format with a header row, such as CSV, the columns of the file are then the fields in order, so a schema with `header: false` needs `fieldsMatch` `"exact"`, and raises `ArgumentError` when a reader or writer of the file is created, before a writer opens its output.
- **A schema matches the columns of a file to its fields, and the keys of the records read are the names of its fields.** Each column of the header row, or key of a JSON record, is matched once to the field whose name it is, or whose `aliases` include it, otherwise to the field whose name or alias is the same once both are compared without their case, spaces and punctuation, with the forms of a character that Unicode treats as the same made the same, so that the field `first_name` matches the column `First Name`, and `email` matches `E-mail`, otherwise to the field whose name or alias is the same once both are cleansed as `cleanse_header` cleansed a header row, so that the field `area_m`, named as the cleansing named the column `Area (m²)`, matches it. A column that is several fields once compared loosely, or none, is the field named as the column once cleansed, if there is one, so that the fields `e_mail` and `email` find the columns `E-mail` and `Email`. `aliases` is a property that IOStreams adds to a field, for columns named another way, such as `["DOB", "Birth Date"]`. A column that could be two fields, or two columns that are one field, raise `IOStreams::Errors::InvalidHeader`, rather than guess or lose a value. The keys of the records are the names as they are given, whether or not the file has a header row, and for a format with a header row, such as CSV, `each(:array)` returns a header row of the names of the fields of its columns, then the values of those fields of each row, in the order of the fields. Writing writes the names of the fields as the header row, in order, rather than the keys of the first record, and matches the keys of each record to the fields the same way, so that a file can have readable column names, such as `First Name`, while the code writes records whose keys are `first_name`. `writer(:array)` writes the header row itself, before the rows, as `writer(:hash)` does, and takes each row written as the values of the fields, in order, as for a file without a header row, while a header row written to it, such as the `IOStreams::Row::HeaderRow` that `each(:array)` yields, gives the columns of the rows after it, which it matches to the fields, without a line of its own, so that the rows that `each(:array)` returns, and that `copy_from(source, mode: :array)` copies, are written in the columns of their fields. A header row without any column that is a field raises `IOStreams::Errors::InvalidHeader`, whatever `fieldsMatch` is, rather than write the rows after it without values. See [Matching columns to fields](https://iostreams.reidmorrison.com/formats#matching-columns-to-fields).
- **`keyType` forms the keys of the records read from the names of the fields of a schema**, a property that IOStreams adds: `string`, `cleansed`, which cleanses each name as `cleanse_header` cleanses a header row, such as `first_name` for `First Name`, `symbol`, or `cleansedSymbol`, such as `:first_name`. Without it the keys are the names as they are given. The header row written is still the names of the fields, and a record written can be keyed by the keys of the records read. A schema held as JSON, or in a database such as MongoDB, has String names, so the schema that v2.2's `IOStreams::Schema.from_layout` returns for a layout whose keys are all Symbols has `keyType: "symbol"`, which keeps the Symbol keys of its records. See [Keys of the records read](https://iostreams.reidmorrison.com/formats#keys-of-the-records-read).
- **`extraColumns: "keep"` keeps the columns that a schema does not list**, a property that IOStreams adds, which `fieldsMatch` `subset` and `partial` otherwise skip: reading keeps them after the fields, by the key that `keyType` forms from each column, with their values as they are, and so it does the keys of each JSON or Parquet record, for which a Parquet file reads every column. With `subset`, a schema can then have no fields, to read every column. So `required_columns:` alone, which read every column, is a schema with `subset`, `extraColumns: "keep"` and `keyType: "cleansed"`, and `cleanse_header: false` alone one with `subset`, `extraColumns: "keep"` and no fields. Writing writes only the fields. Any other `fieldsMatch` raises `ArgumentError` for it, and so does `each(:array)` for JSON and Parquet. See [Keeping the other columns](https://iostreams.reidmorrison.com/formats#keeping-the-other-columns).
- **A field with `skip: true` only holds the place of its column**, a property that IOStreams adds: reading leaves it out of the rows and records, and writing writes an empty value in its column, or leaves it out of a JSON record, and a Parquet file has no column for it, so that a file without a header row, whose columns are the fields in order, can have a column that the code does not read, as a `nil` in `columns:` did. It takes only the properties that place its column, `name`, `aliases`, `width` and `start`, and raises `ArgumentError` for the others. See [Field properties](https://iostreams.reidmorrison.com/formats#field-properties).
- **`fieldsMatch` says which columns a file with a schema can have, and must have**, as Frictionless defines it: `exact`, the default, the fields in order; `equal`, the fields in any order; `subset`, every field and other columns, which are skipped; `superset`, only fields, any of which can be missing; and `partial`, at least one field, and other columns, which are skipped. A file that does not match raises `IOStreams::Errors::InvalidHeader`, which lists each problem. It applies to the keys of each JSON record too, to the values of a row read after its last column, such as after a comma in a value that is not quoted, and when writing, to the keys of each record, the columns of the header row of the rows written, and the values of each row after its last column, which `subset` and `partial` skip. A value after the last column that is `nil`, or blank text, such as the empty value after a comma at the end of each line, is not data, so it is ignored, both when reading and when writing, so that the rows read from such a file can be copied into a file with any schema. Likewise, the columns without a name at the end of a header row, such as the empty column that a spreadsheet exports after the last one, are not columns, so that a file whose lines end with a comma matches `exact`, and a value under one is a value after the last column, while a column without a name between other columns is one that the schema does not list. See [fieldsMatch](https://iostreams.reidmorrison.com/formats#fieldsmatch).
- **A field with `constraints: {required: true}` must have a value**, as Frictionless defines it: a header row or JSON record without the field raises `IOStreams::Errors::InvalidHeader`, whatever `fieldsMatch` is, and a value that is `nil`, or empty text, raises `IOStreams::Errors::InvalidValue`, when reading and when writing, including a blank record or row written, such as `{}`. The other constraints of Frictionless still raise `ArgumentError`. See [Required fields](https://iostreams.reidmorrison.com/formats#required-fields).
- **`allowBlank: true` lets a required field have blank values**, as the deprecated `required_columns:` did: the header row, or each JSON record, must still have the field, but a value that is `nil`, or empty text, is read and written as it is. It is a property of the field that IOStreams adds, rather than a constraint, since Frictionless defines `required` as `true` or `false`, and a tool reports an error for a constraint that it does not support. A field that is not `required` raises `ArgumentError` for it. See [Required fields](https://iostreams.reidmorrison.com/formats#required-fields).
- **`each(:array)` yields its header row as an `IOStreams::Row::HeaderRow`**, an Array that says that it is the header row, and `writer(:array)` with a schema takes one as the header row of the rows after it, whichever row it is, so that the rows that `each(:array)` reads from one file can be written to another, whatever their formats, such as from CSV to JSON with a schema, where the header row was written as a row of values. Without a schema, the first row written is the header row, as before, and a header row after it, such as that of a second file, is still written as a row of values, since its columns cannot be matched to those of the file. Code that reads the rows can skip the header row with `next if row.is_a?(IOStreams::Row::HeaderRow)`. It is equal to an Array of the same columns. See [Records and rows without a schema](https://iostreams.reidmorrison.com/formats#records-and-rows-without-a-schema).
- **With a schema, `columns:`, `allowed_columns:`, `required_columns:` and `cleanse_header:` raise `ArgumentError`**, since the schema describes the columns of the file on its path, so that every reader and writer of the path, including a copy, checks them the same way: its fields are the columns, `fieldsMatch` replaces `allowed_columns:` and `skip_unknown:`, and `constraints` replace `required_columns:`. A nil `columns:`, `allowed_columns:` or `required_columns:` is not supplied, and `skip_unknown:` only applies to `allowed_columns:`, so they are accepted, so that code, such as Rocket Job, can supply the same options with and without a schema. `cleanse_header: nil` still raises, since nil does not cleanse the header row, as before, rather than being the default. They raise before the file is opened, so that a missing file is not reported instead. They still apply without a schema. See [The column options of each call are deprecated](https://iostreams.reidmorrison.com/upgrading#the-column-options-of-each-call-are-deprecated).
- **Using a deprecated method or option reports a Ruby deprecation warning**, which names the line of the application that used it, and what to use instead, such as `app/jobs/export_job.rb:12: warning: IOStreams: stream(:none) is deprecated, use #raw ...`: `stream(:none)`, `option(:encode, ...)` and `stream(:encode, ...)`, `columns:`, `allowed_columns:`, `required_columns:`, `skip_unknown:` and `cleanse_header:`, unless they are nil, apart from `cleanse_header: nil`, `embedded_within:` when reading rows and records, and `IOStreams.enforce_column_restrictions=`, see Deprecated. It is reported with `Kernel#warn` in the `:deprecated` category, so Ruby only shows it while `Warning[:deprecated]` is true: not by default, so production stays quiet, but in tests run with Minitest or test-unit, or with `RUBYOPT=-W:deprecated`. Extend `Warning` with a `warn` of your own to send them elsewhere, such as to a log. See [Seeing deprecation warnings](https://iostreams.reidmorrison.com/upgrading#seeing-deprecation-warnings).

### Changed

- **Reading CSV is faster.** `CSV.parse_line` creates a parser for each line, which costs several times more than parsing the line, so each line is now parsed directly. Converting a row into a record also no longer checks every column of every row for a blank or rejected column name, which made it slower than parsing the line, so reading PSV records is faster too. Reading rows, such as with `each(:array)`, is 4 to 6 times faster, and reading records, such as with `each(:hash)`, 3.5 to 5 times faster, on MRI, YJIT and JRuby. A line with a line break, or with invalid quoting, is still parsed by `CSV.parse_line`, so the values, their encodings, and the errors raised are the same as before.
- **Reading JSON or `:hash` records with `allowed_columns:`, `required_columns:` or `columns:` is about 6 times faster.** Their keys are restricted and matched to the columns once for each set of keys, rather than for every record, so reading JSON records with `allowed_columns:` takes about as long as reading them without it. The records read are unchanged.
- **Writing CSV is faster.** `CSV.generate_line` also creates a CSV object for each line, so each line is now written directly. Writing rows, such as with `writer(:array)`, is 2.5 to 4.5 times faster, and writing records, such as with `writer(:hash)`, 1.4 to 2.3 times faster, on MRI, YJIT and JRuby. A row with a value whose text is neither valid UTF-8 nor ASCII is still written by `CSV.generate_line`, so the lines written, and the errors raised, are the same as before.
- **The stream supplied to a writer block responds to the same methods of an IO whichever streams the data uses**: `#write`, with one or more arguments, `#<<`, which returns the stream so that `io << a << b` works, `#print`, `#puts` and `#printf`, so that code that writes a `.gz` file still works when the file name changes to `.bz2`. Previously the `.bz2` stream had no `#<<`, `#print`, `#puts` or `#printf`, the `.zip` stream and the stream of an `.enc` file written with `compress: false` had no `#print`, `#puts` or `#printf`, the encode stream had only `#write`, with one argument, and `#<<`, and on JRuby `#write` of the `.gz` and compressed `.enc` streams took only one argument. The `.zst` and `.xlsx` streams (both new) respond to them too. The other methods of the stream are unchanged, such as `#flush`, although for `.gz`, `.bz2`, `.zip` and `.enc` the stream is no longer the gem's own writer, such as a `Zlib::GzipWriter`, but passes those methods on to it.
- **S3 `#each_child` lists only the keys within a directory when that is all that the pattern can match**, such as `*.csv` or an exact name, with the delimiter `/`, rather than every key below it, so listing a directory above many keys makes far fewer requests. With `directories: true`, the directories within it are the common prefixes of that listing, so `each_child("*", directories: true)` on a directory above millions of keys makes one request per 1,000 names within it, and an exact name that is not found lists only the names within its directory to match it in another case. A pattern with `**`, or one that names a directory, such as `*/*.csv`, still lists every key below it. `delimiter:`, `encoding_type:` and `start_after:` can no longer be supplied as S3 options, and raise `ArgumentError`, since they change which keys a listing returns, or how: previously they were supplied to every listing, so `delimiter:` missed every key below a directory, `start_after:` skipped keys, including when deleting with `#delete_all`, and `encoding_type: "url"` returned keys that named other objects.
- **An option that the `:line`, `:array` or `:hash` mode does not take raises an `ArgumentError` that names the mode and lists its options**, other than those that are deprecated, which it still accepts, such as `Unknown option :delimitr for the :hash mode. Valid options: :delimiter, :buffer_size.`, before the file is opened, including when a copy writes its target, before it opens the source. Previously it raised Ruby's `unknown keyword: :delimitr`, and in the `:line` mode only once the file was opened, so that reading a file that did not exist raised `IOStreams::Errors::NotFound` instead.

The `ArgumentError` for `file_name:` or `default_format:` supplied to a call says to set the format on the path, which is all that they chose, rather than the file name, which also applies the streams that it implies.
- The name of a path that `#join`, `#directory`, `#cleanpath` or `#sub_ext` returns is frozen, as the name of a path created with `IOStreams.path` is, and so is the url of an SFTP or HTTP path, also one created with `IOStreams.path`, as a frozen copy that leaves the String supplied as it is. Previously the name could be changed in place, through `#to_s`, so that a joined path used as a `Hash` key could no longer be found, and changing the url of an HTTP path changed the file that it downloads.
- A frozen path, such as a root path held in a constant, can be inspected, and an S3 path can list its children and check that it exists. Previously each raised `FrozenError`, whose message was itself replaced by `...` since inspecting the path failed too. Paths joined to it, as in `EXPORT.join("a.csv").read`, already worked.
- `#freeze` on a path that already has streams or options set, for example `IOStreams.add_root(:exports, IOStreams.path("a.csv.gz").option(:gz, level: 1))`, now stops `#option`, `#stream`, `#option_or_stream`, `#remove_from_pipeline` and `#file_name=` from changing it. Previously `#freeze` only froze the path itself, not the builder holding its streams, options and file name, so a path built before it was frozen could still be changed, for the whole process when it was a root path. Changing the Hashes that `#setting`, `#pipeline` and `#schema` return also raises `FrozenError`, rather than changing the root, while the objects that the application supplied are not frozen. `#pipeline` and reading still work on a frozen path, as they already did, and a frozen stream, such as `IOStreams.stream(io).freeze`, can now be read and written too, where it raised `FrozenError`.
- A frozen HTTP path, such as a root path, can be read, and `#exist?`, `#size`, `#delete` and `#allowed?` work on it. Previously each raised `FrozenError`, since the path's url memoized into an instance variable the first time it was needed, the same issue `#each_child` and `#exist?` had on S3, fixed above; `#allowed?` raised instead of returning `false`.
- An S3 path shares its client with the paths copied from it, such as by `#join` or `#directory`, so the client and its credentials are created once. Previously each copy created its own client unless the original had already created one.
- Chaining `<<` when writing arrays or hashes, for example `io << row1 << row2` within `writer(:array)` or `writer(:hash)`, writes each row. Previously `<<` returned the underlying line writer, so every row after the first in a chain was written as its Ruby `inspect` output, such as `{"name" => "Jill"}`.
- `IOStreams.each_child` with a pattern that has no directory, such as `IOStreams.each_child("*.csv")`, searches the current directory. Previously it searched the root directory `/`, so `"**/*.csv"` searched the entire file system.
- `IOStreams.temp_file` runs the block once. Previously, when the block raised `Errno::EEXIST`, for example from `Dir.mkdir`, the block was run again with a new file name up to 5 times, and then a `RuntimeError` was raised instead. It also no longer chooses the name of a file that already exists, which it then deleted when the block finished.
- S3 `#each_child` only returns children within the path. Previously it listed every key starting with the same characters, so `IOStreams.path("s3://bucket/reports").each_child("*.csv")` also returned `s3://bucket/reports_x.csv`, and `"**/*.csv"` returned files in `reports_2024/`. It also no longer parses the path as a URL, so a path containing `+` or `%`, for example one built with `#join`, lists its children instead of none or raising `URI::InvalidURIError`, and the children keep the options of the path, such as `request_payer`.
- `#join` and `#directory` on HTTP and SFTP paths change the url. Previously only `#path` changed, so `IOStreams.path("https://example.com/files").join("report.csv").read` downloaded `https://example.com/files`, allowed paths were checked against that url, and `#to_s` of a joined SFTP path returned the original url. Characters in an HTTP path that cannot appear in a url, such as a space, `?` or `#`, are percent-encoded in the url.
- A failed `#copy_from` or `#copy_to` no longer deletes an existing target. Previously the target was opened, emptying a local file, before the source was opened, so copying from a missing source deleted the target, and when any copy to S3 failed the existing object, which is only replaced once the upload completes, was deleted. The source is now opened first, and a copy no longer checks whether the target exists, or deletes it when the copy fails. Each path cleans up after a failed write itself, the same way for a copy as for `#writer`: a local file is removed, and S3, SFTP and HTTP only store the file once it is complete. A path class registered with `IOStreams.register_scheme` that writes directly to its store should likewise remove an incomplete file when writing fails.
- Reading a PGP file no longer hangs when the block returns before reading the whole file, for example `reader(:line, &:readline)` or `reader { |io| io.read(10) }` on a file larger than the pipe buffer. The rest of the file is now decrypted and checked by gpg before the result is returned, including when the block leaves early, such as with `break`.
- The `:printable` and `:replace_non_printable` cleaners of the `:encode` stream no longer change the string supplied to the writer when writing binary data, for example with `encoding: "ASCII-8BIT"`, which also raised `FrozenError` for a frozen string.
- Reading a CSV file with an unbalanced quote no longer takes quadratic time when the data is read as UTF-8 through an encode stream. The size of such a line is now limited in bytes rather than characters.
- Reading a Zip file without the `rubyzip` gem raises a `LoadError` asking to install `rubyzip`. Previously it asked for `rubyzip v1.x`, which is not a gem name, and suggested that later versions, such as `rubyzip` 3, are not supported.
- Reading lines of UTF-8 text with multi-byte characters, for example through an encode stream with `encoding: "UTF-8"`, is now about as fast as reading the same data as binary. Previously each line rescanned the rest of the 64KB block that it was read from, which made reading lines many times slower. The limit on a line without a delimiter, which raises `IOStreams::Errors::DelimiterNotFound`, now counts bytes, as its message says, rather than characters.
- Copying between S3 paths with `convert: false`, or with `#move_to`, copies a key that contains a space, `+`, `%`, `?` or another character that must be url-encoded. Previously the key was not url-encoded, which S3 requires, so the copy failed or copied another object.
- The format of a file is detected from an upper case extension, so `DATA.JSON` is read as JSON. Previously it was read as CSV, the default. The format and the streams are also no longer detected from the name of the file before its first `.`, or from a directory name: previously `hash.txt` was read as the `:hash` format, a file named `gz` was read as gzip, and `reports.json/data.txt` was read as JSON.
- Local `#each_child` returns the children of a directory whose name contains a pattern character such as `[`, `{`, `*` or `?`. Previously it returned nothing, or the children of other directories. Within the pattern itself such characters must still be escaped with `\`. It also no longer yields the directory itself, as `dir/.`, with `hidden: true` and `directories: true`.
- `#copy_from` and `#copy_to` with `convert: false` no longer change the streams of the source or target path. Previously both paths were left with no streams, as with `stream(:none)`, so for example a later `#read` of a `.gz` source returned its compressed data, and a source with an `#option` raised `ArgumentError`.
- `IOStreams::Pgp.delete_public_or_private_keys` and `delete_public_or_private_keys_v1`, which `delete_keys` calls, raise `ArgumentError` without an `email:` or `key_id:`, as `delete_keys` does since v2.1. They were public, although not documented, and called without either, deleted every key in the keyring, or with `private: true` every secret key.
- `IOStreams::Pgp.list_keys` returns `[]` for an empty keyring, instead of raising `IOStreams::Pgp::Failure`, and `IOStreams::Pgp.pgp_version` raises `IOStreams::Pgp::Failure` with gpg's error when `gpg --version` fails, instead of `NameError`.
- `IOStreams::Pgp.import` returns the name of a key whose user id has no email address, with a `nil` email. Previously it returned the name `"Joe Bloggs"` and the email address `"pgp_test@iostreams.net"`, values left over from its tests, for such a key, and for a key whose user id it could not read.
- `IOStreams::Pgp.import` returns the keys that it imported when the input also has keys that were already in the keyring. Previously it returned `[]` whenever any key in the input was not changed. It still returns `[]` when no key was imported.
- Writing PGP with `IOStreams::Pgp::Writer.audit_recipient` set no longer adds the audit recipient to the Array supplied as `recipient:`, which grew by one on every write, and raised `FrozenError` for a frozen Array, such as one held in a constant.
- Setting `IOStreams::Pgp.executable` finds the version of the new executable, which decides the arguments that IOStreams supplies to it, such as `--pinentry-mode loopback`, and is returned by `IOStreams::Pgp.pgp_version`. Previously the version of the executable first used was kept for the whole process. A version that gpg does not report raises `IOStreams::Pgp::Failure`, where `pgp_version` raised `NoMethodError` or returned nil.
- `IOStreams::Pgp.import` returns `private: true` for a key whose secret key it imported, on GnuPG 2.4 and later. Previously it returned `private: false` for that key, and `private: true` for the key imported after it, since from 2.4 gpg reports a secret key after its public key, rather than before.
- `IOStreams::Pgp.key_info` shows a private key, and `IOStreams::Pgp.import_and_trust` imports and trusts one, as documented, on GnuPG 2.2.8 and later. Previously both raised `IOStreams::Pgp::Failure`, since from 2.1 gpg cannot show a secret key without a command, so a private key could only be imported with `IOStreams::Pgp.import`, without being trusted.
- Reading a zip file whose first entry is a folder reads the first file in it. Previously it raised `NoMethodError`.
- `#move_to` from S3 to a path that is not on S3, such as a local file, returns the target path. Previously it returned the number of bytes copied.
- `#mkpath` and `#mkdir` on SFTP paths create the directories when a file is written, so `#move_to` an SFTP path, which calls `#mkpath`, works. Previously `#mkpath` raised `NotImplementedError`, which also made every `#move_to` an SFTP path raise, and `#mkdir` did nothing. On a frozen path, such as a root path from `IOStreams.add_root`, they return a copy of the path that creates them, such as `ROOT.mkpath.write(data)`, since a frozen path cannot be changed, and `#move_to` creates the directories of an SFTP target without changing the target that it is supplied.
- Reading or writing an SFTP path without a username connects as the user from the ssh config, or the current user, as `sftp` does. Previously it failed with the usage text of `sftp`.
- The `ArgumentError` messages for calling both `#option` and `#stream`, or `#option` without a file name, no longer end with a stray `}`.
- `file://` urls refer to local files, for example `IOStreams.path("file:///home/user/a%20b.csv")` is `/home/user/a b.csv`. Previously the whole url was used as a relative file name, so reading raised `Errno::ENOENT`. A file url is absolute, so one with a host other than `localhost`, such as `file://a.txt`, or with an unencoded `?` or `#`, raises `ArgumentError`. A file url can also start with `~` for the home directory, as an SFTP url can for the login directory, for example `file://~/data/a.csv` or `file:///~/data/a.csv`, so a configured url can change between local files and SFTP without changing the code.
- `IOStreams.home` and `IOStreams.working_path` are now documented.
- Writing PGP with `import_and_trust_key` and an `import_and_trust_level` below `5` (Ultimate), such as the documented `import_and_trust_level: 4`, encrypts the file. Previously gpg raised `There is no assurance this key belongs to the named user`, since gpg only treats a key as valid on its own when it is ultimately trusted. The imported key is now supplied to gpg in a file with `--recipient-file`, which gpg treats as valid without changing its trust, on gpg v2.1.14 and later.
- A path with an option for a stream that only applies when writing, such as `option(:enc, compress: false)` or `option(:gz, level: 9)`, can be read, and one with an option that only applies when reading, such as the PGP `passphrase`, can be written, so the same path can be written and then read. Each direction ignores the options of the other that it does not need, such as `compress` when reading `.enc`, whose header records whether the file was compressed. Previously the option raised `ArgumentError` in the other direction.
- An S3 path with an option that only some requests accept, such as `acl:` or the documented `?acl=` url form, can be read, and each S3 request is supplied the options it accepts. Previously every option was supplied to reading and writing, so reading a path with `acl:` raised `ArgumentError: unexpected value at params[:acl]`, while `#exist?`, `#size`, `#delete` and `#each_child` were supplied none, so for example they did not apply `request_payer` or the `sse_customer_*` options.
- HTTP `parameters:` are added to a url that already has a query string, replacing any parameter with the same name, so that the last value supplied is used, and are added before a `#fragment`. Previously they were appended after a second `?`, so `https://example.org/file?a=1` with `parameters: {b: 2}` requested `?a=1?b=2`. Empty `parameters:` leave the url unchanged, instead of adding a `?`.
- Reading rows or records keeps a newline within a quoted CSV value in its row when CSV is the default format: for a file name without a tabular extension, such as `data.txt`, a stream without a file name, or a spreadsheet, whose cells are read as CSV. Previously the lines were split at the newline, so `each(:array)` and `each(:hash)` raised `CSV::MalformedCSVError`, for example for an Excel cell containing a line break. Lines are also split for a format set with `#format`, rather than the one detected from the file name.
- `#inspect` on a stream, such as `IOStreams.stream(io)`, no longer displays a passphrase set with `#option` or `#stream`, as `#inspect` on a path already did. A custom reader or writer declares the options that hold a secret, such as an API key, with `sensitive_option_names`, so that their values are not displayed either. Previously only an option whose name contained `passphrase`, `password` or `secret` was hidden, and only by `#inspect` on a path.
- The version of `gpg` is compared by its numbers, so that GnuPG 2.10 or later will be supplied `--no-symkey-cache`, which stops it from caching the session keys of the data that it decrypts. Previously the version was compared as a decimal number, which would treat 2.10 as 2.1.
- The `:encode` stream set with `#stream` converts the text that the application reads or writes, whatever order the streams are set in, as it already did when set with `#option`. Previously `stream(:gz).stream(:encode, encoding: "UTF-8")` decoded the compressed data, which raised `Encoding::UndefinedConversionError`, while `stream(:encode, encoding: "UTF-8").stream(:gz)` worked.
- Reading or writing `.enc` loads the `symmetric-encryption` gem when the application has not required it. Previously it raised `NameError: uninitialized constant SymmetricEncryption`, since the check for whether the gem was loaded found `IOStreams::SymmetricEncryption` instead.
- A local `#realpath` keeps the streams, options and `create_path:` of the path, since it is the same file. Previously it returned a new path without them, so for example `IOStreams.path("a.csv", create_path: false).realpath.write("x")` created the directories.
- The docs said that `IOStreams.path("sample/data").mkpath` creates `sample/data`. `#mkpath` treats the last element as the file name, so it creates `sample`; `#mkdir` creates the whole path.
- Reading a local `.zip`, `.xlsx` or PGP file, and writing a local PGP file, no longer copies the file into a temp file: the zip reader and the `creek` gem read the file itself, and `gpg` reads a PGP file through its file descriptor, and writes one through its stdout. Reading or writing one on S3, SFTP or HTTP now uses only the temp file that the path downloads into or uploads from, where previously the format also copied it into a second temp file of the same size. The same applies to a `File` or `Tempfile` supplied to `IOStreams.stream`: a zip file, spreadsheet or Parquet file read from its start, while its name still opens the same file, and a PGP file read from where it is. A `File` that was not opened for reading, or for writing, still raises `IOError`, rather than being opened again by its name. The docs now list [when temp files are used](https://iostreams.reidmorrison.com/config#when-temp-files-are-used), and no longer say that GnuPG cannot stream.
- PGP data within another stream, such as `data.csv.pgp.gz`, or in an IO that is not a `File`, such as a `StringIO` or a socket, is decrypted or encrypted through the stdin and stdout of `gpg` as it is read or written, instead of being copied into a temp file first. The data moves between `gpg` and the IO in the application's thread, so an IO that only that thread can use, such as one that reads an `Enumerator`, still works, and `Timeout` interrupts a read or write of an IO that stalls. An error about the stream names it as the stream rather than a temp file, such as `PGP stream was not signed by sender@example.org`.
- Reading PGP data that ends within its first packet, such as a file that is still being uploaded, raises `IOStreams::Pgp::Failure`. Previously `gpg` exited successfully without any output, so the data was read as an empty file.
- Writing to a local path removes the partial file for any exception, such as `Interrupt`, or the one that `Timeout` raises within its block. Previously only a `StandardError` removed it.
- Writing a file larger than 5MB to S3 through a temp file, which an option that describes the whole object needs, see Added, uploads it with `Aws::S3::TransferManager#upload_file`, which `aws-sdk-s3` v1.197.0 added in place of `Aws::S3::Object#upload_file`. Previously it called `Aws::S3::Object#upload_file`, so the SDK printed a deprecation warning, and the upload would fail once the SDK's next major version removes that method. With a version of `aws-sdk-s3` before v1.197.0, `Aws::S3::Object#upload_file` is still used.

## [2.2.0] - Unreleased

v2.2 prepares applications for v3.0: it adds the methods that replace those that v3.0 deprecates or removes, so that
an application can move to them before it upgrades. What is deprecated still works as before: using it reports a Ruby
deprecation warning, which Ruby shows only while `Warning[:deprecated]` is on. It is off by default, but on in tests run
with Minitest or test-unit, which show the warnings on `$stderr`, including for the calls that another gem makes, such
as Rocket Job 7.0. Apart from these warnings, it changes no existing behavior, other than those under Changed and Fixed.

It adds `#schema`, which describes the rows and records of a file as v3.0 does, so that code that uses one keeps
working after an upgrade. Without a schema, files are read and written as before: the same results, exceptions and
internal interfaces.

### Added

- **`#raw` reads and writes the data as it is stored**, applying no streams, neither those that the file name implies nor any set with `#stream` or `#option`, and no encoding, for example to checksum a compressed file as it is stored, `Digest::SHA256.hexdigest(IOStreams.path("data.csv.gz").raw.read)`, or to write data that is already compressed, `IOStreams.path("data.csv.gz").raw.write(gzipped)`. Setting a stream, option or encoding after it raises `ArgumentError`, since the data is as stored. `#raw?` returns whether `#raw` was called. It replaces `stream(:none)`, which still works.
- **`#encoding` sets the encoding of the text that the application reads or writes**, and the other options of the encode stream, for example `IOStreams.path("export.csv").encoding("UTF-8", cleaner: :printable, replace: "")`. Unlike `option(:encode, ...)`, it keeps working after `#stream`, and for a stream without a file name, and unlike `stream(:encode, ...)`, it keeps the streams taken from the file name, so `IOStreams.path("data.csv.gz").encoding("BINARY")` is still decompressed. The encode stream is applied closest to the application, with the same options and the same results as `option(:encode, ...)`. Each call merges its options with those already set, `stream(:none)` and `remove_from_pipeline(:encode)` remove them, and an option that the encode stream does not take raises `ArgumentError`, as does a value that it does not accept, such as an encoding that Ruby does not know, or a `cleaner` that is neither the name of a built-in rule nor a Proc, when it is set, rather than once a writer has replaced the file. Without any arguments, `#encoding` returns the encoding that was set, or nil, like `IO#encoding`. It replaces `option(:encode, ...)` and `stream(:encode, ...)`, which still work.
- **`#schema` gives the type of each field of rows and records**, a [Frictionless Table Schema](https://datapackage.org/standard/table-schema/), as a Hash, or as the path or url of a JSON file in any store, which is read the first time that a reader or writer needs it. Reading rows and records with a schema returns each value as its type, `string`, `integer`, `number`, which is a `BigDecimal`, or a `Float` with `floatNumber: true`, `boolean`, `date`, `datetime`, `object`, which is a `Hash` read from the text of a JSON object, `array`, which is an `Array` read from the text of a JSON array, or `any`, and writing them writes each value in the text form of its type, for every format, with an `object` or an `array` as its JSON text, or in JSON as itself, and a `Hash` or an `Array` of an `any` field as JSON in a format of text, such as `{"a":1}`. JSON writes numbers and booleans as themselves, with all of the digits of a `number`, such as `12345678901234567.89`, and the digits after the decimal point that its `decimals` give, such as `12.50`, the same as CSV, rather than through a `Float`, including when ActiveSupport replaces how Ruby writes JSON, and reads them back with all of their digits, while the numbers of the other fields are still a `Float`. A `number` field accepts a `Rational`, which keeps every digit of a decimal that ends, and a fixed width file writes a number that is not finite, such as `NaN`, with spaces rather than zeros, so that it can be read back. A value that is not of the type of its field raises `IOStreams::Errors::InvalidValue`. A schema also gives the position of each field of a fixed width file, with the `width`, `start` and `truncate` of each field and the `width` of each line, which IOStreams adds to Frictionless, as it does `decimals`. The parts of Frictionless that IOStreams does not support yet, such as `primaryKey`, raise `ArgumentError`, rather than being ignored. An `integer` field also reads the text of a whole number with a decimal point, such as `12.0`, as a spreadsheet stores every number as a double. A `datetime` without an offset from UTC, or text in a `format` without a zone, is read as UTC, rather than in the time zone of the process. A `number` field needs the `bigdecimal` gem, which is a bundled gem from Ruby 3.4. The schema is held as it was set, a Hash or String as a frozen copy, so `#schema` returns it unchanged when the caller changes the Hash or String that it supplied. See [Schema](https://iostreams.reidmorrison.com/formats#schema).
- **The text of a file read with a schema is UTF-8.** Its values, and its lines read with `each(:line)`, are UTF-8 strings, rather than binary strings, so that its columns can be matched to the names of the fields in every language, and text that is not valid UTF-8 raises the new `IOStreams::Errors::InvalidEncoding`, which is an `Encoding::UndefinedConversionError`, naming the line that it is on, which its `#line_number` returns. An encoding set with `#encoding`, or the data read as it is stored with `#raw`, is taken as it is instead. Binary text written to the rows and records of a file with a schema, such as the values of a file without one that is copied, is written as UTF-8, unless it is not valid UTF-8 and an encoding is set with `#encoding`, which writes it instead, as it does without a schema, while lines written with `writer(:line)` are written as they are, as in IOStreams 3.0. Unlike IOStreams 3.0, a byte order mark is not removed, and a fixed width file counts the characters of its UTF-8 text, see [Schemas in IOStreams 2.2 and 3.0](https://iostreams.reidmorrison.com/formats#schemas-in-iostreams-22-and-30).
- **A schema with `header: false` describes a file without a header row**, whose columns are the fields of the schema, in order: reading takes every line as a row, and writing writes no header row. Since it is set on the path, every reader of the path reads the file that way, including `#copy_from` and `#copy_to`. `copy_from(source, mode: :array)` from such a file gives the target the names of the fields as the columns of its rows, so that a target with a header row, such as CSV, writes them as its header row, and one without, such as JSON, takes the keys of its records from them. A format without a header row, such as JSON or fixed width, ignores `header: false`. For a format with a header row, such as CSV, the columns of the file are then the fields in order, so a schema with `header: false` needs `fieldsMatch` `"exact"`.
- **A schema matches the columns of a file to its fields, and the keys of the records read are the names of its fields.** Each column of the header row, or key of a JSON record, is matched once to the field whose name it is, or whose `aliases` include it, otherwise to the field whose name or alias is the same once both are compared without their case, spaces and punctuation, with the forms of a character that Unicode treats as the same made the same, so that the field `first_name` matches the column `First Name`, and `email` matches `E-mail`, otherwise to the field whose name or alias is the same once both are cleansed as `cleanse_header` cleanses a header row, keeping the letters of every language, as IOStreams 3.0 cleanses one, so that the field `area_m` matches the column `Area (m²)`. `aliases` is a property that IOStreams adds to a field, for columns named another way, such as `["DOB", "Birth Date"]`. A column that could be two fields, or two columns that are one field, raise `IOStreams::Errors::InvalidHeader`, rather than guess or lose a value. Writing writes the names of the fields as the header row, in order, rather than the keys of the first record, and matches the keys of each record to the fields the same way, so that a file can have readable column names, such as `First Name`, while the code writes records whose keys are `first_name`. `writer(:array)` writes the header row itself, before the rows, as `writer(:hash)` does, and takes each row written as the values of the fields, in order. See [Matching columns to fields](https://iostreams.reidmorrison.com/formats#matching-columns-to-fields).
- **`keyType` forms the keys of the records read from the names of the fields of a schema**, a property that IOStreams adds: `string`, `cleansed`, which cleanses each name as `cleanse_header` cleanses a header row, such as `first_name` for `First Name`, `symbol`, or `cleansedSymbol`, such as `:first_name`. Without it the keys are the names as they are given, as before. The header row written is still the names of the fields, and a record written can be keyed by the keys of the records read. A schema held as JSON, or in a database such as MongoDB, has String names, so `IOStreams::Schema.from_layout` adds `keyType: "symbol"` to the schema of a layout whose keys are all Symbols, which keeps the Symbol keys of its records. See [Keys of the records read](https://iostreams.reidmorrison.com/formats#keys-of-the-records-read).
- **`extraColumns: "keep"` keeps the columns that a schema does not list**, a property that IOStreams adds, which `fieldsMatch` `subset` and `partial` otherwise skip: reading keeps them after the fields, by the key that `keyType` forms from each column, with their values as they are, and so it does the keys of each JSON record. With `subset`, a schema can then have no fields, to read every column. So `required_columns:` alone, which read every column, is a schema with `subset`, `extraColumns: "keep"` and `keyType: "cleansed"`, and `cleanse_header: false` alone one with `subset`, `extraColumns: "keep"` and no fields. Writing writes only the fields. Any other `fieldsMatch` raises `ArgumentError` for it, and so does `each(:array)` for JSON. See [Keeping the other columns](https://iostreams.reidmorrison.com/formats#keeping-the-other-columns).
- **A field with `skip: true` only holds the place of its column**, a property that IOStreams adds: reading leaves it out of the rows and records, and writing writes an empty value in its column, or leaves it out of a JSON record, so that a file without a header row, whose columns are the fields in order, can have a column that the code does not read, as a `nil` in `columns:` did. It takes only the properties that place its column, `name`, `aliases`, `width` and `start`, and raises `ArgumentError` for the others. See [Field properties](https://iostreams.reidmorrison.com/formats#field-properties).
- **With a schema, `each(:array)` yields its header row as an `IOStreams::Row::HeaderRow`**, an Array that says that it is the header row, of the keys of the fields of its columns, also for a file without a header row, such as fixed width or JSON, and `writer(:array)` with a schema takes one as the header row of the rows after it, whichever row it is, which it matches to the fields, so that the rows that `each(:array)` reads from a file with a schema can be written to another, whatever their formats. `copy_from(source, mode: :array)` and `copy_to` hand the target the header row of the source in the same way when either of them has a schema, also from a source without one, and skip the blank rows of the source. A target whose columns are supplied with `columns:` skips the header row, since its columns name the values of the rows instead, and a fixed width file with a layout in `#format_options` raises `IOStreams::Errors::InvalidHeader` for it, as it did for those rows before, rather than write blank values, since the layout does not match the columns of the header row to its keys: give it a schema instead. A copy between two files without a schema copies each row as before.
- **`fieldsMatch` says which columns a file with a schema can have, and must have**, as Frictionless defines it: `exact`, the default, the fields in order; `equal`, the fields in any order; `subset`, every field and other columns, which are skipped; `superset`, only fields, any of which can be missing; and `partial`, at least one field, and other columns, which are skipped. A file that does not match raises `IOStreams::Errors::InvalidHeader`, which lists each problem. It applies to the keys of each JSON record too, to the values of a row read after its last column, such as after a comma in a value that is not quoted, and when writing, to the keys of each record, the columns of the header row of the rows written, and the values of each row after its last column, which `subset` and `partial` skip. A value after the last column that is `nil`, or blank text, is not data, so it is ignored, and the columns without a name at the end of a header row are not columns. See [fieldsMatch](https://iostreams.reidmorrison.com/formats#fieldsmatch).
- **A field with `constraints: {required: true}` must have a value**, as Frictionless defines it: a header row or JSON record without the field raises `IOStreams::Errors::InvalidHeader`, whatever `fieldsMatch` is, and a value that is `nil`, or empty text, raises `IOStreams::Errors::InvalidValue`, when reading and when writing, including a blank record or row written, such as `{}`, while a blank row read is `nil`, as a blank line is. `allowBlank: true`, a property that IOStreams adds, lets a required field have blank values, while the header row, or each JSON record, must still have the field. The other constraints of Frictionless raise `ArgumentError`. See [Required fields](https://iostreams.reidmorrison.com/formats#required-fields).
- **With a schema, `columns:`, `allowed_columns:`, `required_columns:` and `cleanse_header:` raise `ArgumentError`**, since the schema describes the columns of the file on its path: its fields are the columns, `fieldsMatch` replaces `allowed_columns:` and `skip_unknown:`, and `constraints` replace `required_columns:`. A nil `columns:`, `allowed_columns:` or `required_columns:` is not supplied, and `skip_unknown:` only applies to `allowed_columns:`, so they are accepted, so that code, such as Rocket Job, can supply the same options with and without a schema. `cleanse_header: nil` still raises, since nil does not cleanse the header row. They raise before the file is opened. `schema:` supplied to each call of `#each`, `#reader` or `#writer` raises `ArgumentError`, since it is set on the path, and so does a schema with the layout of a fixed width file in `#format_options`, when a reader or writer of the path is created.
- **Using a deprecated method or option reports a Ruby deprecation warning**, which names the line of the application that used it, and what to use instead, such as `app/jobs/export_job.rb:12: warning: IOStreams: stream(:none) is deprecated, use #raw ...`, see Deprecated. It is reported with `Kernel#warn` in the `:deprecated` category, so Ruby only shows it while `Warning[:deprecated]` is true: not by default, so production stays quiet, but in tests run with Minitest or test-unit, or with `RUBYOPT=-W:deprecated`. Extend `Warning` with a `warn` of your own to send them elsewhere, such as to a log. What is deprecated still works as before. See [Seeing deprecation warnings](https://iostreams.reidmorrison.com/upgrading#seeing-deprecation-warnings).
- **`IOStreams.tabular_formats` returns the names of the formats that `#format` accepts**, such as `:csv`, `:json` and `:fixed`, so that an application can check a format held in configuration, or offer a choice of formats, without using the internal `IOStreams::Tabular.registered_formats`.

### Deprecated

Each still works as before, and reports a deprecation warning, see Added.

- **`stream(:none)`.** Use `#raw` to read or write the data as it is stored, see Added, or `#file_name` to read a file that is not named for its format, such as `file_name("data.csv")` for a CSV file named `data.txt`.
- **Setting the encode stream with `option(:encode, ...)`, `option_or_stream(:encode, ...)` or `stream(:encode, ...)`.** Use `#encoding` instead, see Added, which sets the same options, with the same results as `option(:encode, ...)`. `stream(:encode, ...)` still stops the streams being taken from the file name, like any other stream set with `#stream`, while `#encoding` keeps them: so to read or write the data as it is stored, as `stream(:encode, encoding: "BINARY")` does for a file name such as `data.csv.gz`, use `#raw`, and to read a file that is not named for its format, `#file_name`, then `#encoding`.
- **`format:`, `file_name:`, `original_file_name:` and `default_format:` supplied to each call** of `#each`, `#reader`, `#writer`, `#copy_from` or `#copy_to` in the `:array` or `:hash` mode, even when they are nil. They describe the file, so set the format on the path instead with `#format`, so that every reader and writer of the path uses it. A file name supplied to a call only chooses the format, when the path has none, and not the streams, as `#file_name` does, so set the format that it names, such as `format(:json)` for `file_name: "data.json"`, and `default_format:` only applies when the path has no format, so set it only then, such as `path.format(:json) unless path.format`. v3.0 raises `ArgumentError` for them.
- **`allowed_columns:`, `required_columns:` and `skip_unknown:` supplied to `#writer`, or to a copy**, which uses its options to write the target, even when they are nil. They only apply when reading, so a writer ignores them, and for example `copy_from(source, mode: :hash, allowed_columns: ["name"])` copies every column. Describe the columns that are written with `#schema` instead, such as with `fieldsMatch: "subset"`. v3.0 raises `ArgumentError` for them.
- **Options supplied to `#writer` when the stream is a line, row or record writer that is already open**, such as the one that `writer(:line)` yields, handed to `IOStreams.stream`, as in `IOStreams.stream(io).writer(:array, columns: ["name"])`. It writes with its own settings, so it ignores them: set them where that writer is opened, or remove them. v3.0 raises `ArgumentError` for them.
- **Options supplied to the `:stream` mode**, which is the default of `#reader` and `#writer`, to `#copy_from` and `#copy_to` without a `mode:`, and to a copy with `convert: false`, including `mode:`. Each of them ignores its options, so remove them. v3.0 raises `ArgumentError` for them.
- **The Zip writer's `zip_file_name`**, even when it is nil. Use `entry_file_name`, which also chooses the file to read within a zip file. v3.0 raises `ArgumentError` for it.
- **An option of `.bz2` that neither its reader nor its writer takes**, such as a misspelled one. BZip2 still ignores it, and logs a warning, as in v2.1, so remove it, since v3.0 raises `ArgumentError` for it. An option of the other direction, such as `block_size` when reading, is still logged, but is not reported as deprecated, since v3.0 accepts it, and ignores it.
- **A file name ending in `.encode`**, which applies the encode stream. File names do not name the encode stream, so set it with `#encoding` instead, after which the file name is not reported, since it adds nothing. v3.0 no longer applies it.
- **`#path=` and `#builder=`.** A path can be used by many objects at once, such as a root path that file names are joined to, so changing it in place changes it for all of them: use `#join` or `#directory`, or `IOStreams.path` with the new name. `#join` and `#directory` return a new path, created with the same arguments, such as the credentials of an SFTP path, but without the streams, options, format and schema set on this one, which `#path=` keeps, so set them again on the new path. `#builder=` takes an internal object: to start again without the streams and options set with `#stream` or `#option`, create the path again with `IOStreams.path`. Neither is public in v3.0.
- **`#format_options`, and `format_options:` supplied to each call.** Use `#schema`, see Added, which gives the `width` of each field of a fixed width file. `#format_options` still reads and writes the file with its layout, as before, and a schema with a layout raises `ArgumentError`. See [Moving a layout to a schema](https://iostreams.reidmorrison.com/upgrading#moving-a-layout-to-a-schema).
- **`columns:`, `allowed_columns:`, `required_columns:` and `skip_unknown:`, and `cleanse_header:`.** A schema describes the columns of the file on its path instead, see Added: its fields are the columns, in order, and with `header: false` the columns of a file without a header row, `fieldsMatch` says which other columns the file can have, and `constraints: {required: true}` which fields it must have. They still work without a schema, and report a deprecation warning unless they are nil, apart from `cleanse_header:`, which reports one even when it is nil, since nil does not cleanse the header row. With a schema, they raise `ArgumentError` instead, unless they are nil, apart from `cleanse_header:`, which raises even when it is nil, see Added, and `skip_unknown:`, which a schema accepts, where it has no effect, and which still reports a deprecation warning. Supplied to `IOStreams::Tabular`, as Rocket Job 7.0 does, they report nothing. `IOStreams.enforce_column_restrictions=` is not deprecated in v2.2, and still applies to them. See [Moving the column options to a schema](https://iostreams.reidmorrison.com/upgrading#moving-the-column-options-to-a-schema).
- **`embedded_within:` when reading rows and records.** The format of the file splits the lines of its rows and records, since its parser must agree with where they are split, so set the format with `#format` instead, such as `format(:psv)` for values that are not quoted. It is still the way to choose the lines that `each(:line)` returns.

### Changed

- **A failed copy no longer deletes a target that it did not write.** `#copy_from`, `#copy_to` and `#move_to` opened the target before the source, and deleted the target whenever the copy raised, so a copy from a source that does not exist, or with a mode that a copy does not convert with, deleted an existing target that it never wrote, and a failed copy to S3 deleted the existing object. The source is now opened first, as in v3.0, and an error raised before the target is opened, such as for a mode that a copy does not convert with, a schema file that does not exist, or a deprecation warning that the application's `Warning.warn` raises, leaves the target as it was. A copy that fails part way still leaves no part of the file: a local file is removed, as for any write that fails, and an S3 or SFTP file is only uploaded once the copy has written all of it, so an existing S3 object is kept. A mode that a copy does not convert with, such as `:stream`, now raises `ArgumentError` before the source or the target is opened, with a message that starts with v2.1's, `Invalid mode: :stream`, and then lists the modes. See [When a copy fails](https://iostreams.reidmorrison.com/copy_files#when-a-copy-fails).

### Fixed

- **A copy of a path or stream has its own streams, options and encoding.** Changing a copy made with `dup`, such as with `#option`, `#encoding` or `#raw`, no longer changes the path that it was copied from, and `#copy_from` and `#copy_to` with `convert: false`, and `#move_to`, no longer change the streams of the source or the target. In v2.1, once the settings of a path had been read, such as with `#pipeline`, a copy with `convert: false` left it reading and writing the data as it is stored. A copy with `convert: false` from a source with options set with `#option` now copies it, where v2.1 raised `ArgumentError`.

## [2.1.0] - 2026-10-04

### Breaking

- **`IOStreams::Pgp.delete_keys` requires an `email:` or `key_id:`.** Calling it with neither now raises `ArgumentError`. Previously, on GnuPG 2.1 and later, it deleted every key in the keyring (and with `private: true`, every secret key). To delete several keys, call it once per email or key id, for example for each key returned by `IOStreams::Pgp.list_keys`. This is the only breaking change in this release, since deleting the keyring cannot be undone.

### Deprecated

These changes would break existing code, so they are postponed to v3.0. Each one logs a warning via `IOStreams.logger` when it would change the result.

- **`allowed_columns`, `required_columns` and `skip_unknown` will apply to every input when reading records.** They are only applied to a header row read from the file, and only when `cleanse_header` is true, so they are ignored for JSON and `:hash` input, when `columns:` is supplied, and with `cleanse_header: false`. Since the format is usually inferred from the file name, renaming an upload from `.csv` to `.json` bypasses the allow list. Set `IOStreams.enforce_column_restrictions = true` to apply them to every input now. JSON keys are then cleansed like a header row (for example `"Name"` becomes `"name"`), unknown keys are skipped or raise `IOStreams::Errors::InvalidHeader`, and a record missing a required column raises `IOStreams::Errors::InvalidHeader`.
- **BZip2 options will be strict.** The BZip2 reader and writer ignore any option that `bzip2-ffi` does not use, and now log a warning. In v3.0 it will raise `ArgumentError`, like every other stream. They accept `autoclose`, `first_only` and `small` when reading, and `autoclose`, `block_size` and `work_factor` when writing.
- **`IOStreams::Pgp.export(email: nil)` without a `key_id:` will raise `ArgumentError`** instead of `IOStreams::Pgp::Failure`.

### Added

- **Allowed paths** restrict IOStreams to accessing only paths within the supplied paths, for example `IOStreams.add_allowed_path("/var/data/uploads")` in an initializer. Once any allowed path is added, reading, writing, listing, deleting or otherwise accessing any other path raises `IOStreams::Errors::AccessDenied`, so an untrusted file name cannot be used to access other files. Local file names are compared by their real path, so `..` and symbolic links cannot be used to leave an allowed path. S3 paths must be in the same bucket, and keys containing `.` or `..` segments are denied since some services that implement the S3 API resolve them. SFTP and HTTP paths must have the same host and port (and scheme for HTTP), with `.` and `..` resolved as the server resolves them, and an HTTP redirect outside the allowed paths is also denied. `#each_child` skips children outside the allowed paths, and temp files from `IOStreams.temp_file` are always accessible. Also adds `IOStreams.delete_allowed_path`, `IOStreams.allowed_paths` and `IOStreams.allowed_path?`. Nothing changes until an allowed path is added. Paths from a scheme registered with `IOStreams.register_scheme` are denied once allowed paths are added, unless their path class implements the private method `#allowed_location`.
- The PGP reader accepts a `verify_first` option, for example `option(:pgp, passphrase: "secret", verify_first: true)`. It decrypts the whole file into a temporary file that only the current user can read, and only passes the contents to the block once gpg has checked the file's integrity and signature. By default the contents are passed to the block as they are decrypted, before those checks complete, which is now documented.
- `IOStreams.enforce_column_restrictions=` applies `allowed_columns`, `required_columns` and `skip_unknown` to every input when reading records, including JSON records, supplied `columns:` and `cleanse_header: false`. It defaults to false, and will default to true in v3.0. See Deprecated above.
- `IOStreams::Pgp.export` accepts `key_id:` as an alternative to `email:`.
- The GZip writer accepts a `level` option to set the compression level, for example `option(:gz, level: 9)`. Previously any option raised `ArgumentError`.

### Changed

- The `ArgumentError` for an option supplied to a stream now says what is wrong. When the option only applies in the other direction, for example `option(:enc, compress: false)` when reading, the message names the direction it belongs to and suggests configuring a separate path for reading. Otherwise it lists the valid options. Previously the error was Ruby's `unknown keyword`, raised from inside the gem that implements the stream. See [#38](https://github.com/reidmorrison/iostreams/issues/38).

### Security

- PGP: the writer's `import_and_trust_key` option now encrypts to the imported key's fingerprint, on GnuPG 2.1 and later. Previously it encrypted to the key's email address, which gpg looks up in the keyring, so another key with the same email address could be used instead. When a key has several user ids, `import_and_trust` now also trusts the key by its fingerprint instead of looking up its last email address.
- SFTP: a `username:` starting with `-` could be read by the `sftp` executable as an option, for example `-D` to run a local command. The destination is now preceded by `--`, and usernames that start with `-` or contain control characters raise `ArgumentError`.
- PGP: email addresses and key ids are now preceded by `--` when passed to `gpg`, so a value such as `--comment=x@example.com` can no longer be read as an option (which matched every key in the keyring).
- PGP: `set_trust(key_id:)` raises `ArgumentError` unless the key id is only hexadecimal digits. It is written into the input of `gpg --import-ownertrust`, where a newline could add trust lines for other keys, for example to give an attacker's key ultimate trust.
- PGP: the signer passphrase and the `export(passphrase:)` passphrase are now supplied to `gpg` on a file descriptor instead of the command line, so they are no longer visible in the process list.
- Internal temp files, which can hold decrypted data such as the plaintext of a `.zip.pgp` file, are now created with mode `0600`, and a new name is chosen rather than reuse an existing file or link.
- S3 and SFTP `#each_child` no longer reparse remote file names as URLs, so a name containing `?`, `+` or `%` can no longer change the child path or add S3 request parameters.
- SFTP `#each_child` now requires a known host key, matching the `sftp` executable's `StrictHostKeyChecking=yes`, instead of trusting a host key the first time it is seen.
- Credentials are no longer included in HTTP error messages, in the `sftp` output included in SFTP errors, or in the passphrase options displayed by `Path#inspect`.
- Removed an unused line that merged the SFTP URL query string into the ssh options. It currently had no effect, but would have allowed options such as `?ProxyCommand=...` to run commands if it were ever fixed.
- Reading a CSV file with an unbalanced quote no longer takes quadratic time.
- Documented that a username and password supplied in an HTTP or SFTP url are returned by `#to_s`, and recommended supplying them with the `username:` and `password:` arguments instead.
- Documented that an S3 URL query string is added to the S3 request parameters, and that untrusted file names should be added with `#join` rather than interpolated into the URL.

### Fixed

- S3 `#each_child` returns children that use the same client as the path, so they keep its credentials and region. Previously each child created a client from the default AWS configuration.
- `Path#join` and `IOStreams.join` only return an element unchanged when it is the path itself or is inside it. Previously any element that merely started with the same characters was returned as-is, so `IOStreams.path("s3://bucket/reports").join("reports_2024.csv")` gave `s3://bucket/reports_2024.csv` instead of `s3://bucket/reports/reports_2024.csv`, and with a root of `/data/uploads`, `join("/data/uploads_other/secret.csv")` escaped the root. Elements containing `..` are still joined as supplied.
- SFTP `#each_child` supports the `HostKey`, `IdentityKey`, `IdentityFile`, `UserKnownHostsFile`, `StrictHostKeyChecking`, `ConnectTimeout`, `ServerAliveInterval`, `ServerAliveCountMax` and `LogLevel` ssh options, using them the same way as reading and writing. Previously supplying any `ssh_options` made it raise `ArgumentError: invalid option(s)` from net-ssh. Any other ssh option now raises an `ArgumentError` that lists the supported options. It also uses only the password when one is supplied, otherwise only public keys, and never prompts for input, like reading and writing.
- SFTP `#each_child` lists the files in the path's directory. Previously it ignored the path and listed the login directory, returning children with paths relative to the root directory, so `IOStreams.path("sftp://host/data/in").each_child("*.csv")` listed `~/*.csv` as `/a.csv`. A url without a path, such as `sftp://host`, still lists the login directory. Children also keep the url's port, instead of using port 22.
- SFTP reading and writing without a password, for example with `IdentityFile`, no longer requires the `sshpass` program, as documented. Previously `sftp` was always run via `sshpass`, and every download waited 7 seconds (`before_password_wait_seconds` and `sshpass_wait_seconds`) for a password prompt, even without a password.
- When reading lines, newlines within quoted values are kept within the line when the tabular format quotes its values, such as CSV. Previously this depended on whether the file name contained `.csv`, so `.format(:psv)` on a `.csv` file still joined quoted lines, raising "Unbalanced delimited field" for a value such as `O"neil`, and `.format(:csv)` on a stream without a file name split quoted values at their newlines. Pass `embedded_within: nil` to disable it.
- When writing PSV or fixed width files, line breaks within a value are now replaced with a space. Previously a value such as `"Jack\nFORGED"` wrote a separate record. PSV already replaced `|` with `:` for the same reason.

## [2.0.0] - 2026-06-19

### Breaking

Some legacy/enterprise systems still produce such files. Only enable for files from a trusted source, since without MDC the decrypted contents are not protected against tampering.

- PGP security improvements, including clearer trust-level handling.

## [1.0.0] - 2020-01-14

Major refactor that reduced the public API footprint to the `IOStreams` module plus the `Stream`/`Path` objects it returns.

### Added

- URI scheme-based `Path` subclasses for local file, S3, SFTP, and HTTP(S).
- `#move`, `#relative?`, and `#absolute?`.
- SFTP support, including key-based authentication (`IdentityKey`) and the Linux `sftp` executable.
- PGP streaming support via temp files.

### Changed

- Renamed the internal `Streams` pipeline builder to `Builder`.
- Use `:array` and `:hash` instead of `array`/`record`.
- Switched to the `zip_tricks` gem to read zip files.
- Moved deprecated methods into a separate mix-in.
