# lib/io_streams

How the internals of IOStreams fit together, for work on the files under `lib/io_streams/`. The public API boundary, backward compatibility, and the conventions that apply everywhere are in the [root CLAUDE.md](../../CLAUDE.md).

Core pipeline (lib/io_streams/):
- `builder.rb` - `Builder` parses file-name extensions (e.g. `.csv.gz.enc`) into an ordered pipeline of reader/writer streams, merging in user-supplied `#stream`/`#option` settings, and asks each stream's format to open it. `#option` adjusts an auto-detected stream; `#stream` replaces auto-detection entirely, and `#raw` applies no streams and no encoding. `#option` and `#stream` are mutually exclusive on one instance.
- `schema.rb` - `Schema`, a Frictionless Table Schema set with `Stream#schema` (a `Schema`, a Hash, or the path or url of a JSON file read when first needed), an object of the public API, which `Stream#infer_schema` returns (`Tabular::Settings#file_schema`, the schema that was set, otherwise the private `Stream#declared_schema`, what the source declares: `Tabular#declared_schema` of the first row that is not blank, which its `Mapping` answers, `HeaderMapping` with a field of `Parser::Base.value_type` for each key of its records, "string" for a format of text, otherwise "any", `Parquet::Reader#declared_schema` from the end of the file, and `Query::Stream#declared_schema` from its columns), whose public methods are `.new`, `.read`, `#fields`, `#fields_match`, `#to_h` (its properties, then `Field#to_h` of each field, with Symbol keys, as given) and `#==`, while its other methods serve the readers and writers, holds the fields of rows and records (the name, type, `aliases` and `constraints` of each one) and `fieldsMatch`, finds the field of a column or key (`#field_for`: exact name or alias, then compared without case, spaces and punctuation, then by the cleansed name, so a field named as `cleanse_header` named a column matches it, which also settles a column that is several fields once compared loosely), and checks a file's columns against `fieldsMatch` (`#check_columns`). `Schema::Columns`, one per reader or writer, holds one file's columns matched to the fields once, and converts its rows and records, which `Tabular::SchemaMapping` asks it to do after its parser parses a line and before it renders one, for every format; the keys of the records read are the field names, unless `keyType` forms them otherwise (`Schema::Keys`, which a field's key is also matched by, so a record keyed as read is written), followed by the columns that the schema does not list when it keeps them (`extraColumns: "keep"`, `Schema#keep_extra?`, found by `Columns#extra_columns`; writing still writes only the fields), and the header row written is the field names, and `writer(:array)` writes that header row itself and takes each row as the values of the fields in order, while a header row written to it (`Row::HeaderRow`, or a copy's `#write_header`) gives the columns of the rows after it, matched to the fields, so that rows read and copied are written in the columns of their fields; a binary key or column written, or a Symbol key whose name is binary, is matched by the UTF-8 text of its bytes when they are valid UTF-8 (`Columns#written_labels`, for `#write_plan` and `#match_written`), as v2.2 takes it, while a column read, and a binary label that is not valid UTF-8, are compared as they are. The fixed width parser takes the position of each field from the schema. The `:text` parser (`Tabular::Parser::Text`) holds the text of each row as the one value of its row, without a header row or quoting, and takes a schema of one field; it is the one verbatim format (`Parser::Base.verbatim?`), so `Settings#rows_format` also accepts it over text whose format a stream decides and whose rows are lines of text (`Tabular.verbatim_text?`, which owns the rule, and `Tabular.lines_of_text?`, which excludes the values of `:array` and `:hash`, such as a query), such as the CSV of a spreadsheet, whose rows are then split, decoded and written in that format: `Settings#tabular` gives the `Tabular` that `text_format` (`Tabular::SOURCE_OPTION_NAMES`), `Tabular.line_format(format, text_format:)` names the format of the lines, which `Tabular.quote_character` and `Tabular.encoding` (and so `Tabular#quote_character`, `#encoding`, `Stream#line_reader`, `#line_writer` and `#lines_quote_character`, through the private `Stream#lines_format`, which works out the text format once) take the quote character and encoding of, so that a `:line` copy to a store of slices (`TargetStream#copy_rows`) keeps each row that its source read whole, while `writer(:line)` to the store splits its lines by the store's own format; `Tabular#build_parser` gives `Parser::Text` the parser class of that format (`lines:`), whose `.one_row` (`Parser::Base.one_row`, which replaces a line break outside a quoted value with a space and raises `TypeMismatch` for a quote left open, and `Parser::Csv.one_row`, which also checks the quoting, so that the xlsx writer never raises the csv gem's error) writes the text of each row as one of its rows, for `#render` and for `Tabular#written_line`, which `Slice::Writer` writes each row of a slice it writes as it is through, so that a slice of a spreadsheet's `:text` rows written to a file of plain text has one row on each line; without a schema nothing names the columns of its rows (`Tabular#unnamed_columns?`, which `HeaderMapping` answers for a format with neither a header row nor keyed rows), so `Record::Reader.check` and `Record::Writer.check`, which the stream calls before it opens the file, and each constructor again, raise (`Tabular#check_records`), and a copy in the `:array` mode raises before it opens a target that would take its columns from the first row written (`Stream#copy_target`, the one place that a copy, also to a store of slices, finds its target, asks `Row::Reader#unnamed_columns?`, then `Tabular#check_unnamed_rows` of the target, or of a row writer supplied to `IOStreams.stream`), as `Slice::Writer` does for the first of its slices, once the target is open, since only that slice gives their format, and `validate: true` parses such a line as a row (`Tabular#validate_line`), since it has no record. v3.0 removed the per-call column options (`columns:`, `allowed_columns:`, `required_columns:`, `skip_unknown:`, `cleanse_header:`) and `IOStreams.enforce_column_restrictions=`, which v2.2 deprecates, since a schema describes the columns instead (`extraColumns`, `keyType` and a field's `skip` cover what only they did), so they raise as unknown options; `Tabular#cleanse_header!` raises with a schema (`SchemaMapping#cleanse_header!`), whose fields name the keys of the records. v3.0 removed the layout of a fixed width file (`#format_options`), which v2.2 deprecates and converts with `Schema.from_layout`; `Errors::InvalidLayout` is kept, though nothing raises it, so that code that rescues it still works. Settings that describe the file are set on the path: `#encoding` on the builder, and those of its rows (`#format`, `#schema`, and the options of a row format such as `option(:parquet, ...)`) on its `Tabular::Settings`, one per stream, created when first needed, which checks each one when it is set, resolves the format of the rows (`#rows_format`), and builds the `Tabular` of each call (`#tabular`). `Tabular::FORMAT_OPTION_NAMES` lists the settings that `#each`/`#reader`/`#writer` reject per call, with an example of setting each on the path in `Stream::PATH_SETTINGS`; the line, row and record readers and writers declare the options of each call in their mode in `option_names` (the row, record and slice readers take the options of lines other than `embedded_within`, `Row::Reader.line_option_names`, since the format splits their lines), and `Stream#reject_unknown_options!` raises for any other before anything is opened, listing the options of the mode; `Stream.read_option_names` lists those that writers and copies reject, since a copy uses its options to write the target, computed from those `option_names`; docs/streams.md explains the rule to users. `Tabular` also owns the header-row protocol of the readers and writers, such as `#read_row`, `#read_line`, `#start_rows` and `#render_record`, and maps the columns of the file to the values of its rows and records with a `Tabular::Mapping`, one role with two implementations, chosen once when the `Tabular` is created, which it asks instead of branching on what describes the columns: `HeaderMapping` without a schema (by the header row, which a `Tabular::Header` holds, and which it always cleanses, `Header#cleanse!`, or the keys of the first record or row written) and `SchemaMapping` (the fields, through `Schema::Columns`; its `Header` keeps the header row as read, for `read_header(header.columns)`). `Mapping` declares the methods of the role, which raise `NotImplementedError` until a mapping implements them. Each one reads lines into rows and records, renders rows and records, and the header row, and answers the questions of the protocol (`#requires_header?`, `#header?`, `#rows_header?`, `#first_row_header?`, `#columns_from_first_row?`, `#columns_from_header_row?`, `#columns_supplied?`). A parser only turns a line into a row in the form of its format and back, a Hash for a format of keyed records such as JSON (`Tabular::Parser::Base.keyed?`), otherwise an Array in the order of the columns, such as CSV or fixed width, which the mapping arranges, so it never sees a `Header`, and returns an Array that it is given as it is, a row already parsed, so that `record_parse(row)` reads the rows that `each(:array)` yields, as Rocket Job's workers do; whether the format has a header row (`#requires_header?`) is a separate question. `Parser::Json` owns how JSON text is written (`.generate`, which `#render` and `Schema::Field.any_text`, for the JSON of a Hash or an Array value in another format, ask): each key, String value and Symbol value as UTF-8 (`.json_text`, which raises `InvalidEncoding` for a character that is not valid, or that UTF-8 does not have, at its byte offset within the key or value, as `Encode.utf8_failure` finds it, which `Slice::TargetStream` asks too), in the block of its `JSON::Coder`, which it uses only when the json gem hands that block the text that it does not write as it is (`.hands_text?`, json 2.16 and later on MRI), otherwise in its own walk of each value before `to_json` (`.json_value`, the one walk of a Hash or an Array, which asks `Schema::Field.any_json` how to write each other value, such as a BigDecimal), so that the json gem never writes such text itself: json 2.10 to 2.15 write binary text with a warning, and JRuby's json 2 writes the bytes of binary text that is not valid UTF-8 once Ruby has scanned it, such as for `String#ascii_only?`. `each(:array)` yields an Array for every format, and every file whose columns are known starts with a header row: a file without one (fixed width, JSON and Parquet with a schema, or `header: false`) first yields the names of the fields (`Mapping#read_rows_header`), then the values of the fields in order (`Schema::Columns#match_in_order`, `#read_row`), and JSON or Parquet without a schema first yields the keys of its first record as a header row (`Tabular#rows_header?`, `#read_row`), whose columns `HeaderMapping` holds as the keys of the rows, raising `InvalidHeader` for a key that the first record lacked; `writer(:array)` takes the first row written to JSON as its header row, without a line. The header row that `each(:array)` yields is an `IOStreams::Row::HeaderRow` (`Tabular#read_row`), an Array whose class says so, which `Row::Writer#<<` hands to `#write_header`, so that rows copied by a loop keep their header row whatever the formats. A blank row is the same in every format: `Utils.blank_text?` (Rails' `String#blank?`) and `Utils.blank_row?` (every value nil or blank text, `Utils.blank_value?`) decide it, and `Mapping#parse` applies them to every line and row already read, header row included, so each mapping returns nil for one, unless its `Tabular` is told that such a row is a record (`blank_rows: false`, `Tabular::SOURCE_OPTION_NAMES`, which the stream of a source of rows supplies, such as a query, rather than a call); the row and record readers own `skip_blanks:`, which leaves out that nil, and the the keys of a record that it skips are not checked, and the slices from it on keep their record numbers, while `Slice::Reader`, like the line reader, hands on every row as it is, blank or not. to take `replace:` and `cleaner:`. A `Slice` is not an Array: it holds its rows (`#rows` returns a copy, `#size`, `#empty?`, `#[]` read them) and is responsible for them and their numbers, so only its own methods add and change rows (`#add(row, line_number:, record_number:)`, `#<<` without numbers, `#[]=`, which keeps the numbers of the row that it replaces, `#delete_at` and `#delete_if`, after which the rows left keep theirs, and `#drop`, a new slice of the rest, and `#from_record`, a new slice from a record number that it holds, which `Slice::Stream#reader` reads for `resume_at:`, so that a slice resumes at its own record numbers rather than a count of its rows), and `#each` yields each row with its line number, the line of the file that it starts on, nil for rows that are not lines (Parquet, a query, the rows that the row and record writers render to a store), and its record number, counting from 1 without the header row, blank rows included (`#line_number_at`, `#record_number_at`; `#line_number` and `#record_number` are the first row's), and yields the row alone to a block, lambda or method of one argument (`#row_alone?`, by its arity), so that `slice.each(&method(:process))` works as it does for an Array. It does not include Enumerable, since Ruby passes the three values of `#each` to some of its methods as one Array and to others as the row alone. It stores the numbers sparsely: those of its first row, and `@jumps`, `[index, line_number, record_number]` of each row that does not follow the row before it (the row after a quoted value with line breaks, a row added without numbers), so `#add` compares each row with the numbers that the last one gives the next (`@next_line_number`, `@next_record_number`) and checks numbers only on a jump, since a number that follows is `eql?` to the Integer that the last row gives the next, which a Float or Rational of the same value is not; numbers belong to rows, so `Slice.new` raises for them without rows; a frozen slice holds frozen rows and jumps, also once cloned (`#initialize_clone`, since Ruby freezes a clone without calling `#freeze`), so that `#add` raises before it changes anything without a check per row; a change that removes rows numbers every row (`#numbered_rows`), changes that list, and adds the rows again through `#add` (`#renumber`), as `#drop` does, so that the jumps stay those of the rows, which is O(rows) per change but keeps one way of numbering, while `.from_h` normalizes the jumps that it is given (`#jumps=`) without adding each row, so that turning a stored slice back costs O(jumps). `Slice::Collector#add(row, line_number, record_number)` numbers each row by the record number that whoever adds the rows supplies, the rows of a slice, otherwise counts the records as it builds the slices, since only its tabular knows which line is the header row, and asks the slice to add each row with its numbers. `Slice::Reader` never asks what its rows are: it takes rows whose `#each` yields each row with its line number, or nil, which the stream that opens them supplies (`Stream#open_slice_rows`): `Slice::LineRows`, the lines of its `Line::Reader`, each with the line that it starts on (`#each_with_line_number`, the first line of a row that a quoted value joins, while `#line_number` stays its last, since the line reader's own `#each` yields the line alone, as `each(:line)` and `reader(:line)` hand it on), `Slice::Rows`, whose rows start on no line (Parquet, `Row::Stream`, such as a query, and the lines of text that a stream decides the format of, such as the CSV of a spreadsheet, `Builder#lines_of_file?`, derived from `#text_format` rather than a method of `StreamFormat`, which a registered format would then have to answer), and the private `Slice::Stream::NumberedRows`, the rows of a slice with their lines and record numbers, so that the slices read from a slice keep both (`Slice::Reader` passes a record number on only when its rows give one, `collector.add(row, line_number, *record_number)`, so that the collector counts the records of rows that give none, such as the lines of a file, and keeps nil for a row of a slice that has none); `TargetStream::Lines` counts the lines written in the `:line` mode, and gives them to the rows unless a copy's source says that they are not lines of its file (`Stream#copy_lines_of_file?`, protected like `#copy_blank_rows?`). `Slice#to_h` returns what a slice holds as a Hash of Strings, Integers and Arrays to store it, with `"blank_rows" => false` only when its blank rows are records, `"line_number"` and `"record_number"` when its first row has them, and `"jumps"` only when there are any, which `IOStreams.slice` turns back into a slice (`Slice.from_h`, which drops a jump that the rows before it already give, so that equal slices have equal Hashes, `Slice#==`), so that a runner stores it without knowing its keys; `#as_json` and `#to_json` give the same Hash, `#as_json` applying its options, such as `only:`, through ActiveSupport's `Hash#as_json`, and raising for them without it; `#==`, `#eql?` and `#hash` compare what it holds without copying it (`#contents`), `#eql?` by `eql?`, as an Array does, so that slices of the rows `[1]` and `[1.0]` are equal but not the same Hash key. `IOStreams.stream(slice)` returns a `Slice::Stream`, a `Row::Stream` whose source is the rows of the slice, after its header row (`#rows`), in the format of the slice (`Stream#text_format`, which the builder answers for any other stream), so that `Tabular::Settings` still owns the format and schema; `Row::Stream`, the stream of rows already read, raises for what needs bytes, such as `#stream`, `#encoding`, the `:line` mode and the options of lines (in `#reader`, before anything is read), and for writing, naming its source (`#source_name`); a source whose rows must be opened before they are read, such as a query, overrides `#open_rows` rather than supplying `#rows`, so that its reader, and the target of a copy, is opened only once they are open.
- `contract.rb` - `Contract`, the schema that a program states for its records, set with `Stream#as` (`Tabular::Settings#contract=`, which takes a `Contract` class, or builds one from a Hash or a `Schema`), is a class, as `Struct.new` makes one: `Contract.new(hash)` on `Contract` itself returns a new subclass, while a subclass declares its fields (`.field`, `.fields_match`, `.key_type`, `.extra_columns`) and answers `.schema`, a `Schema` that it checks as each is set, rejecting what lays out a file (`Schema#layout_properties`, from `Schema::LAYOUT_PROPERTIES` and `Field::LAYOUT_PROPERTIES`, which the schema owns; `Schema#to_contract` drops them, and the `format` of a field, `Field#to_contract_h`). `Settings#tabular` gives `Tabular.new(contract:)` its schema: without a schema set, the contract is the schema that the rows are read and written by (`Tabular#schema`, and the default schema of a query is not used, so its values are cast, `Settings#schema_or_contract?`), apart from a parser that lays out a line itself (`Parser::Base.layout?`, true for fixed width), which takes only a schema set; with one, `SchemaMapping` reads the file by the schema and meets the contract through `Schema::ContractColumns`, which answers the requests of `Schema::Columns`, matching the contract to the keys of the records that the schema of the file reads (`Columns#field_keys` for a writer, which reads no header row, and `Columns#labels`, the column that each field of the contract matched, to write each value in its column). A contract reads a key that a record of a format whose records supply their own keys leaves out as a missing value (`Parser::Base.keys_vary?`, true for JSON and `:hash`, false for Parquet, `Columns.new(keys_vary:)`, which `SchemaMapping` sets only for a contract read without a schema, so a schema keeps v2.2's rule, `Schema#check_columns(missing: false)`). A contract reads every field (`Schema#columns(every_field: true)`, so `Columns#match` and `#read_plan` keep the fields that a file does not have, at the position nil). `Stream#with_copy_schema` gives a copy's schema only to a target with neither a schema nor a contract. A stream format can read and write rows itself, rather than text, when it is the stream closest to the application (`StreamFormat#rows_format`, `:array` for `Xlsx`, whose reader and writer take `rows: true`): `Stream#stream_rows?` (its rows are in the format of its text, not `:text`) makes `Stream#tabular` read and write rows of that format, `#open_rows_reader` and `#open_rows_writer` open `#rows_stream`, a copy of the stream whose builder opens that stream with `rows: true` and its other arguments (`Builder#for_rows`, which leaves out the encode stream, since rows are not text, and `Builder#open_stream` passes the arguments as `StreamFormat#open_stream(arguments:)`), through the storage of the path, so a spreadsheet's lines and bytes stay CSV text. `Xlsx::Reader::Rows` types each cell with `Xlsx::Cells` (`.number_formats` classifies Excel's number formats itself, `.value` replaces creek's conversion on the sheet, through `Xlsx::Reader.convert_cells`), and keeps the displayed digits of a column that `Tabular#decimal_column?` names, while `Xlsx::Reader#each`, the CSV text, takes the text of a cell of a date or a time from `Cells.text`, so that the lines and the rows agree on which cells hold one, and the same text in every time zone, and every other cell as creek converts it, without creek's guess of a date (`#creek_value`), as v2 read it; `Xlsx::RowsWriter` writes typed cells, applying `auto_format` only to the columns that `Tabular#text_columns` does not name. A slice carries the schema of typed values (`Slice#schema`, replacing the `typed` mark): `Slice::Collector.new(schema:)`, which `Slice::Reader.new(schema:)` passes from `Stream#slice_schema` (the `#declared_schema` of the rows of a format whose rows are not lines, `Slice::Rows#declared_schema`, such as Parquet, the columns of a query, `Query::Stream#slice_schema`, or that of a slice, `Slice::Stream#slice_schema`), or the schema of a tabular whose values are those of its fields; `Slice::Stream#tabular` reads a slice by it as its default schema, `#declared_schema` answers it, and `Slice#to_h` holds it by String keys (`Utils.string_keys`) with each value as `Field#dump` gives it, which `Slice.from_h` turns back (`Field#load`, `#load_rows`, matched to the columns by `#row_fields`). `Row::Reader` and `Record::Reader` number their rows (`Row::Numbered#each_numbered`, by `#each_with_numbers` of the rows of a slice, `Slice::Stream#rows`, which give the record and line numbers of its file, or by `Line::Reader#each_with_line_number`, otherwise none, counting the records themselves after the header row), parse each row within their own rescue, never around the block of their caller, and locate an `Errors::InvalidValue` (`#at`, `#reason`, `#field`, `#value`) or, with `on_invalid:`, hand an `IOStreams::InvalidRow` of every error of the row (`Tabular#value_errors`, `Mapping#value_errors`, `Columns#value_errors` and `#hash_errors`, `ContractColumns` the same) to the handler (`Row::Numbered#invalid`); after the header row, `#each` parses each row without a block (`Tabular#row_parse`, `#record_parse`), which keeps it as fast as before. `Stream#infer_schema(sample:)` drafts a schema (`#draft_schema`, which reads a source of text, or of keyed records, once, its records by a tabular without the contract and its header row from that tabular, `#read_sample`, and `#draft_typed_schema`, which drafts only the fields of type "any" of a typed source) with `Schema::Inference`, which only sees the records, never a format, and owns how a type is guessed from values, US dates included (`Inference.check_sample`, `#<<`, `#fields`, `#names`). The instances of a contract are its records: `Contract#initialize` takes each value by its accessor, or its name, and casts it (`Field#cast`), the accessors that `.define_accessors` defines whenever the fields change (`.record_fields`, accessor to field; `.reserved?` names the methods that every record answers, which `.field` rejects and `.accessor_of` suffixes), and `.from_record` builds one from a record read through the contract without casting it again; `Stream#reader(:record)` and `#writer(:record)` (`#contract_record_reader`, `#contract_record_writer`, `#records_contract!`) wrap the record reader and writer in `Contract::RecordReader` and `Contract::RecordWriter`. `Contract.to_dsl` writes the class of a contract (`.accessors`, the accessor that `.field` declared, otherwise `.accessor_of` its name), and `Schema#to_dsl` that of `#to_contract`. A contract meets the types that a source declares before the first row (`Schema#check_types`, by `Field#converts?`, whose `CONVERTED_TYPES` say which declared types each type of field converts without loss, raising `Errors::IncompatibleType`): `Settings#tabular` checks a schema of the file, or the default schema of a query, and `Stream#open_rows_reader` asks `Tabular#check_declared_types` with the `#declared_schema` of the reader of a format whose rows are not lines, such as Parquet. `Stream#validate_contract!`, `#contract_valid?` and `#contract_errors` meet the contract without reading a row, through the private `Stream#contract_source` (the keys of a schema set, the `#declared_schema` of a typed source, otherwise `#first_row` as read, by a tabular without the contract, `Settings#tabular(contract: false)`, which `#declared_schema` reads by too), with `Columns#check_meeting` and `#meeting_errors`, and `Schema#column_errors` and `#type_errors`, the problems that `#check_columns` and `#check_types` raise as one, not raised.
- `utils.rb` - `Utils::PathName` joins and splits the names of paths (`.join`, `.dirname`, `.extname`, `.basename`, and `.keeping_bytes` for `Pathname`, as `#cleanpath` and `#relative_path_from` use it), with `::File` where it keeps the bytes of a name that is not valid UTF-8, otherwise by those bytes, as CRuby does (`FILE_KEEPS_NAMES`, found by what `::File` does), since JRuby's change such a name, such as a Latin-1 name that SFTP lists, so that the path no longer names the file (https://github.com/jruby/jruby/issues/9880). Join and split the names of a path with it, never with `::File.join`, `::File.dirname`, `::File.extname`, `::File.basename`, or `Pathname` outside `.keeping_bytes`; `test/utils_test.rb` compares it with CRuby's `File` for every short name. Likewise a copy without a mode copies with `Stream#copy_data`, which reads and writes the text itself where JRuby's `IO.copy_stream` would write it as binary, so that a target that converts text did not (`COPY_STREAM_KEEPS_ENCODING`, https://github.com/jruby/jruby/issues/9881).
- `query.rb` and `query/` - how IOStreams reads the rows of an Active Record query, `IOStreams.stream(relation)`, is in [query/CLAUDE.md](query/CLAUDE.md), which loads when working with the files there: `Query::Stream`, `Query`, how a query is opened before the target of a copy, on a connection of its own, its sources, Rails' batches, the types of its columns, its failures, and its tests. The copy of the rows of any source gives a target with neither a schema nor a contract the contract of the source (`Stream#copy_contract`), otherwise the schema of its rows (`Stream#copy_schema(rows)`, which asks the private `#rows_schema(rows)` of the source: nil for a file of text, whose schema describes its text, the schema that was set or that the reader declares for a format whose rows are not lines, such as Parquet, through `Row::Reader#declared_schema` and `Record::Reader#declared_schema`, the schema of the columns of a query, and the schema of a slice), unless the target is a row or record writer of the mode that is already open (`Stream#open_writer?`).
- `parquet.rb` - Parquet is a tabular format (`Tabular::Parser::Parquet`, records of typed values like `:hash`), not an extension registered with `Builder`, since it turns bytes into rows rather than other bytes. A parser class names the format module (a `StreamFormat`, such as `IOStreams::Parquet`) of a format whose rows are not lines with `row_format`; `Stream` asks `Tabular#lines?` and then reads and writes rows through `Tabular#read_rows`/`#write_rows`, which open that module with the options set by `Stream#option(:parquet, ...)`. `Tabular::Settings` holds those options (`#merge_row_options`), apart from the streams of the builder, since they are not part of the byte pipeline, checked by the module as soon as they are set; `Stream.row_format(name)` decides whether `#option` and `#stream` set the options of a row format or of a stream, so they set them alike, a registered extension of the same name takes precedence, and `#inspect` and `IOStreams.redact_stream_options` show them redacted by their format (`Stream.stream_format`). `Tabular.new(row_format_options:)` supplies them to the format, and the schema is passed with `StreamFormat#open_stream(arguments:)`, so it is not an option, to the writer and to the reader. With a `subset`/`partial` schema, `Schema#projection` picks the columns that the reader decodes, unless the schema keeps the others (`extraColumns: "keep"`). `Parquet::Reader` moves the values of a column of times of day, which the gem reads on the day that it reads them, to 2000-01-01 (`Schema::Field.time_of_day`, as Active Record holds a time of day). `Parquet::Column` maps each schema field to its Parquet type, apart from a field with `skip: true` (`Schema::Field#skip?`, which reading leaves out of the rows and records and writing writes empty, or leaves out of a keyed record, while its column still counts when the columns are matched); the writer needs a schema, and runs the `parquet` gem in a thread fed by a queue, since the gem pulls rows from an Enumerator while records are pushed with `#<<`.
- `reader.rb` / `writer.rb` - base classes. Every format stream is a `Reader` (implements `#read`) or `Writer` (implements `#write`) opened via `.open`/`.stream`/`.file` class methods that yield the wrapped stream to a block. The base classes provide automatic fallback: a format that only works on files (e.g. zip, xlsx) gets the input copied to a temp file first. The stream that a reader or writer block receives behaves like an IO whichever format or store it is, since a path is configuration: a reader that receives its data in chunks, of a format or of a store, such as S3's `RangeReader`, includes `IOStreams::ChunkReader` (`#read`, `#readpartial`, `#gets`, `#readline`, `#readlines`, `#each_line`, `#eof?`) and supplies `#next_chunk`, and a writer, of a format or of a store, such as S3's `Uploader`, includes `IOStreams::Writable` (`#write`, `#<<`, `#print`, `#puts`, `#printf`) and supplies `#write_data`, or wraps the writer of a gem in `Writable::Adapter`. `test/stream_io_test.rb` checks every registered stream, and the tests of a store the stream that it supplies itself, such as `test/paths/s3_uploader_test.rb`.

Registries at the bottom of `lib/io_streams/io_streams.rb` map file extensions to formats and URI schemes to path classes; new formats are added with `IOStreams.register_extension` / `IOStreams.register_scheme`. A format is a module, such as `IOStreams::Gzip` in `lib/io_streams/gzip.rb`, that answers `reader_class`, `writer_class`, `compressed?` and `encrypted?`, and extends `IOStreams::StreamFormat`, which combines the options of its reader and writer, checks them, and opens the reader or writer with the options it uses. The `:encode` stream (`IOStreams::Encode`) is not registered: file names do not name it, since it converts the text that the application reads or writes, so `Builder` owns it as a built-in stream, applies it whenever its options are set, and always places it closest to the application. `Builder::RESERVED_KEYWORDS` holds the names that cannot be registered, `:encode` and `:none`, with what to use instead, since `#option`/`#stream` raise for them (v3.0 removed `option(:encode, ...)`, `stream(:encode, ...)` and `stream(:none)`, which v2.2 deprecates, for `#encoding` and `#raw`), and `IOStreams.register_extension` asks `Builder` so that it rejects them. Facts about a format's data, and anything that combines both directions, belong on its module; its `Reader` and `Writer` hold what applies to one direction, such as `option_names`. A format registered with just its reader and writer classes is wrapped in a frozen `IOStreams::Extension`, which is neither compressed nor encrypted.

Reading uses a pull model (each stream reads from the previous one on demand); writing uses a push model. See CONTRIBUTING.md for the design philosophy.

`IOStreams::Pgp` shells out to the `gpg` executable rather than using a library.
