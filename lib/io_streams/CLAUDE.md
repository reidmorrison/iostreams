# lib/io_streams

How the internals of IOStreams fit together, for work on the files under `lib/io_streams/`: who owns which decision, and why, plus the gotchas the code does not explain. Read the code for which method calls which. The public API boundary, backward compatibility, and the conventions that apply everywhere are in the [root CLAUDE.md](../../CLAUDE.md); Active Record queries are in [query/CLAUDE.md](query/CLAUDE.md).

## Builder, formats and streams

- `Builder` turns file-name extensions (e.g. `.csv.gz.enc`) into an ordered pipeline of reader/writer streams and asks each stream's format to open it. `#option` adjusts an auto-detected stream, `#stream` replaces auto-detection entirely, and `#raw` applies no streams and no encoding. `#option` and `#stream` are mutually exclusive on one instance.
- Registries at the bottom of `io_streams.rb` map extensions to formats and URI schemes to path classes (`IOStreams.register_extension` / `.register_scheme`). A format is a module, such as `IOStreams::Gzip`, that extends `StreamFormat`, which combines, checks and opens with the options of its reader and writer. Facts about a format's data, and anything that combines both directions, belong on the module; its `Reader` and `Writer` hold what applies to one direction, such as `option_names`. A format registered with just its classes is wrapped in a frozen `IOStreams::Extension`.
- The `:encode` stream is not registered: file names never name it, since it converts the text the application reads or writes, so `Builder` owns it, applies it whenever its options are set, and always places it closest to the application. `Builder::RESERVED_KEYWORDS` (`:encode`, `:none`, each with what to use instead) cannot be registered; v3.0 removed `option/stream(:encode, ...)` and `stream(:none)`, which v2.2 deprecates, for `#encoding` and `#raw`.
- Reading pulls (each stream reads from the previous one on demand); writing pushes. See CONTRIBUTING.md. `IOStreams::Pgp` shells out to the `gpg` executable rather than using a library.
- A format that only works on files (zip, xlsx) gets its input copied to a temp file by the `Reader`/`Writer` base classes. The stream a block receives behaves like an IO whatever the format or store, since a path is configuration: a chunked reader (such as S3's `RangeReader`) includes `ChunkReader` and supplies `#next_chunk`; a writer includes `Writable` and supplies `#write_data`, or wraps a gem's writer in `Writable::Adapter`. `test/stream_io_test.rb` checks every registered stream.
- In a `SimpleDelegator` subclass, such as `BytesOutput` or `Writable::Adapter`, name top-level constants with `::`, such as `::Encoding::BINARY`. `Delegator` descends from `BasicObject`, so a bare constant is not found on `Object` and `Delegator.const_missing` resolves it on every call, uncached (about 80 ns per `#write_data`). Methods of a module included into it, such as `Writable`, are not affected. When a benchmark of the same code differs between the file and `class_eval`, suspect this.
- Join and split path names only with `Utils::PathName`, never `::File.join`/`.dirname`/`.extname`/`.basename` or `Pathname` outside `.keeping_bytes`: JRuby changes a name that is not valid UTF-8, such as a Latin-1 name that SFTP lists, so the path no longer names the file (https://github.com/jruby/jruby/issues/9880). `test/utils_test.rb` compares it with CRuby's `File`.

## Schemas and contracts

- `Schema` (a Frictionless Table Schema) is a public object, returned by `Stream#infer_schema`. Its public methods are `.new`, `.read`, `#fields`, `#fields_match`, `#to_h`, `#==` and the contract checks without a file (`#contract_errors(contract)` and friends, strict: every file it reads must meet the contract); the rest serve the readers and writers. Without a schema set, `#infer_schema` returns what the source declares (`#declared_schema`): "string" fields for a text format, "any" otherwise, Parquet's from its footer, a query's from its columns.
- A `Field` owns casting (missing values, then conversion to its type, then its `Constraints`) and which properties it knows. An unknown property is kept, as Frictionless allows, unless `Schema::NearMiss` finds it close to a known one (`trueValue`), while `Contract.field` raises for any unknown one. Date/time `format` is Python strptime (`%Y` is 4 digits, `%f`), owned by `Schema::Pattern`. Schema-level settings (`missingValues`, `primaryKey`) are given to each field by the `Schema`.
- A column matches a field by exact name or alias, then compared without case, spaces and punctuation, then by the cleansed name. Two fields of the same name are accepted, as Frictionless requires, matched to same-named columns in order; where records are keyed that raises instead.
- `Schema::Columns` is built once per reader or writer and holds that file's columns matched to the fields; `Schema::Uniqueness` lives in it so `unique`/`primaryKey`/`uniqueKeys` belong to one read or write (`uniqueLimit`). Record keys are the field names unless `keyType` says otherwise; `extraColumns: "keep"` keeps unlisted columns when reading, while writing still writes only the fields. A written binary key or column is matched by its UTF-8 text when valid UTF-8, as v2.2 does.
- v3.0 removed the per-call column options (`columns:`, `allowed_columns:`, `required_columns:`, `skip_unknown:`, `cleanse_header:`) and `IOStreams.enforce_column_restrictions=`, which v2.2 deprecates, since a schema describes the columns (`extraColumns`, `keyType`, a field's `skip`); they now raise as unknown options. v3.0 also removed the fixed-width layout (`#format_options`; v2.2 converts it with `Schema.from_layout`); `Errors::InvalidLayout` is kept, though nothing raises it, so code that rescues it still works.
- Settings that describe the file are set on the path, not per call: `#encoding` on the builder, and `#format`, `#schema` and row-format options (`option(:parquet, ...)`) on its `Tabular::Settings`, which checks each when set. `#each`/`#reader`/`#writer` reject them per call (`Tabular::FORMAT_OPTION_NAMES`, with advice in `Stream::PATH_SETTINGS`), and `Stream#reject_unknown_options!` raises for any option of the wrong mode before anything opens; docs/streams.md explains the rule to users.
- A `Contract` (`Stream#as`) is the schema a program states for its records. It is a class, like `Struct.new` makes: `Contract.new(hash)` returns a new subclass, and its instances are its records, each value cast through its accessor. It rejects layout properties (`Schema::LAYOUT_PROPERTIES`, `Field::LAYOUT_PROPERTIES`). Without a schema set, the contract is the schema the rows are read and written by, except for fixed width, which takes only a schema set. With one, the file is read by the schema and meets the contract through `Schema::ContractColumns`.
- A contract reads a key that a JSON or `:hash` record leaves out as a missing value (`Parser::Base.keys_vary?`), but only without a schema, so a schema keeps v2.2's rule. A contract reads every field, even those the file lacks. It meets the types a source declares before the first row (`Field::CONVERTED_TYPES`, raising `Errors::IncompatibleType`), and `#validate_contract!`/`#contract_valid?`/`#contract_errors` check it without reading a row.
- `Schema::Inference` sees only records, never a format, and owns how a type is guessed, US dates included.

## Tabular, mappings and parsers

- `Tabular` owns the header-row protocol of the readers and writers, and maps columns to values through one `Tabular::Mapping`, chosen once when it is created: `HeaderMapping` without a schema (by the header row, which it always cleanses, or the keys of the first record) and `SchemaMapping` (by the fields). Ask the mapping; never branch on what describes the columns.
- A parser only turns a line into a row of its format and back: a Hash for keyed formats such as JSON, otherwise an Array in column order. It never sees a `Header`, and returns an Array it is given as is, so `record_parse(row)` reads the rows that `each(:array)` yields, as Rocket Job's workers do.
- `each(:array)` yields an Array for every format, and always starts with a header row, a `Row::HeaderRow` so `Row::Writer#<<` passes it to `#write_header` and copies keep it. A file without one (fixed width, JSON or Parquet with a schema, `header: false`) yields the field names first; JSON or Parquet without a schema yields the keys of its first record, raising `InvalidHeader` for a key a later record lacks.
- Without a schema, nothing names the columns of a format with neither a header row nor keyed rows (`:text`, a headerless slice), so record readers/writers raise before the file opens, and an `:array` copy raises before it opens a target that would take its columns from the first row.
- `:text` (`Parser::Text`) is the one verbatim format: each row's text is its one value, no header, no quoting. It reads a spreadsheet's CSV text one row per value, split by CSV quoting so a multi-line cell stays whole. `.one_row` writes a row's text as one row, replacing line breaks outside quotes and raising `TypeMismatch` for an open quote, so the xlsx writer never raises the csv gem's error.
- `Parser::Json` owns how JSON text is written, including the JSON of a Hash or Array value in another format. It writes keys and String/Symbol values as UTF-8 and raises `InvalidEncoding` at the byte offset of an invalid character, so the json gem never writes such text itself: json 2.10 to 2.15 write binary text with a warning, and JRuby's json 2 writes the raw bytes of invalid binary text once Ruby has scanned it. It uses `JSON::Coder` only when the gem hands its block unwritten text (json 2.16+ on MRI) and the coder can be shared (2.17+), otherwise its own walk before `to_json`.
- A blank row is the same in every format: Rails' `String#blank?` (`Utils.blank_text?`, `Utils.blank_row?`), applied by `Mapping#parse` to every row, header included. A source of rows whose row of nulls is a record (a query) passes `blank_rows: false`; Parquet's rows are never blank. `skip_blanks:` belongs to the row and record readers; `each(:slice)`, like `each(:line)`, hands on every row as it is.
- Rows in UTF-16 raise a clear `ArgumentError` naming "UTF-16LE:UTF-8" for CSV and PSV rows or any schema (`encoding("UTF-16LE")` still reads lines), since a schema compares missing values and casts text as ASCII. This is deliberately strict: do not auto-convert to UTF-8 or parse in UTF-16 without the maintainer agreeing; relaxing it later is backward compatible.
- `resume_at:` counts records without parsing them, so the keys of skipped records are not checked and slices keep their record numbers.
- Row and record readers locate every error of a row (`Errors::RowError`: `#record_number`, `#line_number`, `#reason`). A parser tags its gem's exception, keeping its class (`CSV::MalformedCSVError`, `JSON::ParserError`), through `Row::Locator`, which keeps the helpers off the public `RowError`. Per-row hot paths rescue inline rather than through a block, since a block costs each row more, and only around reading a row, never the caller's block. `on_invalid:` handles `Errors::InvalidValue` only; any other row error still stops the read.

## Slices

- `each(:slice)` hands on rows without parsing them. A `Slice` carries everything needed to read its rows later, without the file: format, header row as read, whether its blank rows are records, whether it is headerless (so its first row is never taken as a header), the schema of typed values (`Slice#schema`), whether its values are a spreadsheet's typed cells (`cell_text?`), and `part_of_file: true`, so uniqueness is checked only by `validate:`, which reads the whole file.
- A `Slice` is not an Array and does not include Enumerable (Ruby passes `#each`'s three values to some Enumerable methods as one Array and to others as the row alone). It owns its rows and their numbers, so only its own methods add, change or remove rows. `#each` yields each row with its line number (the line it starts on, nil for rows that are not lines, such as Parquet or a query) and record number (from 1, without the header row, blank rows included), or the row alone to a block of one argument.
- Numbers are stored sparsely: the first row's, and a jump for each row that does not follow the one before. They are compared with `eql?`, so a Float or Rational is a jump. A change that removes rows renumbers through `#add`, which is O(rows) but keeps one way of numbering, while `.from_h` normalizes jumps in O(jumps), so equal slices have equal Hashes. A frozen slice freezes its rows and jumps, also when cloned.
- `Slice.new`/`#add` raise for a row its format does not read (`Parser::Base.row?`, by class). The parser class is looked up once per slice and rows of one class are checked with `Array#all?`, so the check stays cheap.
- `Slice#to_h` is a Hash of Strings, Integers and Arrays, so a runner stores it without knowing its keys. A value that neither JSON nor BSON holds as is, in a slice without a schema or an "any" field, is noted in a `"types"` sidecar (`Slice::KeptTypes`) and restored by `IOStreams.slice`. A typed slice restores each value from the form a store returned (`Field#restore`), such as BSON's seconds for a duration, which `Field#cast` rejects because a bare number does not say what it counts. `#eql?` uses `eql?`, as an Array does.
- A store is a target of `IOStreams.stream` when its class includes `Slice::Target` (`Slice::TargetStream`). The mixin is public and stays at three methods until a store needs another: `#write_slice(slice)` (named so it does not clash with the `#write`/`#<<` of a class the store inherits, such as a queue), `#slice_size` (100, or nil for one slice per write) and optional `#write_header(header)`. Each default calls `super` when the parent defines the method.
- `writer(:line)` to a store splits lines as reading the file back would: a quoted value stays whole, `MalformedDataError` once the open-quote text exceeds `Line::Reader.max_embedded_bytes`, and `InvalidEncoding` at the byte offset and line that reading would report. `#encoding(replace:, cleaner:)` apply to the `:line` mode only, and bytes are counted before cleaning. `Collector.write` writes the last slice when the block returns or breaks, not when it raises. The `:line` mode raises for formats whose rows are values (`Tabular.lines_of_text?`).
- `writer(:slice)` is the inverse of `each(:slice)`: the first slice decides how every slice is written, all must describe the same file (`Slice#same_file?`), and slices already in the file's format and header form are written as is.
- `IOStreams.stream(slice).schema(hash)` builds a new `Schema` from the Hash for every slice, about 30 µs (14% of parsing a 100-row slice). This is an accepted cost, left as a possible future enhancement (an internal cache of the built schema), so do not report it as a finding: workers spend far longer on each record, and Rocket Job reads its schema file once and hands each slice the Hash.
- `IOStreams.stream(slice)` is a `Slice::Stream`, a `Row::Stream`: a stream of rows already read, so it raises for anything needing bytes (`#stream`, `#encoding`, `:line`, line options) and for writing. A source whose rows must be opened first, such as a query, overrides `#open_rows`.

## Copies

- A copy without a mode asks its source: a source of rows (query, slice) copies in `:array`; otherwise the data is copied as stored, unless neither side is `#raw` and the formats differ and are both file formats (lines of text or a layout of their own, such as Parquet; not `:text`, `:hash` or `:array`), when it copies in `:array`.
- Data copies use `Stream#copy_data`, which reads and writes text itself where JRuby's `IO.copy_stream` would write it as binary (https://github.com/jruby/jruby/issues/9881).
- A target with neither a schema nor a contract gets the source's contract, otherwise the schema of its rows: the schema set (without layout and text properties, keeping `timeZone`), Parquet's declared schema, a query's columns or a typed slice's schema; never a guessed schema for text. A row or record writer that is already open keeps its own settings.
- Source opens before the target, so a source that fails keeps an existing target.

## Spreadsheets (xlsx)

- A stream format can read and write rows itself when it is closest to the application (`StreamFormat#rows_format`, `:array` for xlsx, opened with `rows: true`, values in the `:scalar` form). The lines and bytes of a spreadsheet stay CSV text.
- IOStreams reads a workbook itself, with no XML gem: `Xlsx::Package` finds parts by relationship type (Transitional or Strict, without case), `Xlsx::Book` reads the workbook part, and `Xlsx::XmlScanner` streams each part with `StringScanner`, by local names, skipping `extLst` (later Office versions put same-named elements there, such as an `x15:workbookPr` without `date1904`) and raising for a DOCTYPE. `Xlsx::Cells` classifies Excel's number formats and types each cell. The CSV text and the rows agree on which cells hold a date or time, with the same text in every time zone, and on the digits Excel displays.
- A cell holds no time zone, so a zoned time is written and read as the clock of its zone in UTC (`Field#clock_of`), and the cell reader and writer never know the zone. A `list` whose items are strings reads as the text Excel shows, so rows read as the CSV text does.
- Without a schema or contract, slices of cells hold each cell's text, as slices of lines do, so a schema reads them later as it reads the workbook.
- IOStreams writes a workbook itself too, streamed with `zip_kit`: `Xlsx::WorkbookWriter` writes the parts, `Xlsx::WorksheetWriter` the cells by the Ruby type of each value (`RowsWriter` gives them those types), `Xlsx::CellStyles` the fixed styles (date 1, date and time 2, time of day 3, `h:mm:ss`), `Xlsx::SharedStringTable` the shared strings, and `Xlsx::Text.encode` escapes text as `Text.decode` reads it back. A `time` field is written as a `WorksheetWriter::TimeOfDay`. A time-of-day cell reads as ISO 8601 for a `duration`, and as clock text for other types but `time` and `any`, so a `date` field raises for it. An elapsed format (`[h]:mm:ss`) shows a day or more as a date and time.

## Parquet

- Parquet is a tabular format, not an extension registered with `Builder`, since it turns bytes into rows rather than other bytes. Its options live in `Tabular::Settings`, not the byte pipeline, and a registered extension of the same name takes precedence for `#option`/`#stream`. The schema is passed to the reader and writer as an argument, not an option.
- With a `subset`/`partial` schema only its columns are decoded, unless `extraColumns: "keep"` or the stream reads slices, which hold every column, as lines of CSV do.
- A time-of-day column holds the clock a schema wrote, without a zone (`time_micros` not adjusted to UTC). The gem reads it on today's date, so `Parquet::Reader` returns it on 2000-01-01 in UTC, as Active Record does, and the reading `Tabular` reads it in its `time` field's zone. A copy without a schema or contract of its own reads the clocks by the target's fields (the contract's, else the file schema's, only for a `time` field with a `timeZone`). A loop that writes what it reads without the contract writes the clock in UTC, as the docs say.
- The writer needs a schema and runs the `parquet` gem in a thread fed by a queue, since the gem pulls rows from an Enumerator while records are pushed with `#<<`. A field with `skip: true` is left out when reading and written empty, though its column still counts when matching.

## Ractors

IOStreams is being prepared to run in Ractors other than the main Ractor on Ruby 4, which is not yet supported or documented for users, so keep its state shareable. A non-main Ractor reads a constant, or an instance variable of a class or module, only when its value is shareable (`Ractor.shareable?`), and never sets the latter. So:

- Every constant is deeply frozen (`.freeze` on each String, Array and Hash within a literal, `Utils.shareable` for any other object or a lambda, but never for an object that another library caches or shares, such as a `Gem::Version`).
- Class-level state is set only by the methods that configure IOStreams or declare a contract, which an application calls in the main Ractor (`CLASS_STATE_WRITERS`, checked by test/shareable_test.rb with the Prism visitor of test/class_state_writers.rb), and holds shareable values (a setting keeps `Utils.frozen_copy` of what it is given; a registry is replaced by a frozen copy under its mutex).
- A value a class finds once is built as the class loads (Ruby loads in the main Ractor, also for an autoload from another), or remembered only `if Utils.main_ractor?` and found again elsewhere.
- A method defined with `define_method` gets a Proc made shareable with `Utils.shareable`, reading only shareable variables.
- Code a Ractor may run never calls `Gem::Version.new` or `Gem.path`, whose state only the main Ractor can read. `IOStreams.logger` is nil in a non-main Ractor when it cannot be shared.

test/shareable_test.rb checks every constant and filled class-level instance variable in a process of its own (test/query/shareable_test.rb for `IOStreams::Query`); test/ractor_test.rb reads and writes in Ractors on Ruby 4 (test/ractor_cases.rb). Its `WORKER_CASES` are the shape to support first: the main Ractor reads a file into slices, a worker Ractor parses each slice (by a `Schema` made shareable once, also with `resume_at:`) and renders results into a store's slices, and the main Ractor writes them out. So slices of sources whose gems cannot run in a Ractor (xlsx, Parquet) are still processed in one. An `Errors::InvalidValue` raised in a worker reaches the main Ractor, with its numbers, as the cause of `Ractor::RemoteError`.

Not working in a non-main Ractor yet: a contract built from a Hash or `Schema` (such as by `#as`, which defines a class); zip and xlsx (rubyzip, zip_kit); Parquet's extension; SymmetricEncryption's cipher; root paths of S3 (so also Google Cloud Storage) and HTTP, whose caches a frozen path fills, so any one of them makes every root unreadable there; a `duration` field (activesupport 8.1 leaves `ActiveSupport::Duration::ISO8601Parser` constants unfrozen; Rails `main` has frozen them); and a named `timeZone` in a schema built in that Ractor (tzinfo keeps its data source in a class variable), though a contract defined in the main Ractor reads one.
